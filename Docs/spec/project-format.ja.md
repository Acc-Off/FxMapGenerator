# プロジェクトファイルと作業フォルダ

FxMapGenerator のプロジェクト（1 つのサーバーの地図づくり）が持つファイルの形。

コードの正:

- `src/FxMapGenerator.Core/Projects/ProjectFile.cs`: プロジェクトファイル。
- `src/FxMapGenerator.Core/State/`: 作業フォルダ。
- `src/FxMapGenerator.Core/Jobs/RunFolder.cs`: 実行の記録。

プロジェクトファイルの `format` は、形の番号。
最初の公開（0.1.0）の形が 1 で、形を変えるときに、この番号を上げる。
アプリの読める番号より大きい `format` のプロジェクトファイルは、開けない（`NEWER_FORMAT`）。

公開した版で作ったプロジェクトは、その後の版でも使えるようにする。
対象は、プロジェクトファイル、作業フォルダ、道の編集・スタイル・POI のファイル。
形を変えるときは、前の形を読む処理を足す。

## 地図の枠・ブロック・名前

**地図の枠（標準の枠）**

ゲームの m で、x −4140〜4860、y 8400〜−5100（y は北が正）。

**プロジェクトの枠**

- 標準の枠のまわりに、セル（2250 m 四方）を、上下左右に足せる（`range.extraCells`）。
  上と下で合わせて 2 まで、左と右で合わせて 4 まで。
  書き出す Web タイルの z0 の 1 枚（18000 m 四方）に収まる広さ。
- 番号の原点は、足しても、標準の枠の北西の角のまま動かない。
- 上と左に足した所のブロック・セル・タイルの番号は、マイナスになる。
  例 `z8_-8_-32`、`cell_-1_0`、`tiles/<地図>/8/-8/-32.png`。

**タイル**

- 256 px の Web タイル。z8 の 1 枚が 70.3125 m。
  z6 は 281.25 m。z0 は、標準の枠全体を 1 枚に収める。
- loaf-scripts の地図タイルと同じ格子。
- タイルの番号は、標準の枠の北西の角から、東へ `x`、南へ `y`。西と北はマイナス。
- 書き出す Web タイルだけは、上か左にセルを足したとき、プロジェクトの枠の北西の角から番号を振り直す
  （下の「書き出しの Web タイルの番号」）。

**ブロック**

- z8 のタイル 4×4。281.25 m 四方で、z6 のタイル 1 枚と同じ。
- 標準の枠は、32×48 ブロック。
- 名前は `z8_<tx>_<ty>`。北西の角の z8 タイルの番号。どちらも 4 の倍数で、マイナスもある。
- 撮影・採取・オルソ補正の単位。

**ブロックの陸・水域**

- 使う所は、見積もりの 1 ブロックの時間と、衛星地図の外洋の色を取るブロック。
  外洋の色を取るブロックは、範囲を北西から見て、最初の水域。
- 範囲の各ブロックを、次の順で決める。
  範囲が使う範囲のプリセットの表 → 既定の範囲の表 → どちらにもなければ水域。
- 範囲のプリセット（`data/range-presets.json`: `cayoPerico`、`roxwood`）は、
  通常範囲外の地図の陸のブロックと、そのまわり 2 ブロックの水域。
  水域は、陸が要る枠の中で切る。
- `cayoPerico` は、既定の範囲と同じく、その先の水深 200 m より浅い海のあるブロックも持つ。
  撮影したデータから数えたもの。
- 範囲がプリセットを使うのは、そのプリセットのブロックのうち、
  既定の範囲にないものが、範囲に 1 つでもあるとき。
  2 つが同じブロックを持てば、後の方。
- ブロックがどうやって範囲に入ったかは、見ない。

**セル**

- 8×8 ブロック。描画の単位。
- 名前は `cell_<行>_<列>`。マイナスもある。
  ブロック (bx, by) のセルは、(⌊by / 8⌋, ⌊bx / 8⌋)。切り捨ては、小さい方へ。

**ミニマップのシート**

- 4500 m 四方、2×3 のシート（行 0 が北、列 0 が西）。
- 名前は `<行>_<列>`。
- ゲームのミニマップの並びなので、プロジェクトの枠を広げても、標準の枠の 6 つのシートのまま。

**地図の id**

- `satellite`（衛星地図）、`roadmap`（道路地図）、`atlas-<スタイル>-<言語>`（アトラス）。
  例 `atlas-postalcodemap-en`。
- 作業フォルダの中の名前と、プロジェクトファイル（`minimap.map`・`export.maps`）は、この id を使う。
- 書き出しのタイルのフォルダは、英語のアトラス地図だけ、言語を付けない（`atlas-postalcodemap`）。
  日本語の地図は、`atlas-postalcodemap-ja`。
  ビューアと lb-phone の例の名前も、同じ。

## プロジェクトファイル `<名前>.fxmapgen.json`

- UTF-8 の JSON。
- パスは、プロジェクトファイルのフォルダからの相対（絶対でもよい）。
- exe は、読むときに中身を確認する。おかしな所があれば、理由をすべて挙げて止める。

```json
{
  "format": 1,
  "name": "my server",
  "workFolder": ".",
  "maps": {
    "satellite": true,
    "atlas": { "enabled": false, "styles": [ "postalcodemap" ], "languages": [ "en" ] },
    "roadmap": false
  },
  "minimap": { "map": "satellite", "outside": "map" },
  "range": { "base": "default", "add": [], "remove": [], "extraCells": null },
  "server": { "preset": "qbox", "stopResources": null },
  "console": { "host": "127.0.0.1", "port": 29200 },
  "gameFiles": { "serverResources": [] },
  "cayoPerico": false,
  "roadEdits": "road-edits.json",
  "styles": null,
  "previewPlaces": null,
  "postals": null,
  "poi": null,
  "poiStyles": null,
  "heightQuality": null,
  "parallel": 12,
  "export": { "folder": null, "tiles": true, "maps": null, "zip": false, "baseUrl": null,
              "minimap": true, "maxZoom": 8,
              "editable": { "zoom": 6, "formats": ["psd"] },
              "picture": { "file": null, "map": null } }
}
```

| 項目 | 既定 | 中身 |
|---|---|---|
| `format` | 1 | この形の番号 |
| `name` | | プロジェクトの名前 |
| `workFolder` | `.` | 作業フォルダ（下） |
| `maps.satellite` | true | 衛星地図を作る |
| `maps.atlas.enabled` / `styles` | false / `["postalcodemap"]` | アトラスを作るか。作るスタイルの一覧 |
| `maps.atlas.languages` | `["en"]` | 地図の言語 |
| `maps.roadmap` | false | 道路地図を作る |
| `minimap.map` | null | ゲーム内ミニマップ（ytd）にする地図の id。null はなし |
| `minimap.outside` | `map` | ミニマップの、範囲の外のブロックの扱い |
| `range.base` | `default` | 範囲の元: `default` か `none` |
| `range.add` / `remove` | [] | 元に足すブロック・元から外すブロックの名前 |
| `range.extraCells` | null | 標準の枠の外の地図。上・下・左・右に足すセルの数 |
| `server.preset` | `qbox` | サーバーのプリセット（`data/presets/<id>.json`: `qbox`、`qbcore`） |
| `server.stopResources` | null | 撮影の間にクライアントで止めるリソース。null は、プリセットの一覧 |
| `console.host` / `port` | `127.0.0.1` / 29200 | ゲームのコンソールソケット |
| `gameFiles.serverResources` | [] | サーバーが自分で配る ynd を拾う所の一覧 |
| `cayoPerico` | false | サーバーがカヨ・ペリコの島を出している |
| `roadEdits` | null | 道の編集のファイル。null は、編集なし |
| `styles` | null | 自分のスタイルのフォルダ。null は、自分のスタイルなし |
| `previewPlaces` | null | スタイルエディタのプレビューの場所のうち、このプロジェクトで足したもの |
| `postals` | null | アトラス地図の番地 |
| `poi` / `poiStyles` | null / null | POI のフォルダと、自分の POI スタイルのファイル |
| `heightQuality` | null | 高さの品質 |
| `parallel` | 論理コア数の半分 | ゲームを使わないステップの並列数の既定（画面のスライダー） |
| `export.folder` | null | 前回の書き出し先。null は、プロジェクトファイルの横の `export` |
| `export.tiles` / `maps` | true / null | Web タイルを書き出すか、その地図。null は、タイルのある地図すべて |
| `export.zip` | false | Web の部分を、`web.zip` 1 つにする |
| `export.baseUrl` | null | Web タイルを置く URL（lb-phone の例に使う） |
| `export.minimap` | true | ミニマップのリソースを書き出す |
| `export.maxZoom` | 8 | Web タイルの最大ズーム（6〜8） |
| `export.editable.zoom` | 6 | 編集用のファイルのズームレベル（6 か 7） |
| `export.editable.formats` | `["psd"]` | 編集用のファイルの形式（`psd`・`svg`） |
| `export.picture.file` | null | 前回変換した、編集した画像の場所 |
| `export.picture.map` | null | その画像の元の地図の id |

項目ごとの詳細は、次のとおり。

**`name`**

使う所は、画面、書き出しの README とビューアの題、lb-phone の例の `label`。

**`maps.atlas.enabled` / `styles`**

- アトラスを切っても、スタイルの一覧は残る。
- スタイルは、同梱の `postalcodemap`・`regional` か、このプロジェクトの自分のスタイルの id。
  自分のスタイルの id は、`styles` のフォルダのファイル名。
- 同じスタイルは、1 回だけ。

**`maps.atlas.languages`**

- 地図の言語は、ラベル（地図に描く文字）の言語。
- 英語 `en` は、必ず入れる。日本語の地図も作るときは、`ja` を足す。
- どのスタイルも、この言語のそれぞれで、地図を 1 つ作る。地図の id は、`atlas-<スタイル>-<言語>`。
- 画面は、プロジェクト設定の「ラベル」の「地図の言語」。
- 日本語の地図を作らないときは、画面は、日本語の欄と、ラベルの言語の切り替えを出さない。
  - 日本語の地図を作らないとは、`ja` がないか、アトラス地図を作らないとき。
  - 日本語の欄は、POI の日本語のラベル、日本語の通り名など。

**`minimap.map`**

作る地図のどれかの id。

**`minimap.outside`**

ミニマップの、範囲の外のブロック（未取得のブロック）の扱い。

- `map`: 塗る。地図のタイルのまま。
  - アトラス・道路地図は、スタイルの海の最も深い帯の色と不透明度。
    その帯が透明の、同梱の「PostalCodeMap 風」と「地域色」では、透明。
  - 衛星地図は、外洋の塗り。
- `transparent`: 塗らない。範囲の外のブロックを、透明にする。
  ゲームの地図（ESC）では後ろのゲーム画面が、レーダーでは下の全体図が見える。
- 画面では、計画・進捗の「ミニマップ」の「未取得のブロック」。
- 変えると、ミニマップの 6 つのシートと、標準の枠の外のセルのテクスチャを作り直す。

**`range.base`**

- `default`: 同梱の 1,045 ブロック（`data/range-default.json`）。陸 674 と水域 371。
  水域は、次の 3 つ。
  - 陸のまわり 2 ブロック（斜めも数える）。
  - その先の、水深 200 m より浅い海のあるブロック。撮影したデータから数えたもの。
    同梱の「PostalCodeMap 風」「地域色」の海の帯が 200 m で終わるので、帯が輪に閉じる。
  - ロスサントスの南東の空母の 3 ブロック。
- `none`。

**`range.add` / `remove`**

- 足すブロックは、プロジェクトの枠の中だけ。外にあれば、プロジェクトの誤り。
- 計画・進捗の地図の「プリセットから追加」で足したブロックも、ここに入る。
  プロジェクトファイルに、プリセットの名前は残らない。

**`range.extraCells`**

- 形は、`{"top", "bottom", "left", "right"}`。
  どれも 0 以上。上と下で合わせて 2 まで、左と右で合わせて 4 まで。
- null は、プロジェクト設定の「通常範囲外の地図を含める」がオフ。
- 4 つとも 0 は、オンで、まだ何も足していない。
  枠は、標準のまま。計画・進捗の地図に、「プリセットから追加」が出る。
- 上と左に足した所の番号は、マイナス（上の「地図の枠・ブロック・名前」）。
- 変えると、ゲームファイル・地域の色・縮小タイルを作り直す。
- 画面では、プロジェクト設定の「通常範囲外の地図」で変える。
  範囲のブロックが枠の外に出る狭め方は、できない。

**`gameFiles.serverResources`**

- 並べるものは、resources・カテゴリ・リソースのフォルダ（かそのコピー）、パックの zip、ynd 1 つ。
- サーバーが ensure する順に並べる。同じ区画は、後勝ち（`ynd-format.ja.md`）。

**`cayoPerico`**

- true なら、ゲームファイルのステップが、島の道のファイルを、その区画の元のファイルの代わりに読む。
  ゲームも、島の近くではそうする。
  - 島の道のファイルは、区画の番号に 1024 を足した番号の `nodes*.ynd`。
    中の点は、元の区画の番号を持つ。
  - 島のファイルのある区画は、すべて島のファイルにそろえる。
  - サーバーが配る島の番号のファイルがあれば、それが勝つ。
  - 変えると、ゲームファイルを読み直す。
- アトラス地図の島の地区（`ISHEIST`）の名前も、true のときだけ置く。
  false では、島のブロックが範囲にあっても置かない。変えると、文字を置き直す。
- ミニマップのリソースの島の地図も、true のときだけ書き出す。
- 画面では、プロジェクト設定の「カヨ・ペリコの道を読み込み、既定の地図を置き換える」。

**`roadEdits`**

- 形は、下の「道の編集のファイル」。
- 新しいプロジェクトの既定は、null ではなく、同梱の編集のコピー。
- 新しいプロジェクト（画面とコマンドの `new`）は、出力する地図にかかわらず、
  同梱の編集（下の「同梱の編集」）のコピーを、プロジェクトファイルの横に書いて、ここに付ける。
  - ファイル名は `road-edits.json`。名前がふさがっていれば、`road-edits-2.json`…。
  - まとまりの名前は、画面ではその時の画面の言語、コマンドでは英語の、名前 1 つになる。

**`styles`**

- 1 つのスタイルが、1 つのファイル `<id>.json`。形は、`style-format.ja.md` の「自分のスタイル」。
- スタイルエディタで最初のスタイルを作ったとき（複製・読み込み）に、
  プロジェクトファイルの横に `styles` を作って、ここに付ける。
- 実行は、始めたときに、地図が使う自分のスタイルを `logs/run-<時刻>/inputs/styles/` にコピーし、それを読む。

**`previewPlaces`**

- 持つのは、`name` と、窓の中心 `x`・`y`（m）。
- 推奨の場所（Legion Square など 6 か所）は、書かない。
- null は、足した場所なし。

**`postals`**

- nearest-postal の形のファイルか、http(s) のアドレス。
  形は `[{"code", "x", "y"}, ...]`。大きさ `"size"`（m）は任意。
- 一覧を `{"credit": "...", "codes": [...]}` に入れると、
  `credit` の文が、書き出しのクレジットに入る（下の「クレジット」）。
- null は、nearest-postal の postal code map 用の表（GitHub の `new-postals.json`、MIT）。
- 作るときに 1 回取りに行き、作業フォルダにコピーを置く（下の「番地のコピー」）。

**`poi` / `poiStyles`**

- `poi` は、地図に描く POI のフォルダ。
  中のフォルダが POI のフォルダ、`.json` 1 つが POI のまとまり 1 つ。
- `poiStyles` は、自分の見た目（POI スタイル）のファイル。形は、`poi-format.ja.md`。
- `poi` が null なら、同梱の POI（`data/poi/`）。
  Highway One の A〜Z の POI 26 個と、色付きの丸 5 個。
- POI スタイルは、同梱のもの（`data/poi-styles.json`）に、`poiStyles` のものを足す。
- 地図の編集タブの「POI」で最初に保存したときに、プロジェクトファイルの横に作って、ここに付ける。
  - `poi`: 同梱の POI のコピーから作る。
  - `poi-styles.json`: 自分の POI スタイルがあれば作る。
  - PNG のアイコンは、その横の `poi-icons/`。
- 実行は、始めたときに、次のものを `logs/run-<時刻>/inputs/` にコピーし、それを読む。
  POI のフォルダ、POI スタイルのファイル、それが指定している PNG。

**`heightQuality`**

高さの品質は、撮影・採取で、面の高さに何を取るか。

- `speed`（速度重視）: 高さデータ = 撮影・採取の高さの格子だけ。衛星地図だけのとき。
- `balance`（バランス）: 地面の採取だけ。当たった高さと水面の高い方。
- `quality`（品質重視）: 両方を取り、マスごとに高い方を使う。
- null は、地図の組み合わせの既定。
  衛星地図だけなら `speed`。アトラスか道路地図を含むなら、衛星地図がなくても `quality`。
- 写真の位置合わせと、アトラス・道路地図の地面と建物（地表）と陰影・等高線は、
  `balance` なら地面の採取、`quality` なら両方のマスごとに高い方を使う。
- 地図の組み合わせに合わないもの（アトラスか道路地図と `speed`）は、プロジェクトの誤り。

**`export`**

- 書き出しの画面の、前回の選択。書き出すたびに更新する。
  コマンドの `export` は、更新しない。
- `export.maxZoom`: z8 は、衛星地図の全域で 32,769 ファイル。z7 は 8,193、z6 は 2,049。
- `export.editable`: 編集用のファイル（地図をレイヤーに分けた PSD・SVG）を、前回どう書いたか。
  どの地図を書いたかは、残さない。書き出しのたびに選ぶ。
  - `zoom`: 6 は、1 ブロックが 256 px（ゲーム内ミニマップと同じ画素）。7 は、その 2 倍。
  - `formats`: 形式の一覧。`psd` と `svg`。
    選んだ地図を、一覧の形式のすべてで書く。
- `export.picture`: 書き出しの画面の「編集した画像を変換」で、前回変換した画像。
  - `file`: PNG の場所。null は、まだない。
  - `map`: 元の地図の id。null は、まだ選んでいない。
  - 変換するたびに更新する。コマンドの `convert` は、更新しない。
  - 出力形式の選択は、残さない。

### 道の編集のファイル（`roadEdits`）

地図の道のために、ゲームの道のデータ（`game/paths.json`）へ足す・動かす・変える・隠すノードとリンクと、
自分で付ける通り名、一緒に扱う編集のまとまり。

- ゲームのデータとの差分。
  道路グラフと道の形のステップが、`paths.json` を読んだ後に適用する。`paths.json` は、そのまま。
- 通り名は、道の形と文字のステップが、ゲームの名前と一緒に使う。
- この地図にだけ効き、ゲームの ynd には書き出さない。
- UTF-8 の JSON。注釈（`/* */`、`//`）と、末尾のカンマを許す。
- 読むときに、中身を確認する。おかしな所があれば、理由をすべて挙げて、そのステップが失敗する。
- 書くときは、1 行に、まとまり・通り名・ノード・リンクを 1 つ。
  位置と幅を 0.001 m に丸め、名前はそのままの文字で書く。

```json
{
  "format": 1,
  "groups": {
    "islandRunway": "アラモ島の滑走路"
  },
  "streets": {
    "1143239786": {"en": "Alamo Island Rd", "ja": "アラモ島通り"}
  },
  "nodes": {
    "added:1": {"x": 324.5, "y": 3601.25, "z": 48.3, "street": 1143239786, "highway": false, "tunnel": false, "unpaved": false, "switchedOff": false},
    "added:2": {"x": 330, "y": 3700, "z": 48, "street": 0, "highway": false, "tunnel": false, "unpaved": false, "switchedOff": false, "group": "islandRunway"},
    "added:3": {"x": 330, "y": 4100, "z": 48, "street": 0, "highway": false, "tunnel": false, "unpaved": false, "switchedOff": false, "group": "islandRunway"},
    "784:40": {"original": {"x": 310.125, "y": 3590.5, "z": 31.25}},
    "752:12": {"hidden": true, "original": {"x": 1210.125, "y": 3980.5, "z": 30}},
    "431:205": {"street": 1234, "original": {"x": 214, "y": -790.5, "z": 30.125, "street": 0}},
    "431:206": {"x": 216.5, "y": -801, "original": {"x": 215.25, "y": -800.5, "z": 30.125}}
  },
  "links": [
    {"from": "784:40", "to": "added:1", "lanesForward": 1, "lanesBack": 1, "narrow": false, "width": null},
    {"from": "431:205", "to": "431:206", "lanesForward": 1, "width": 9.5, "original": {"lanesForward": 2, "lanesBack": 1, "narrow": false}},
    {"from": "added:2", "to": "added:3", "lanesForward": 1, "lanesBack": 1, "narrow": false, "width": 45, "group": "islandRunway"}
  ]
}
```

| 欄 | 中身 |
|---|---|
| `format` | 1 |
| `groups` | 一緒に扱う編集のまとまりと、その名前 |
| `group` | ノード・リンクの入るまとまりの id（`groups` にあるもの）。なくてもよい |
| `streets` | 自分で付ける通り名 |
| `nodes` | ノードのキーごと |
| `x`・`y`・`z` | 位置（m） |
| `street`・`highway`・`tunnel`・`unpaved`・`switchedOff` | `paths.json` と同じ意味 |
| `hidden` | ゲームのノードかリンクを隠す |
| `original` | ゲームのノード・リンクの、編集したときの元の値 |
| `links` | リンクの一覧 |
| `lanesForward`・`lanesBack`・`narrow` | `paths.json` と同じ意味 |
| `width` | 幅（m、0 より大きく 100 以下） |

欄ごとの詳細は、次のとおり。

**`groups`**

- まとまりは、id ごと。id は、英数字と `-`・`_`。英数字で始まる。
- 名前は、文字 1 つ。画面の一覧に出し、地図には描かない。
- 同梱の編集のまとまりは、`{"en", "ja"}` で名前を持ち、画面の言語で出す。
  プロジェクトにコピーするとき（新しいプロジェクト、取り込み）は、その時の画面の言語の名前 1 つになる。
  以後は、その名前のまま。
- あるノードにだけ適用するまとまりは、名前の代わりに、`{"name": 名前, "whereFound": true}` と書く。
  同梱の編集では、`{"en", "ja", "whereFound": true}`。
  - そのまとまりのゲームのノード・リンクへの編集は、
    プロジェクトのゲームのデータに `original` のとおりにあるものにだけ、適用する。
  - ないものは、黙って飛ばす（「適用できない編集」に書かない）。
- まとまりがなければ、書かない。
- 画面は、どのノード・リンクも入っていないまとまりを外す。

**`streets`**

- ハッシュごと。ハッシュは、10 進の数の文字列。
- 地図に描く文字なので、地図の言語ごとに持つ。
  - `en`: 英語の名前。必須。
  - `ja`: 日本語の名前。なければ、日本語の地図にも英語。
    画面は、日本語の地図を作るときだけ、日本語の欄を出す。
- ノードの `street` に、このハッシュを使う。
- 0 でなく、同じハッシュは 1 回だけ。
- 通り名がなければ、書かない。
- 画面は、英語の名前を小文字にしたゲームのハッシュ（joaat）を使う。
  ゲームかほかの名前が使っていれば、どの通りも使っていない、次の数にする。
- どのノードも使わない名前は、画面が外す。

**`nodes`**

- ゲームのノードは、`区画:ノード`（`paths.json` と同じ）。
- 足したノードは、`added:<番号>`。

**`x`・`y`・`z`**

- 足したノードは、必ず持つ。ゲームのノードは、動かしたものだけ。
- どのプロジェクトの枠も入る広さの中に置く。
  その広さは、標準の枠に上下 2 セル・左右 4 セルを足した四角。
- プロジェクトの枠の外の点は、読み込むが、描かない。

**`street`・`highway`・`tunnel`・`unpaved`・`switchedOff`**

- 意味は、通り名のハッシュ、高速、トンネル、未舗装、普段の交通が走らない。
  通り名のハッシュは、0 = 名前なし。`streets` のハッシュも使える。
- 足したノードは、必ず持つ。ゲームのノードは、変えたものだけ。
- 足したノードに、交差点の印は付かない。

**`hidden`**

- 隠したものは、道路グラフにも、道の形にも入れない。
  ノードを隠すと、そのリンクも入らない。
- 隠すものは、ほかの欄を変えない。
- 隠したノードにつながる編集は、置けない。

**`original`**

- ノードは、位置（`x`・`y`・`z`）と、変えた欄の元の値。
- リンクは、`lanesForward`・`lanesBack`・`narrow`。
- 編集が触るゲームのノード（足したリンクの端も）は、変えないときも、`original` だけで並べる。
- `original` のないリンクは、足したリンク。

**`links`**

- `from`・`to` は、`nodes` のキー。
- ゲームのリンクは、2 つのノードの組で見つける。向きは問わない。
- 同じ組は、1 回だけ。

**`lanesForward`・`lanesBack`・`narrow`**

- 意味は、`from` から `to` への車線数、逆向きの車線数（0〜7）、狭い道。
- 足したリンクは、必ず持つ。ゲームのリンクは、変えたものだけ。
- 両向きとも 0 には、できない。

**`width`**

- 道の形も道路グラフも、この幅。
- null か、ないときは、道の形は車線数から決める。未舗装なら 5 m。
- 足したリンクは、採取の道路判定に出ず、幅を測れない。
  そのため、道路グラフでも、車線数からの幅（道の形と同じ式）。

**適用のしかた**

- 足したノードとリンクは、ゲームのものの後に入る。
- 足したリンクは、ナビに使わないリンクでも、近道のリンクでもない。車線のずれは 0。
- ゲームのノードは、キーで見つける。
  今の `paths.json` の位置が `original` と同じ（0.001 m の丸めの差まで）で、
  `original` にあるほかの値も同じときだけ、適用する。
- ゲームのリンクは、2 つのノードの間にあり、車線数と狭い道が `original` と同じときだけ、適用する。
- 足したリンクは、同じ 2 つのノードの間にゲームのリンクがあれば、適用しない。
- 適用しないノードにつながる編集も、適用しない。
- 適用しなかった編集は、数と理由を、実行のログと記録（下の `roadEdits` の `notApplied`）に書く。

| 理由 | 意味 |
|---|---|
| `nodeMissing` | そのノードがない |
| `nodeChanged` | 位置か値が違う。サーバーの道のデータが変わったときなど |
| `linkMissing` | そのリンクがない |
| `linkChanged` | 車線数か狭い道が違う |
| `linkExists` | 足したリンクの所に、ゲームのリンクがある |
| `endNotApplied` | 端のノードの編集を適用していない |

**道路グラフの幅**

- 幅の決まったリンクの上の測る点は、測る代わりに、その幅にする。幅は、その点の幅の中央値。
  幅の決まったリンクは、`width` のあるリンクと、足したリンク。
- 測る点が 3 つに満たない短い道は、幅の決まったいちばん長いリンクの幅。
  その道は、同じ通りの束や幅そろえの後も、この幅のまま。

**道路グラフの通り名**

- 道の名前は、そのノードの通り名の多数決。
  名前のないゲームのノードは、数えない。同じ数なら、先に出た方。
- 足したノードは、名前なし（`street` 0）も、1 票に数える。
- 名前のある道のノードから足した道は、足したノードの名前（なければ名前なし）になる。

**道の形の角**

- 足したリンクの端で、ほかに 2 本以上の道がつながるノードは、交差点と同じく、角を半径 6 m で丸める。
  対象は、交差点の記録のないノード。ゲームの道の途中のノードや、足したノード。
- ノードから東西南北へ 10 m ずつ、一辺 20 m の四角を、交差点の四角とみなす。

**通り名**

- 道路グラフは、通り名をハッシュで扱う。
- 道の形と文字のステップは、ゲームの名前（`game/names.json`）に `streets` を足して使う。
  道の形が使うのは、高速道路の名前の判定と、同じ通りの続き。
- 文字のステップは、`streets` が記録と違えば、作り直す。
  記録は、`labels-<言語>-record.json` の `streetsSha256`。

**まとまり**

- まとまり（`groups`・`group`）は、地図に効かない。道路グラフ・道の形・文字は、読まない。
- 画面の編集の一覧は、まとまりを 1 行にまとめる。「取り消し」で、まとまりのすべてを取り消す。
- まとまりの項目は、画面で直しても（非表示、移動、分割）、まとまりのまま。

**同梱の編集**

- アプリは、どのサーバーの地図にも使える道の編集を、このファイルの形で持つ
  （リポジトリの `data/road-edits-default.json`）。
  空港の滑走路、登山道、ノース・ヤンクトンの道の非表示、カヨ・ペリコの道、追加の細かい道、
  市街地の道路形状の改善。
- 1 つの編集ごとに、1 つのまとまり。すべてのノード・リンクが、まとまりに入る。
- まとまりの名前は、英語と日本語（`{"en", "ja"}`）。
- 新しいプロジェクトの編集のファイルは、このコピー。
  まとまりの名前だけ、画面の言語の名前 1 つにする。
- 今のプロジェクトには、画面の道路の編集の「同梱の編集を取り込む…」で、まとまりごとに足す。
  - 保存前の編集に入る。
  - まとまりの名前は、その時の画面の言語の名前 1 つ。
  - 足したノードは、プロジェクトの次の番号から振る。
    同じ位置（1 cm 以内）に足したノードがあれば、それを使う。
  - ゲームのノード・リンクへの編集は、次のどちらかのときは、取り込まない。
    プロジェクトの編集が、同じものを編集している。
    プロジェクトのゲームのデータが、同梱の編集の `original` と違う。
  - 通り名は、英語の名前で合わせる。
- アプリを新しくして同梱の編集が変わっても、プロジェクトの編集は変わらない。
- 同梱の編集で足したノードのうち、地表の材質で未舗装になる道のものは、未舗装の印を持つ。
  追加の細かい道のほとんどと、カヨ・ペリコの滑走路沿いの道と小道。
  地表のデータがまだない、撮影・採取の完了前の道の形でも、未舗装の道として描かれる。

**ノース・ヤンクトンの道の非表示**（まとまり `northYankton`、`whereFound`）

- プロローグの町ノース・ヤンクトンは、普段読み込まれない。
  しかし、その車の道のノード 395 個は、ゲームの道のファイルにある。
  区画 184〜187・213〜218・247、海面の 77〜117 m 上。
- 範囲がそこに届くと、海の上に、通りの名前（Cavalry Blvd）が出る。
- 同梱の編集は、その全ノードを隠す。
- あるノードにだけ適用する。
  枠の外で読まれない区画と、カヨ・ペリコの道を読むときに島のファイルに置き換わる区画があるため。
- 取り込みでは、ゲームのデータにないノードの編集も入れる。後で枠や設定を変えても、効く。
- ノース・ヤンクトンを読み込むサーバーは、画面の編集の一覧でこのまとまりを取り消すと、道が出る。

**カヨ・ペリコの道**（まとまり `cayoPerico`、`whereFound`）

- 島の滑走路と、一部の道。
- 足したノードとリンクだけ。
  ゲームのノードは、足したリンクの端になる、島の道のファイルの 2 つだけ。
- カヨ・ペリコの道を読まないプロジェクトには、その 2 つのノードがない。
  そのため、そこにつながる 2 本だけを、黙って飛ばす。
- ほかの足したノードとリンクは、どのプロジェクトの道のデータにも入る。
  範囲に島のブロックがあれば、描かれる。

**追加の細かい道と、市街地の道路形状の改善**（まとまり `minorRoads`、`cityRoadShapes`）

- 本土の、ゲームの道のデータにない細かい道（未舗装の道や歩道など）を足す。
- 市街地の一部の道の、位置・車線数・トンネルの印を直す。
- ゲームのノード・リンクへの編集を含む。
  そのため、サーバーの道のデータがそこで違うプロジェクトでは、その分が「適用できない編集」に出る。

**実行**

- 実行は、始めたときに、このファイルを `logs/run-<時刻>/inputs/` にコピーし、コピーを読む。
- 道路グラフ・道・文字のステップが残っている実行の間は、画面から編集を保存できない。

## 作業フォルダ

撮影・採取・途中のデータ・タイル。
既定は、プロジェクトファイルのフォルダ。
1 つの作業フォルダを使う実行は、同時に 1 つだけ。

```
state/                               状態の記録
capture/                             撮影
scan/                                採取
game/                                利用者のゲームから読んだもの
data/                                地図データ
cells/<セル>/                        セルの地図データと、セル描画の記録
tiles/<地図>/{z}/{x}/{y}.png         タイル
ytd/<地図>/4096/                     ミニマップのテクスチャ
before/<地図>/{z}/{x}/{y}.png        書き換えたタイルの、書き換える前の中身
logs/run-<yyyyMMdd-HHmmss>/          実行ごと
logs/precheck-<yyyyMMdd-HHmmss>/     事前確認ごと
```

**`state/`**

| ファイル | 中身 |
|---|---|
| `blocks.json` | ブロックごとのデータ項目と、取った時刻、再取得の印 |
| `stages.json` | ステップごと・単位ごとの、書き終えた時刻 |
| `scale.json` | 衛星地図の縮尺の補正 |
| `settle.json` | 描画の安定待ち（事前確認の測定） |
| `capture-resource.json` | 撮影用リソースがサーバーにあるという印（下） |
| `capture-stopped.json` | アプリが撮影用リソースを止めた時刻（下） |
| `run.lock` | 実行が使っている間、開いたままにする（持ち主のプロセス番号） |

**`capture/`、`scan/`**

- `capture/`: `<block>.png`、`.cam.txt`、`.hmap`。撮影。形は、`link-protocol.ja.md`。
- `scan/`: `<block>.txt`。採取。

**`game/`**

- `paths.json`、`names.json`、`sources.json`。
- 利用者のゲームから読んだもの。配らない。
- 形は、`ynd-format.ja.md`・`gxt2-format.ja.md`。
- `sources.json` は、次のものも持つ。
  - 枠にセルを足したとき: `extraCells`（上・下・左・右）。
  - `cayoPerico` のとき: `cayoPerico` と、島のファイルで読んだ区画 `islandAreas`。

**`data/`**

地図データは、ここに増えていく。

| ファイル | 中身 |
|---|---|
| `roads.json`、`roads-record.json` | 道路グラフ |
| `landcover/<block>.grid`、`landcover-record.json` | 地表 |
| `zones.grid`、`regions-<key>.grid`、`regions-record.json` | 地区と地域の色 |
| `road-shapes.grid`、`road-shapes-record.json` | 道の形 |
| `postals.json`、`postals-record.json` | 番地のコピー |
| `labels-<言語>-<key>.json`、`labels-<言語>-record.json` | 文字 |
| `draw-<地図>.json` | セル描画の記録: スタイル |
| `sea-<地図>.txt` | アトラス・道路地図の、範囲の外の塗りの色 |
| `low-zoom-<地図>.json` | 縮小タイルを作ったプロジェクトの枠の、足したセル |
| `minimap-<地図>.json` | ミニマップの範囲の外の扱い `outside` |
| `minimap-<地図>-<行>_<列>.json` | シートを作った元のタイルのハッシュ `source` |
| `minimap-<地図>-lod.json` | 全体図を作った z2 のタイルのハッシュ `source` |
| `minimap-<地図>-cell_<行>_<列>.json` | 標準の枠の外のセルのテクスチャの、元のタイルのハッシュ `source` |

- `landcover-record.json`: 記録は、作ったときの高さ `heights` = `scan`・`both`。
  高さの品質と違えば、全ブロックを作り直す。
  読んだ道路グラフの中身のハッシュ `roadGraph` も持つ。
- `low-zoom-<地図>.json`: 標準の枠なら、置かない。
- `minimap-<地図>.json`: 6 つのシートがそろったときに書く。
  今の設定と違えば、6 つのシートと、標準の枠の外のセルのテクスチャを作り直す。
- `minimap-<地図>-lod.json`: 全体図は、`minimap_lod_128`。
- `minimap-<地図>-cell_<行>_<列>.json`: 元のタイルは、z6 のタイル。
  テクスチャは、`fxmapgen_extra_<行>_<列>`。
  記録の名前は、セルの名前のまま。
  テクスチャの名前は、マイナスを `m` と書く: `fxmapgen_extra_m1_0`。

**`cells/<セル>/`**

- `layers.json`、`shade-<key>.grid`、`ground-<スタイル>.png`、`record.json`: セルの地図データ。
- `draw-<地図>.json`: セル描画の記録。

**`tiles/<地図>/{z}/{x}/{y}.png`**

- 衛星地図は、z8 がオルソ補正。
- アトラスと道路地図は、z8〜z5 がセル描画。
- 範囲の外と z7〜z0 は、lowZoom。

**`ytd/<地図>/4096/`**

- `minimap_sea_<行>_<列>.ytd`（DXT5）と、`minimap_<行>_<列>.ytd`（DXT1）。
- `minimap_lod_128.ytd`: 全体図。DXT5、128 px。
- `fxmapgen_extra_<行>_<列>.ytd`: 標準の枠の外のセル。DXT5、2048 px。

**`before/<地図>/{z}/{x}/{y}.png`**

- 書き換えたタイルの、書き換える前の中身。
- 前回の書き出しの後、最初に書き換えたときだけ残す。
  同じ中身で書き直すときは、タイルも書かない。
- 地図表示の「変更前との比較」が読む。
- 書き出しが済むと、その地図の分を消す。

### 採取（scan/&lt;block&gt;.txt）

リソースが出した `MSCAN` の行（形式 v=1、`link-protocol.ja.md`）を、そのまま並べたもの。

- 撮影・採取は、地面の採取の行、道の採取の行の順に、接頭辞を外して書く。
  片方だけを取り直したときは、もう片方の行を、前のファイルから残す。
- コマンドの `import` で取り込んだ採取は、元の行のまま。
  行の頭に `[mapscan]` などが付いていてもよい。
- 行の頭は、読むときに見ない。

**地面の走査**（`BEGIN kind=mat`）

- n × n 点を、step m ごと。行 0 = 北の端、列 0 = 西の端。高さの格子と同じ並び。
- `dict mat <番号> <ハッシュ>` の、材質の辞書。
- 行は、次のもの。
  - `mat`: 材質の番号。0 = 当たりなし。
  - `hz`: 当たった高さ。
  - `water`: 水面の高さ。
  - `fol`: 水面の当たり判定 = flags 128 の当たり。見出しに `fol=1` のときだけ。
  - `fol2`: 木の茂み = flags 256 の当たり。見出しに `pflags2` のあるときだけ。
- 高さの `x` か `.` は、当たりなし。

**道の走査**（`BEGIN kind=road`）

- 通り名のハッシュ（`street`）と、地区の番号（`zone`、1 から）を、step m（4 m）ごとに n × n。
  地区は、`dict zone <番号> <地区コード> <表示名>`。
- 道路の上か（`onroad`）を、pstep m（1 m）ごとに pn × pn。

**行の形**

- 行は、`<種類> j=<行> k=<部分> <値>…`。
- 値は、`値*個数` の連長で縮める。
- 1 行が複数の部分に分かれて届けば、`k` の順につなぐ。
- 届かなかった行は、「なし」のまま。

**材質の名前と種類**

- 同梱の `data/materials.json`（ハッシュ → 名前）と、`data/material-classes.json`（名前 → 種類）。
  種類の並びが、番号。
- ハッシュ 0 は `none`、名前のないハッシュは `unknown`、どの種類にもない名前は `other`。

### 道路グラフ（data/roads.json）

道のリンク（`game/paths.json`）を、地図の道にまとめたもの。
通り名のラベル、地表の駐車場の規則などが読む。

```
{"roads": [{"class": "street", "width": 11, "divided": false, "street": 0, "oneWay": false, "length": 20996.1,
            "lanes": [1, 1], "points": [[-1612.25, -3549.25], ...]}, ...]}
```

| 欄 | 意味 |
|---|---|
| `class` | 道の格 |
| `width` | 道の幅（m） |
| `divided` | 同じ通りの平行な鎖を、1 本の中心線に寄せた道 |
| `street` | 通り名のハッシュ（`names.json` で引く。0 = 名前なし） |
| `oneWay` | リンクの 7 割以上が一方通行 |
| `length` | 鎖の長さ（m、交差点の中心を含むリンクの長さ） |
| `lanes` | 鎖の向きの車線数と、逆向きの車線数（リンクあたりの平均） |
| `points` | 線（ゲーム座標 m） |

- `class`:
  - `highway`: 高速。
  - `major`: 幹線。2 本の車道を 1 本にまとめた道も。
  - `street`。
  - `minor`: 通り名のない、使われない道。
  - `track`: 未舗装。
  - `parking`: 駐車場の通路。
    `minor` のまとまりのうち、ほかの道と 1 点以下でしかつながらないもの。
- `width`:
  - 採取の道路判定（1 m）を、道に直角に 4 m ごとに見た幅の、中央値。
  - まとめた道は、束全体の幅。
  - 測れないときは、格ごとの既定。高速・幹線 20、`street` 12、`minor` 5、ほか 4。
  - 道の編集で幅の決まったリンクの上は、その幅（上の「道の編集のファイル」）。
- `divided`: 平行な鎖は、上下の車道、右折の車線など。
  高さの差が 3 m 以上の鎖どうしは、寄せない（高架と下の道）。
- `points`: 交差点の中心を抜き、間引いて（1.5 m、まとめた道は 2.5 m）、ゆるい角を丸めたもの。

幅と点は 0.01 m、長さは 0.1 m、車線数は 0.1 に丸める。
小数の正確な値で、ちょうど半分なら、偶数の側。

**`data/roads-record.json`**

- 作ったときのブロックの一覧（`blocks`）。範囲がこれと違えば、作り直す。
- 数。ノード、リンク、鎖、まとめた鎖、高さで分けた組、格を上げた道、捨てた切れ端、道。
- 格ごとの、道の数・長さ・幅の中央値・一方通行の割合。
- かかった秒。
- `roadEdits`: 適用した道の編集。編集がなければ、null。
  - `file`: プロジェクトの `roadEdits`。
  - `digest`: 適用したファイルの中身のハッシュ。今のファイルと違えば、作り直す。
  - 適用した数: `nodesAdded`・`nodesMoved`・`nodesChanged`・`nodesHidden`・`linksAdded`・
    `linksChanged`・`linksHidden`。
  - `notApplied`: 適用しなかった編集。
    `kind` = `node`・`link`、`key` = ノードのキーか、リンクの 2 つのノードのキーを空白でつないだもの、
    `reason`。
  - `blocks`: 編集が触るブロックごとに、その編集の中身のハッシュ。
    ノードは、今の位置と元の位置。リンクは、編集の前と後の線が通るブロック。
    やることの表が、編集の変わったブロックを見込むのに使う。

### 地表（data/landcover/&lt;block&gt;.grid）

ブロックごとの、地面の種類・水・建物・木の茂み。

- グリッドのファイル（下）。採取の地面の走査と同じ、n × n の格子（1 m、行 0 = 北の端）。
- ブロックとまわり 8 ブロックの地面の採取、ブロックの道の採取、道路グラフ（駐車場の規則）から作る。
- 高さは、プロジェクトの `heightQuality` で決まる。
  - `balance`: 地面の採取。各点で、当たった高さと水面の高い方。
  - `quality`: それと、高さの格子の、各点で高い方。

| 配列 | 型 | 意味 |
|---|---|---|
| `landcover` | u8 | 描く地面の種類（値は `classes` の並びの番号） |
| `surface` | u8 | 各マスで当たった、材質の種類そのまま |
| `water` | bool | 開けた水面 |
| `buildings` | bool | 建物 |
| `heightAboveTerrain` | f32 | 面の高さ（上の高さ）− 地形の高さ（m） |
| `canopy` | bool | 木の茂み |

**`landcover`**

材質の種類から決め、次の順に直したもの。

1. 開けた水から 20 m 以内の砂を、砂浜にする。
2. 5 × 5 の多数決。当たりなしは、まわりにほかの種類がないときだけ。
3. 50 m² 未満の欠片を、まわりで一番多い種類に合わせる。

**`surface`**

上の手直しの前の値。道の未舗装の判定などが読む。

**`water`**

次のどちらか。桟橋や橋の下は、水にしない。

- 水面の高さ。地面の当たりがその上 0.05 m を超えない所で、4 マス以上のまとまり。
- 水面の当たり判定（川・プール・噴水）の当たり。同じく、30 m² 以上。

**`buildings`**

- 地形から 3 m より高く、屋根になりうる材質か、歩ける地面から外れた自然の材質のマス（水でない）を、
  3 × 3 で開いてつないだ、30 m² 以上のまとまり。
  屋根になりうる材質は、自然の地面・水・当たりなし以外。
- 次のまとまりは、除く。
  - 半分より多くが道（道路判定か舗装）のまとまり。
  - 屋根の材質が 5 % 未満のまとまり（岩）。
- 駐車場の建物を足す。
  高さの基準より 6 m 以上高い舗装の、300 m² 以上のまとまりで、
  道路グラフの通り・幹線・高速の下が 4 分の 1 未満、まわり 20 m の水が半分未満のもの。
- そのあと、次のものを外す。
  - 岩場。材質の 5 割以上が `DEFAULT` か自然の地面で、壁が縁の 6 割未満、
    まわり 5 m の 9 割以上が自然の地面か `DEFAULT`。
  - まわり 10 m に、同じ高さ（3 m 以内の下）の自然の地面が 15 % 以上か、
    水が 20 % 以上ある、駐車場のまとまり。

**`heightAboveTerrain`**

- 歩ける地面の上は、0。
- 地形は、次のように決める。
  - 種は、自然の地面か舗装のマスのうち、壁で区切った面のうち、
    大きいか 3 × 3 の外まで続く面の上にあるもの。
    壁は、隣と 1 m あたり 2.5 m より大きい段差。
  - 種から、1 m あたり 0.15 m 以下の段差で歩いて行けるマスの高さを使う。
    歩いてつながる面に、となり合う種が 2 つ以上のまとまりがあるときだけ。
  - ほかのマスには、一番近いそのマスの高さを入れる。

**`canopy`**

- 木の茂みの探り（flags 256）の当たりが、地面の当たりより 2 m 以上高いマスを、
  2 m 広げ、10 m² 未満を除いたもの。
- 採取に木の茂みの探りがあるブロックだけ。

**付記**

- `block`、`x0`・`y0`（北西の角、m）、`step`（m）、`classes`。
- `classes` は、地面の種類の名前を、番号の順に並べたもの。
  `none`、`urban`、`grass`、`dirt`、`sand`、`beach`、`rock`、`vegetation`、`snow`、
  `waterMaterial`、`defaultMaterial`。

材質の種類との対応:

| 材質 | 地面の種類 |
|---|---|
| 当たりなし | `none` |
| 濡れた砂 | `beach` |
| 水の材質 | `waterMaterial` |
| 材質 `DEFAULT`（材質の種類 `default`） | `defaultMaterial` |
| 自然の種類 | それぞれ同じ名前 |
| ほかの硬い面と、名前の分からない材質 | `urban` |

材質 `DEFAULT` は、ゲームが固有の材質を付けていない、地形・岩・小物など。

### 地区と地域の色（data/zones.grid、data/regions-&lt;key&gt;.grid）

ステップ「地域の色」が、範囲のブロックの道の採取と地表から作る（全域で 1 つ）。

**`zones.grid`**

- 地区（ゲームの `GET_NAME_OF_ZONE` のコード）の、4 m の格子。
- 始まりの点（`x0`、`y0`）は、道の採取のあるブロックを囲む四角の北西の角を、
  端数 0.5 の 1 m の格子に寄せた点。そこから、4 m ごと。
- 点 (行 r, 列 c) は、(x0 + 4c + 0.5, y0 − 4r − 0.5) の真下のブロックの、
  いちばん近い道の採取の点の地区。
- 配列: `zone`（u16、付記 `zones` の番号。0 = 地区なし）、`inside`（bool、採取したブロックの中）。
- 付記: `x0`、`y0`、`step`（4）、`zones`、`width`・`height`。
  - `zones`: "" と、出てくる地区のコードを、文字コード順に。
  - `width`・`height`: 格子の枠の大きさ（m）。ブロックの四角を、整数の m に丸めたもの。
    文字は、この枠の中に置く。
- 地域の色と、文字（地区名と、番地の大きさを決める地区）が読む。

**`regions-<key>.grid`**

- 地域の色（スタイルの `regions`）の、4 m の格子。
- プロジェクトの枠を覆う。区切りは、標準の枠の北西の角にそろえる。
  標準の枠なら、2250×3375。上か左に足した枠では、始まりがその分だけ西・北になる。
- 地区から、スタイルの表で地域を決める。
  表にない地区の陸は、いちばん近い決まった陸の地域。
- 地域ごとの陸の割合を、ガウスぼかし（スタイルの `regions.blur` m）で混ぜた色。
  まわりに陸のない所は、`regions.sea` の地域の色。
- 地面の画像が地域の色を使うスタイルの地図があるときだけ、スタイルの `regions` の中身ごとに 1 つ作る。
  そのスタイルは、同梱の `regional` と、それを元にした自分のスタイル。
- `<key>` は、`regions` の JSON の SHA-256 の先頭 12 桁。
  同じ中身のスタイルは、1 つを共有する。
  どの地図も使わなくなったものは、次に作るときに消す。
- 配列: `red`・`green`・`blue`（f32、0〜255）、
  `region`（u8、スタイルの `regions.colors` の順の番号。255 = なし）、
  `zone`（u16、付記 `zones` の番号）。
- 付記: `x0`、`y0`、`step`、`zones`、`regions`（作ったときのスタイルの `regions` の中身）。

**`regions-record.json`**

- 作ったときのブロックの一覧（`blocks`）。
- 地区の数（`zones`）。
- かかった秒（`seconds`）。
- 作ったときの枠の足したセル（`extraCells`）。
  標準の枠なら、書かない。今の枠と違えば、作り直す。
- `fields`: 作った地域の色の `<key>` ごとに、次の 2 つ。
  どの地図も地域の色を使わないときは、null。
  - `regions`: 作ったときのスタイルの `regions` の中身。
  - `cells`: 範囲のセルごとに、そのセルの地面の画像が読む地域の色の部分の、
    `red`・`green`・`blue` の中身のハッシュ。
    読む部分は、セルの 1 m の格子の点を双一次で読む 4 m のマスと、まわり 1 マス。

### 番地のコピー（data/postals.json）と文字（data/labels-&lt;言語&gt;-&lt;key&gt;.json）

ステップ「文字」が、アトラス地図の言語ごとに作る。

**`postals.json`**

- プロジェクトの `postals` の元の中身の、そのままのコピー。
  元は、ファイル、アドレス、既定の nearest-postal の表。
- `postals-record.json` に、元（`source`）、中身の SHA-256、番地の数、取った時刻。
- 元のファイルが書き換わるか、元を替えると、コピーし直す。
- アドレスは、コピーがなければ取りに行く。取り直したいときは、コピーを消す。

**`labels-<言語>-<key>.json`**

- その言語で置いた文字。形は、`Core/Labels/LabelsFile.cs`。
- `key` は、スタイルの `labels` の置き方のハッシュ（`style-format.ja.md`）。
  同じ置き方のアトラス地図は、1 つのファイルを使う。
- 付記: `format`（1）、`language`、`key`、`frame`（左・上・右・下 m）。
- `labels`: `kind`（`postal`・`zone`・`street`）、`text`、`x`・`y`（中心）、
  `rotation`（度、反時計回り）、`size`（em、m）、`font`、`weight`、`spacing`（字間 m）。
- 通り名は、`chars`。1 字ずつ `char`、`x`・`y`、`rotation`、`advance`。0.01 に丸め。
- POI は、入らない。描画が、POI のフォルダから描く。
  文字を置くときは、POI が先に場所を取る。

**`labels-<言語>-record.json`**

- 作ったファイルごとに、`key`、使う地図、種類ごとの数と、路線番号を付けた通り名の数（`routes`）。
- `cells`: 範囲のセルごとに、そのセルの描画が使う文字の中身のハッシュ。
  使う文字は、中心がセルの四角の外 200 m までにある文字。
- 番地のコピーと、POI の SHA-256。
  POI の SHA-256 は、すべての POI の、地図に描く値から。
  まとまりやフォルダの名前、`credit`、注釈は入らない。
- 入っていなかったフォント。
- かかった秒。
- `streetsSha256`: 道の編集が足した通り名の中身のハッシュ。なければ、null。
- `cayoPerico`: 置いたときのプロジェクトの `cayoPerico`。島の地区の名前を置いたか。
  値のない記録の文字は、置き直す。

### セルの地図データ（cells/&lt;セル&gt;/）

ステップ「セルの地図データ」が、セルのブロックの地表・採取・高さから作る。
セルのブロックは、セルの 8×8 と、まわり 1 ブロックのうち範囲にあるもの。

- セルの 1 m の格子は、始まりの点（`grid.x0`、`grid.y0`）から、1 m ごとに点を置く。
  始まりの点は、ブロックを囲む四角の北西の角を、端数 0.5 の 1 m の格子に寄せた点。
- 点 (行 r, 列 c) は、(x0 + c, y0 − r) のまわり 1 m 四方を表す。隣のセルと、格子がそろう。
- 各点は、真下のブロックの、いちばん近い標本の値。
  地表の種類・水・建物・木の茂み、採取の材質・線路・水深、道の採取の地区。
- 陰影と等高線の高さは、地表と同じ。
  `balance` は、地面の採取の表面 = 当たった高さと水面の高い方。
  `quality` は、それと高さの格子の、各点で高い方。

**`layers.json`**

ベクタの層を、描く順に持つ。

- `rect`（絵を描くブロックの四角: 西・北・東・南）、`grid`（`x0`、`y0`、`width`、`height`）、`blocks`。
- `layers`: 層ごとに、次の項目。
  - `kind`: `ground`、`canopy`、`water`、`sea`、`building`、`contour`、`rail`。
  - `paint`: 地面の色の名前、建物の色の名前、水底の `sand` / `rock`。ほかは、種類の名前。
  - `band`: 深さの帯の番号。`sea` だけ。
  - `set`: その層が、どのスタイルの値で作られたか（下）。
  - `cells`: 覆う 1 m のマスの数。
  - `rings`（輪: `area` m²、`points` = x, y の並び m）、
    または `lines`（等高線: `level` m と `points`）。
- 輪は、1 m のマスクを、potrace の多角形の処理で輪郭にしたもの。頂点を、すべて角として持つ。
  外周と穴を、見つけた順に並べる。偶奇の規則で塗ると、元のマスクになる。
- `set` は、スタイルの値で中身が変わる層の、スタイルの値を表す名前。
  - `ground:<地面の種類ごとの色の名前>`
  - `canopy:<minArea>`
  - `sea:<bands>;<rockMinArea>`
  - `buildings:<建物の色の表と地区の表の要約>`
  - `contours:<interval>`
  - 地図のスタイルと同じ名前の層だけを描く。水と線路は、名前なし。

**`shade-<key>.grid`**

- 陰影の明るさ（`light`、u8 = 255 × 明るさを四捨五入。0.5 は偶数へ）。
- 付記: `flat`（平らな所の明るさ）、`shade`（作ったときのスタイルの `blur`・`altitude`・`lights`）。
  強さは、描くときにかける。
- 地図のスタイルの、陰影の値の組ごとに 1 つ。
  `<key>` は、その値の組の JSON の SHA-256 の先頭 12 桁。
- 同梱のアトラスのスタイル 2 つは、強さしか違わないので、1 つを共有する。
- どのスタイルも使わなくなったものは、セルを作り直すときに消す。

**`ground-<スタイル>.png`**

地面の画像を持つスタイルの、1 m の画像。
RGBA。画素 (0, 0) = 格子の点 (0, 0)。水とブロックの外は、透明。

**`record.json`**

- 作ったときのブロック。
- ブロックごとの高さの出どころ。
  `scan` = 地面の採取、`both` = 地面の採取と高さデータの高い方。
- 作った層の、スタイルの値を表す名前。
- 陰影の値の組の一覧 `shades`。
- 地面の画像のスタイルごとの値。
- 層と輪の数、かかった秒。
- `inputs`: ブロックごとに、読んだ地表・採取・高さの格子のファイルの中身のハッシュ
  `landcover`・`scan`・`height`。高さの格子は、品質重視のときだけ。
- `regions`: 地域の色の `<key>` ごとに、地面の画像が読んだ部分のハッシュ。
  地域の色を使わないときは、null。
- `outputs`: 書いた `layers.json`・`shade-*.grid`・`ground-*.png` の、ファイルごとの中身のハッシュ。

**`draw-<地図>.json`**

その地図のセルを描いたときに使ったものの、ハッシュ。

- `prep`: セルの地図データのうち、その地図が読むものの、`outputs` のハッシュをまとめたもの。
  読むものは、`layers.json`、そのスタイルの陰影と地面の画像。
  ほかのスタイルのファイルが変わっても、変わらない。
- `roads`: 道の形のうち、セルの四角の外 50 m までにかかるもの。
- `labels`: その言語の文字のうち、中心がセルの四角の外 200 m までにあるもの。
  道路地図は、空の一覧のハッシュ。
- `pois`: その地図に出る POI のうち、同じく 200 m まで。地図に描く値のハッシュ。
  横にラベルを書く POI（POI スタイルの `showLabel`）は、ラベルが西から届くものも。

### 道の形（data/road-shapes.grid）

道を描くための形。

- ゲームファイルの道のリンク（`game/paths.json`）と通り名（`names.json`）、
  範囲の地表の水（`water`）と材質（`surface`）から作る。
- 座標は、ゲーム座標の m（x 東、y 北）。
- グリッドのファイル（下）。
  輪や線の集まりは、点を 1 つの `n × 2` の f64 の配列にまとめる。
  項目ごとの点の始まりを、`…Start`（i32、項目の数 + 1）に持つ。

| 配列 | 中身 |
|---|---|
| `tracks`（f64、n × 4） | 未舗装の道の短い区間（x0, y0, x1, y1） |
| `ground.class`、`ground.casing`（`Start`）、`ground.fill`（`Start`） | 地面の高さの道 |
| `raised.level`、`raised.class`、`raised.casing`（`Start`）、`raised.fill`（`Start`） | 段 1 以上の区間の帯 |
| `cornerPatches.class`、`cornerPatches.ring`（`Start`） | 角のつぎ |
| `junctionCorners.class`、`.region`（`Start`）、`.arc`（`Start`）、`.seam`（`Start`） | 交差点の角の丸め |
| `tunnels.group`（i32、輪ごと）、`tunnels.ring`（`Start`） | トンネルのまとまりごとの、輪郭の輪 |

- `tracks`: 幅 `trackWidth`（付記）の線で描く。
- `ground`: 道の片ごと・格ごとの帯。縁取りの輪と、塗りの輪。
- `raised`: 段 1 以上の区間は、ほかの道の上を通る所。
- `cornerPatches`: 2 本以上の道の端が同じノードで止まる所で、端の角を、角度の順につないだ多角形。
- `junctionCorners`: 道の色で塗る所、縁取りで描く弧、縁に沿ったつなぎ目。
- 格（`class`）: 0 道、1 高速、2 未舗装。
- 付記: `trackWidth`（5 m）、`casing`（縁取りの幅 0.6 m）、`pieces`、`tunnelPieces`。

作り方（`Docs/development.ja.md` の「道」）:

- 描くのは、車のリンク。近道のリンクを除く。道の編集を適用したもの。
- 船の航路は、外す。
  船の航路は、半分以上が水の上の、交差点から交差点までの並び。
- 交差点の中のリンクは描かず、来る道を延ばす。
  交差点の中のリンクは、交差点の記録があり、3 本以上がつながるノードのもの。
- 道の片は、2 本だけがつながるノード（まっすぐ続く組の所）を通って続く、リンクの並び。
- 中心線は、ノードを通る曲線で、2 m ごと。
- 幅は、車線数から。片に沿って、30 m で平らす。
- ほかの道の 3 m 以上上を通る所は、段を上げる。
- 未舗装は、交差点から交差点までの並びの半分以上が、自然の地面の材質のとき。

**`data/road-shapes-record.json`**

- 作ったときのブロックの一覧（`blocks`）。範囲がこれと違えば、作り直す。
- 数。
  描けるリンク、外した船の航路、高速、未舗装の km、描いたリンク、延長・通し・到達、fork、
  まっすぐ続く組、ほかの道の上を通るリンク、片、トンネルの片、地面の帯、段ごとの帯、角のつぎ、
  交差点の丸め、未舗装の区間、トンネルのまとまりと輪。
- かかった秒。
- `cells`: 範囲のセルごとに、そのセルの描画が使う形の中身のハッシュ。
  使う形は、セルの四角の外 50 m までにかかる、トンネルのまとまり・未舗装の区間・帯・角・段の帯。
- `roadEdits`: 適用した道の編集。`roads-record.json` と同じ形。

### グリッドのファイル（*.grid）

地図データの途中の格子（地表など）の形。
名前付きの 2 次元の配列と、少しの付記。

```
"FXGRID1\n"                8 バイト
u32（リトルエンディアン）   見出しの長さ
見出し                      UTF-8 の JSON: { "meta": {…}, "arrays": [ { "name", "type", "width", "height", "bytes" } ] }
配列を見出しの順に          行優先・リトルエンディアンの値を zlib で縮めたもの（"bytes" バイト）
```

型: `bool`（1 バイトの 0 / 1）、`u8`、`i16`、`u16`、`i32`、`u32`、`f32`、`f64`。

### state/blocks.json

```json
{
  "z8_60_128": {
    "items": { "shot": "2026-01-15T12:27:51.28Z", "height": "2026-01-15T12:27:51.28Z" },
    "captures": { "shot": 1, "height": 1 },
    "retake": false
  }
}
```

- データ項目: `shot`（撮影画像）、`height`（高さの格子）、`scanGround`、`scanRoads`、`scanCanopy`（採取）。
  値は、取った時刻（UTC）。
- `captures`: 項目ごとの、取ったときのリソースの取り方の番号（`link-protocol.ja.md` の「版」）。
  取り込んだデータと、番号を応答しないリソースで取った項目には、ない。
- `retake`: 再取得の印。
  印のあるブロックは、項目がないものとして数える。
  次の撮影・採取で、古い項目を消して、印を外す。

### state/stages.json

```json
{
  "ortho": { "z8_60_128": "2026-01-15T12:28:03.11Z" },
  "lowZoom": { "satellite": "2026-01-15T13:10:41.13Z" },
  "ytd": { "satellite@4096/0_0": "2026-01-15T13:12:02.50Z" }
}
```

ステップの単位ごとに、出力を書き終えた時刻。

- 出力は、その記録が入力より新しければ、済みとみなす。
  入力は、データ項目や、前のステップの記録。
- セルの地図データ・セル描画・ミニマップのシートは、入力の方が新しくても、
  読む部分の中身が作ったときと同じなら、済みとみなす。
  - 中身のハッシュ = SHA-256 の先頭 128 ビットを、各記録に持つ。
  - ハッシュのない記録は、中身が違うものとして扱う。
- 地表は、道路グラフだけを、中身で比較する（ハッシュがなければ、時刻）。
  ブロックとまわりのブロックの採取・高さは、時刻で比較する。
- そのため、一部のブロックを取り直した後は、全域で 1 つのステップは作り直すが、
  描き直すのは、中身の変わったセルだけになる。
  全域で 1 つのステップは、ゲームファイル・道路グラフ・地域の色・文字・道。

| キー | 単位 | ステップ |
|---|---|---|
| `ortho` | ブロック | オルソ補正と、z8 の衛星タイル |
| `gameFiles` | `world` | ゲームファイル（`game/`） |
| `roadGraph` | `world` | 道路グラフ（`data/roads.json`） |
| `landcover` | ブロック | 地表（`data/landcover/<block>.grid`） |
| `regions` | `world` | 地区と地域の色（`data/zones.grid`、`data/regions-<key>.grid`） |
| `labels` | 言語 | アトラス地図の文字（`data/labels-<言語>-<key>.json`） |
| `cellPrep` | セル | セルの地図データ（`cells/<セル>/`） |
| `roads` | `world` | 道の形（`data/road-shapes.grid`） |
| `cells` | `<地図>/<セル>` | アトラスと道路地図のセル描画 |
| `lowZoom` | 地図の id | 範囲の外の外洋の塗りと、枠の z7〜z0 |
| `ytd` | 下の 3 つ | ミニマップのテクスチャ辞書 |

キーごとの詳細は、次のとおり。

**`ortho`**

- 撮影の間に仮の縮尺で作ったものも、同じ記録。
- 作り直すのは、ブロックの撮影か、写真の位置合わせに使う高さ（`PhotoItems`）が、これより新しいとき。
  `PhotoItems` は、速度重視は高さデータ、バランスは地面の採取、品質重視は両方。
- 縮尺の補正が変わったときは、全ブロックの記録を消す。

**`gameFiles`**

- 読み直すのは、次のどれかのとき。
  - 範囲の道の採取が、これより新しい。
  - `gameFiles.serverResources` が、`sources.json` と違う（中身か順番）。
  - プロジェクトの枠の足したセルか、`cayoPerico` が、`sources.json` と違う。
  - ファイルがない。
- 読む区画は、プロジェクトの枠の下にある、道の格子の区画だけ。
  道の格子は、32 × 32、x・y とも −8192〜8192 m。
- 範囲に道の採取のないブロックがある間は、待つ。

**`roadGraph`**

- 作り直すのは、次のどれかのとき。
  - ゲームファイルか、範囲の道の採取が、これより新しい。
  - 範囲が、`roads-record.json` のブロックと違う。
  - 道の編集の中身が、記録の `roadEdits` と違う。
    ファイルを替えたとき、null にしたときも。同じ中身で保存し直したときは、作り直さない。
  - ファイルがない。
- 道の編集のファイルが読めないときは、理由を出して失敗する。
- 道の採取のないブロックがある間と、ゲームファイルが古い間は、待つ。

**`landcover`**

- 作り直すのは、次のどちらかのとき。品質重視では、高さデータも入力。
  - ブロックの地面と道の採取、まわり 8 ブロックのうち地面の採取のあるもの（範囲の外でも）のそれの、
    どれかが、これより新しい。
  - ファイルがない。
- 次のどれかのときは、全ブロックを作り直す。
  - `landcover-record.json` の高さが、高さの品質と違う。
  - 記録がない。
  - 道路グラフの中身が、記録の `roadGraph` と違う。駐車場の決まりが読むため。
    同じ中身で作り直された道路グラフでは、作り直さない。
- 次の間は、待つ。
  - ブロックに、地面か道の採取がない間。品質重視では、高さデータも。
  - 範囲の中のまわりのブロックに、地面の採取がない間。同じく、高さデータも。
  - 道路グラフが古い間。

**`regions`**

- 地域の色の 4 m の格子は、プロジェクトの枠を覆う。区切りは、標準の枠の北西の角にそろえる。
- 作り直すのは、次のどれかのとき。
  - 範囲のブロックの道の採取か地表が、これより新しい。
  - 範囲かプロジェクトの枠が、`regions-record.json` のブロックか、足したセル（`extraCells`）と違う。
  - 地域の色を使う地図のスタイルの `regions` の `<key>` が、記録（`fields`）にない。
  - ファイルがない。
- 道の採取のないブロックがある間と、範囲に地表のできていないブロックがある間は、待つ。

**`labels`**

- 作り直すのは、次のどれかのとき。
  - 道路グラフ・地区・ゲームの名前が、これより新しい。
  - アトラス地図のスタイルの、置き方のハッシュの文字がない。
  - 番地のコピーか、POI か、道の編集の通り名（`streetsSha256`）か、
    プロジェクトの `cayoPerico` が、記録と違う。
  - ファイルがない。
- 番地の元か、道の編集のファイルが読めないときは、理由を出して失敗する。

**`cellPrep`**

- 作り直すのは、次のどれかのとき。
  - セルのブロックの地表・採取・高さデータのどれかが、これより新しく、
    中身が `record.json` の `inputs` と違う。
  - `record.json` のブロックの高さ（`scan`・`both`）が、今の高さの品質の高さと違う。
  - 地図のスタイルの値が、`record.json` にないか、違う。
    スタイルの値は、層のスタイルの値を表す名前、陰影の値の組、地面の画像。
  - 地域の色を使うスタイルがあって、地域の色がこれより新しく、
    セルの部分が、`regions` のその `<key>` のハッシュと違う。
  - ファイルがない。
- 範囲に地表のできていないブロックがある間と、地域の色が古い間は、待つ。

**`roads`**

- 作り直すのは、次のどれかのとき。
  - ゲームファイルか、範囲のブロックの地表が、これより新しい。
  - 範囲が、`road-shapes-record.json` のブロックと違う。
  - 道の編集の中身が、記録の `roadEdits` と違う。
  - ファイルがない。
- ゲームファイルと道路グラフが古い間と、範囲に地表のできていないブロックがある間は、待つ。

**`cells`**

- ステップは、地図ごとに `cells.<地図>`。
- 作るのは、セルの自分のブロックの z8 タイルと、その上の z7〜z5。
  セルは、z5 のタイルの格子にそろった 8×8 ブロック。
  そのため、z5 のタイルは、2 つのセルにまたがらない。
- 描き直すのは、次のどれかのとき。
  - 地図のスタイルが、`data/draw-<地図>.json` の記録と違う。
  - セルの `draw-<地図>.json` がない。
  - セルが使うものの中身が、記録と違う。
- セルが使うものは、次の 4 つ。
  前の 3 つは、そのステップがこれより新しいときだけ、比較する。
  - セルの地図データのうち、その地図が読むもの。
  - 道の形のうち、セルのまわりのもの。
  - その言語の文字のうち、セルのまわりのもの（アトラスだけ）。
  - POI。
- 道の形・文字がない間は、待つ。

**`lowZoom`**

- ステップは、`lowZoom.<地図>`。
- 作るのは、プロジェクトの枠の中で範囲の外の、外洋の塗りと、枠の z7〜z0。
- 塗る色は、次のとおり。
  - 衛星地図は、外洋の色を、写真から取る。
  - アトラスと道路地図は、スタイルの海の最も深い帯の色（`paint.sea.sand` の最後）。
    その帯の不透明度（`paint.sea.opacity` の最後）で塗る。
  - 塗った色は、`data/sea-<地図>.txt`。
    不透明度が 1 でないときは、色の後ろに、空白と不透明度。
- 作り直すのは、次のどれかのとき。
  - 地図のタイル（オルソ補正かセル描画）が、これより新しい。
  - アトラス・道路地図の、その色が変わる。
  - プロジェクトの枠が、`data/low-zoom-<地図>.json` と違う。
    枠を狭めたときは、枠の外に残ったタイルを、すべてのズームで消す。
- セル描画の済んでいないセルがある間は、待つ。

**`ytd`**

単位は、`<地図>@4096/<行>_<列>`、`<地図>@4096/lod`、`<地図>@4096/cell_<行>_<列>`。

- `<行>_<列>`: シート。次のどちらかのとき、作り直す。
  - 範囲の外の扱いが、`minimap-<地図>.json` と違う。
  - 地図の縮小タイルがこれより新しく、シートを作る z6 のタイル 16 × 16 枚の中身が、
    `minimap-<地図>-<行>_<列>.json` の `source` と違う。
- `lod`: 全体図 `minimap_lod_128`。
  縮小タイルがこれより新しく、標準の枠の z2 のタイル 6 枚の中身が、
  `minimap-<地図>-lod.json` の `source` と違えば、作り直す。
- `cell_<行>_<列>`: 標準の枠の外のセルのテクスチャ。範囲のブロックを持つセルごと。
  シートと同じ決まりで、そのセルの z6 のタイル 8 × 8 枚の中身が、
  `minimap-<地図>-cell_<行>_<列>.json` の `source` と違えば、作り直す。

### state/scale.json

```json
{
  "fov2": { "qx": 0.99667, "qy": 0.98868, "pairs": 1800, "measuredUtc": "2026-01-15T13:10:12.00Z" },
  "tiles": { "qx": 0.99667, "qy": 0.98868, "pairs": 0, "measuredUtc": "2026-01-15T12:27:44.30Z" }
}
```

- `fov<視野角>`: このプロジェクトの縮尺の補正。
  x と y、隣り合う撮影の重なりから測った組の数。
  一度測ると、次からはこれを使う。
  コマンドの `--recalibrate` で測り直し、`--scale` で指定する。
- `tiles`: 今のオルソ補正の記録（と衛星タイル）を作った補正。
  これと違う補正で作るときは、全ブロックを作り直す。
- 撮影の間は、ブロックを撮るたびに、このプロジェクトの補正でオルソ補正して、記録する。
  なければ、同梱の既定値。
- 撮影の後に測った補正が、`tiles` とブロックの端で 3 cm 未満しか違わなければ、
  `tiles` の補正を、そのままこのプロジェクトのものにする。
  3 cm は、z8 の 1 画素の 1/10。

### state/capture-resource.json

exe は、サーバーのフォルダを見られない。
そのため、撮影用リソース（`fxmapgen-capture`）がサーバーにあることを、この印で持つ。
印の版が exe の版と違えば、印はないのと同じ（新しい版のリソースが要る）。

| 項目 | 中身 |
|---|---|
| `version` | 印を付けたときのリソースの版 |
| `how` | 印の付き方 |
| `atUtc` | 付けた時刻 |
| `folder` | 書き出したフォルダ（`saved` のときだけ） |

`how` の値:

- `saved`: 画面で、フォルダに書き出した。
- `answered`: リソースの起動か事前確認で、リソースがその版で応答した。
- `user`: 利用者が、チェックを付けた。

### state/capture-stopped.json

- 範囲のブロックをすべて撮影・採取した実行は、最後に、撮影用リソースを止める。
- 止められたとき（止めた後に、応答がなくなったとき）に書く。
- これより前の接続の確認（`logs/precheck-<時刻>/`）は、確認していないものとして扱う。
  次の撮影・採取の前に、リソースの起動と接続の確認を、もう一度する。

| 項目 | 中身 |
|---|---|
| `atUtc` | 止めた時刻 |
| `resource` | 止めたリソースの名前（応答した名前） |

### state/settle.json

事前確認で測った、描画の安定待ち。
測れたときだけ書く。測れなければ消し、撮影は、既定の 1.5 秒で待つ。

| 項目 | 中身 |
|---|---|
| `atUtc`, `district` | 測った時刻と地区（`north` / `south`） |
| `blocks` | 撮ったブロックごとの値 |
| `stableMs` | 測れた 2 ブロックの長い方 |
| `waitMs` | 撮影で送る落ち着き待ち |
| `fps` | 描く速さ |

- `blocks`: 名前、画面が変わらなくなるまでの ms（`stableMs`、測れなければ null）、fps、
  落ち着き待ちの ms、最大の読み込み要求、水の点、0.2 秒ごとの変化の割合、測れなかった理由。
- `waitMs`: `stableMs` の 1.5 倍。10 ms 単位で切り上げ。

### logs/run-<時刻>/

| ファイル | 中身 |
|---|---|
| `inputs/` | 実行を始めたときの、入力のコピー。実行は、これを読む |
| `run.log` | 実行の記録（時刻つきの行） |
| `units.csv` | 単位ごとに 1 行 |
| `run.json` | 最後の状態、並列数の変更、失敗、始めたときのやることの表 |
| `console.log` | 撮影の実行だけ: ゲームとの会話 |
| `stopped-resources.txt` | 撮影の実行だけ: クライアントで止めたリソース |

- `inputs/` にコピーするもの:
  - プロジェクトファイル。
  - 道の編集のファイル（あれば）。
  - `styles/` に、地図が使う自分のスタイル。
  - `poi/` に、POI のフォルダ。
  - `poi-styles.json` に、POI スタイルのファイル。それが指定している PNG は、その横に。
- `units.csv` の列は、`stage,unit,started_utc,seconds,result,workers`。
  - 結果は、`done` / `failed` / `interrupted`。
  - `workers` は、そのときの並列数の上限。
  - 撮影と並べて実行したオルソ補正は、`stage` が `ortho.provisional`。
- `stopped-resources.txt`: 撮影の後に、`ensure` で戻したもの。

### logs/precheck-<時刻>/

- `report.json`: 確認項目ごとの合否・値・理由のコード、描画の安定待ちの測定。
- `shot.png`: テスト撮影。
- `shot-marked.png`: 地図に使う範囲と、目立つものを描いたもの。
- `console.log`。
- `settle-<block>-first.png` / `-last.png`: 測ったブロックの最初と最後の画面の、地図に使う範囲。

## 書き出し先

```
<書き出し先>/
  fxmapgen-export.json          このフォルダの書き出しの記録。これがあるフォルダには上書きできる
  web/ または web.zip           index.html、leaflet/、tiles/<地図>/{z}/{x}/{y}.png、lb-phone.lua、README.txt、CREDITS.txt
                                （tiles の <地図> は、英語のアトラス地図が atlas-<スタイル>、ほかは地図の id）
  fxmapgen-minimap-<日付>/      ミニマップのリソース
  editable/                     編集用のファイル。<地図>-z<ズーム>.psd（PSD に入らない大きさは .psb）
                                と、<地図>-z<ズーム>.svg、その SVG がリンクする PNG のフォルダ <地図>-z<ズーム>-svg/
                                （<地図> は、tiles のフォルダと同じ名前）
  web-edited/<地図>/            編集した画像の Web タイル。中身は web/ と同じで、地図は 1 つ
                                （<地図> は、画像の元の地図の、tiles のフォルダと同じ名前）
```

### 書き出しの Web タイルの番号

- プロジェクトの枠の上か左にセルを足したときだけ、
  書き出す Web タイルは、枠の北西の角を原点に、番号を振り直す。
  ビューアも、lb-phone の例も、その原点で書く。
  loaf-scripts の地図タイルの代わりに、そのまま使うことはできない。
- 1 セルは、z3 のタイル 1 枚。
  そのため、z3〜z8 は、作業フォルダのタイルを、番号をずらしてコピーする。
  z2〜z0（枠の角をまたぐ）は、書き出した z3 から作り直す。
- 右と下にだけ足したときと、標準の枠では、番号は作業フォルダと同じ。
- 書き出すのは、どの地図も、プロジェクトの枠の中のタイルだけ。
- ビューアの枠（`index.html` の `LEFT`・`TOP`・`RIGHT`・`BOTTOM`）と、
  lb-phone の例の `topLeft`・`bottomRight`・`resolution` は、プロジェクトの枠から書く。

`fxmapgen-export.json`:

| 項目 | 中身 |
|---|---|
| `atUtc`, `version`, `project` | 最後に書き出した時刻、exe の版、プロジェクトファイル |
| `web` | 最後に書いた Web の部分 |
| `resources` | このフォルダに書いたミニマップのリソース（`atUtc`、`name`、`map`、`size`） |
| `editable` | このフォルダに書いた編集用のファイル |
| `webEdited` | このフォルダの `web-edited/` に書いた、編集した画像の Web タイル |

- `web`: `atUtc`、`maps`、`zip`、`tiles`（枚数）、`bytes`、`baseUrl`、
  `complete`（途中で止めていないか）、`maxZoom`。
- `resources`: フォルダを消したものは、次の書き出しで外れる。
  編集した画像から作ったリソースは、`fromPicture` が true。
- `editable`: `atUtc`、`map`、`zoom`、`format`、`file`（`editable/` の中の名前）、`bytes`、
  `width`・`height`（画素）、`layers`（レイヤーの名前。下から順）。
  同じ名前のファイルを書くと、前の行と入れ替わる。ファイルを消したものは、次の書き出しで外れる。
  `format` は `psd` か `svg`。
  SVG の `bytes` は、リンクする PNG を含む。
- `webEdited`: `atUtc`、`name`（`web-edited/` の中のフォルダ名）、`map`（元の地図の id）、
  `picture`（画像のファイル名）、`zoom`（画像のズームレベル）、`tiles`（枚数）、`bytes`、
  `complete`（途中で止めていないか）。
  同じ名前で書くと、前の行と入れ替わる。フォルダを消したものは、次に書くときに外れる。

## アプリの設定（プロジェクトではない）

`%LOCALAPPDATA%\FxMapGenerator\settings.json`。`--data-dir` で変えられる。

| 項目 | 中身 |
|---|---|
| `recentProjects` | 最近のプロジェクト |
| `language` | 言語: `auto`・`ja`・`en` |
| `theme` | 表示: `system`・`light`・`dark` |
| `jobListWidth` | 計画・進捗の画面の、右の欄の幅（px） |
| `gtaFolder` | GTA V のフォルダ |
| `keysFolder` | RPF の鍵のフォルダ |
| `guides` | 画面のガイドへの答え |

`guides` は、ガイドの id → `seen` か `never`。

- `seen`: 表示した。最後まで見たか、途中で閉じた。
- `never`: 今後表示しない。
- 答えのない画面は、初めて開いたときに、表示するかを聞く。

**GTA V と鍵のフォルダ**

- GTA V と鍵のフォルダは、この PC のもので、プロジェクトは持たない。
- 起動の引数（`--gta`・`--keys`）→ この設定 → 見つけられるもの、の順に決まる。
- GTA V は、環境変数 `GTA_FOLDER`、次にレジストリ（Steam・Rockstar・Epic）。
- 鍵は、4 つのファイルがそろったフォルダを、次の順に探す。EmotePreviewer と共用できる。
  環境変数 `FXMAPGEN_KEYS` → `%LOCALAPPDATA%\FxMapGenerator\keys` → `%LOCALAPPDATA%\EmotePreviewer\keys`。
- 4 つのファイルは、`gtav_aes_key.dat`、`gtav_ng_key.dat`、`gtav_ng_decrypt_tables.dat`、
  `gtav_hash_lut.dat`。EmotePreviewerKeyTool で作る。
- 引数か設定でフォルダを指定したときは、そのフォルダだけを見る。

**共通のスタイル**

- 同じフォルダの `styles\`。形は、`style-format.ja.md` の「自分のスタイル」。
- スタイルエディタの「共通のスタイルに保存」で置く。
- どのプロジェクトでも、「複製…」の元に選べる。選ぶと、プロジェクトの `styles` にコピーする。

**スタイルエディタの見本の土地**

- 同じフォルダの `sample-island\`。
- プレビューを初めて開いたときに、アプリが作る。
  同梱の見本の土地のプロジェクトと、ゲームなしのステップで作った、セルの前処理までのデータ。
- `sample.json` に、アプリの版と、同梱のデータの SHA-256 を書く。どちらかが違えば、作り直す。
- 消してもよい。次にプレビューを開いたときに、作り直す。
