# 道のノードのファイル（ynd）の読み方

FxMapGenerator がアトラス・道路地図の道を描くのに読む、GTA V の `nodesNNN.ynd` の中身と、
作業フォルダに書く形。

- 読むコード: `src/FxMapGenerator.GameData/Paths/YndFile.cs`
- 書くコード: `src/FxMapGenerator.Core/GameFiles/`

## ファイルの置き場と区画

**区画**

- 1 つのファイルが、512 m 角の区画 1 つを持つ。
- 区画は、(−8192, −8192) から東へ 32 列、北へ 32 行。
  番号は `行 × 32 + 列`（ファイル名の NNN）。
- 区画の格子は、y 8192 まで。
  そのため、標準の枠（−4140, 8400）〜（4860, −5100）には、行 6〜31・列 7〜25 の 494 区画がかかる。
  そのうち、ファイルがあるのは 254。
  枠の y 8192 より北の部分と、そこへ足したセルに、区画はない。
- プロジェクトの枠を広げると、その枠にかかる区画を読む。

**カヨ・ペリコの島の道**

- 島の道は、区画の番号に 1024 を足した番号のファイルにある。
  区画 153 の島の道は、`nodes1177.ynd`。ノードが持つ区画の番号は、元の 153 のまま。
- プロジェクトの `cayoPerico` がオンのとき、島のファイルがある区画は、
  元の番号のファイルの代わりに、島のファイルを読む。
  島の区画は、すべて島のファイルにそろえる。

**ゲームのアーカイブの順**

- ゲームの中では、同じ区画が、複数のアーカイブにある。
- 使うのは、次の順で最初のもの。
  `update\update.rpf` > `update\x64\dlcpacks` の DLC > ほかの DLC > 基底のアーカイブ。
- 同じ順位に 2 つあれば、索引の順で先のものを取り、記録に残す。

**サーバーの ynd**

- サーバーが自分のリソースで配る ynd（地図の追加パックなど）は、区画をまるごと置き換える。
- プロジェクトの `gameFiles.serverResources` に、次のものを、**サーバーが ensure する順に** 並べる。
  フォルダは、どれもコピーでよい。
  - サーバーの resources フォルダ。
  - カテゴリのフォルダ（`[maps]` など）。
  - リソース 1 つのフォルダ。
  - パックの zip。
  - ynd のファイル 1 つ。
- 同じ区画のファイルが 2 つ以上あれば、**後勝ち**: 一覧の後の項目が勝つ。
- 1 つのフォルダの中は、パスをフォルダ名ごとに辞書順に並べ、後のものが勝つ。
  - 英字は小文字にそろえて、1 文字ずつ比較する。`[maps]` → `a` → `a b` → `B` の順。
  - 数字も文字として比較するので、`res10` は `res9` より前。
- 上書きされたものは、記録と実行のログに出す。
- フォルダは、下のフォルダまで全部探す。そのため、サーバーで ensure していないリソースも拾う。
  要らないものが入っているときは、使うフォルダだけを並べて指定する。

## 中身

RSC7 のリソース（版 1）。
gta-toolkit の `NodesFile` が 5 つの配列を読み、欄の意味はここで決める。
数は、リトルエンディアン。

**ノードの名前**

- ノードの名前（`区画:ノード`）は、**ファイル名の区画と、ノードの配列の中の順番**（0 から）。
  リンクと交差点の参照が、この 2 つで相手を指すため。
- ノードに書いてある区画（0x10）と番号（0x12）は、比較するだけ。
- 違うノードのあるファイルは、ログと `sources.json` の `numberMismatches` に出す。読むのは止めない。
- ゲームのファイルでは、どのノードも一致する。

**読めないファイル**

- サーバーの ynd が読めないときは、そのファイルを飛ばす。
  その区画は、前のファイルのままにする。
  前のファイルは、ゲームのもの、または一覧で先のサーバーのもの。
- 読めないのは、次のとき。
  - 先頭の 4 バイトが RSC7 でない。
    Cfx のアセットの暗号化 `FXAP`、GTA V Enhanced の `RSC8`、ほかの何か。
  - RSC7 だが、中身を展開できない。
- ファイルの場所と理由を、ログと `sources.json` の `serverFileErrors` に出す。
- ゲームのアーカイブの中のファイルが読めないときは、止まる。

**ノード（40 バイト）**

| 位置 | 型 | 中身 |
|---|---|---|
| 0x10 | u16 | 区画の番号 |
| 0x12 | u16 | 区画の中のノードの番号 |
| 0x14 | u32 | 通り名のハッシュ（GXT2 のキー。0 は名前なし） |
| 0x1a | u16 | リンクの配列の中の、最初のリンクの位置 |
| 0x1c / 0x1e | i16 | x × 4 / y × 4（m） |
| 0x20 | u8 | f0: bit 3 未舗装、bit 5 大きな車が通らない、bit 7 左折できない |
| 0x21 | u8 | f1: bit 0 合流の車線、bit 1 左に寄る合図、bit 2 右に寄る合図、bit 3〜7 特別な種類 |
| 0x22 | i16 | z × 32（m） |
| 0x24 | u8 | f2: bit 0 GPS に使わない、bit 2 交差点、bit 4・7 普段の交通が走らない、bit 6 高速 |
| 0x25 | u8 | bit 0 交差点の記録がある、bit 1〜2 速さ、bit 3〜7 リンクの数 |
| 0x26 | u8 | f3: bit 0 トンネル、bit 1〜7 経路探索用の値（0〜127） |
| 0x27 | u8 | f4: bit 0〜3 交通の多さ、bit 4〜6 行き止まり |

- f2 の bit 4 と bit 7 は、同じ値。
- 速さは、遅い・普通・速い・もっと速い。
- 特別な種類は、下の表。10・14・18 は、歩行者のノード。
- ノードの数は、車のノード（先）と歩行者のノードを合わせたもの。

| 値 | 特別な種類 |
|---|---|
| 0 | なし |
| 2 | 駐車場 |
| 10 | 歩行者の横断 |
| 14 | 歩行者の補助移動 |
| 15 | 信号の停止線 |
| 16 | 一時停止 |
| 17 | 注意 |
| 18 | 歩行者の横断（待たない） |
| 19 | 緊急車両だけ |
| 20 | 未舗装の交差点 |

**リンク（8 バイト）**

| 位置 | 中身 |
|---|---|
| 0x00 | u16 相手の区画 |
| 0x02 | u16 相手のノード |
| 0x04 | f0: bit 0 GPS で両向き |
| 0x05 | f1: bit 1 狭い道、bit 4〜6 車線のずれの大きさ、bit 7 ずれの向き |
| 0x06 | f2: bit 0 ナビに使わない、bit 1 近道、bit 2〜4 逆向きの車線数、bit 5〜7 順向きの車線数 |
| 0x07 | 長さ |

- ノードは、自分のリンクを、「最初の位置」から「リンクの数」だけ持つ。
- どのリンクも、両端のノードから 1 回ずつ出てくる。
  一方通行の道も同じで、逆向きの側は、順向きの車線数が 0。
  2 つの車線数は、入れ替わった値。
- 「ナビに使わない」は、交差点の中へ斜めに入るつなぎや、上下線の分かれ目のつなぎに付く。
  交差点の外のリンクにもある。
- 「近道」は、車線を移るための斜めのリンク。道としては描かない。
- 「長さ」は、両端の直線の距離（m、切り捨て）と同じことが多いが、4 本に 1 本ほどは合わない。
  何を測った値かは、分かっていない。このツールは使わない。

**交差点の記録（12 バイト）**

| 位置 | 中身 |
|---|---|
| 0x00 | i16 最大の z × 32 |
| 0x02 / 0x04 | i16 格子の角の x × 4 / y × 4 |
| 0x06 | i16 最小の z × 32 |
| 0x08 | u16 高さのバイト列の中の位置 |
| 0x0a | u8 x 方向の数 |
| 0x0b | u8 y 方向の数 |

格子は 2 m ごとで、1 点 1 バイト。
0〜255 を、最小〜最大の z に割り当てる。

**交差点の参照（8 バイト）**

| 位置 | 中身 |
|---|---|
| 0x00 | u16 区画 |
| 0x02 | u16 ノード |
| 0x04 | u16 交差点の記録の番号 |
| 0x06 | u16 |

## 作業フォルダに書くもの（`game/`）

どれも利用者のゲームから作ったもので、配らない。

### `paths.json`

地図の枠の全区画の、車のノードとリンク。

```json
{
  "areas": [199, 200, …],
  "nodes": {
    "464:12": { "x": 215.25, "y": -800.5, "z": 30.125, "street": 1234567890, "junction": true,
                "highway": false, "tunnel": false, "unpaved": false, "switchedOff": false,
                "noBigVehicles": false, "cannotGoLeft": false, "slipLane": false,
                "indicateKeepLeft": false, "indicateKeepRight": false, "noGps": false,
                "special": "none", "trafficDensity": 5, "speed": "normal", "deadEnd": 0, "heuristic": 12,
                "junctionArea": [205.75, -810, 225.75, -790] }
  },
  "links": [
    { "from": "464:12", "to": "464:13", "lanesForward": 2, "lanesBack": 2, "narrow": false,
      "dontUseForNavigation": false, "shortcut": false, "laneOffset": 0, "gpsBothWays": false, "length": 9 }
  ]
}
```

| 欄 | 元 | 意味 |
|---|---|---|
| `areas` | — | 読みにいった区画 |
| ノードのキー | — | `区画:ノード`（ファイル名の区画と、配列の中の順番） |
| `x`・`y`・`z` | 0x1c・0x1e・0x22 | 位置（m、小数 3 桁に丸める） |
| `street` | 0x14 | 通り名のハッシュ（`names.json` で引く。0 は名前なし） |
| `junction` | f2 bit 2 | 交差点 |
| `highway` | f2 bit 6 | 高速 |
| `tunnel` | f3 bit 0 | トンネル |
| `unpaved` | f0 bit 3 | 未舗装 |
| `switchedOff` | f2 bit 7（bit 4 も同じ値） | 普段の交通が走らない |
| `noBigVehicles` | f0 bit 5 | 大きな車が通らない |
| `cannotGoLeft` | f0 bit 7 | 左折できない |
| `slipLane` | f1 bit 0 | 合流の車線 |
| `indicateKeepLeft`・`indicateKeepRight` | f1 bit 1・bit 2 | 左に寄る合図・右に寄る合図 |
| `noGps` | f2 bit 0 | GPS に使わない |
| `special` | f1 bit 3〜7 | 特別な種類 |
| `trafficDensity` | f4 bit 0〜3 | 交通の多さ（0〜15） |
| `speed` | 0x25 bit 1〜2 | `slow`、`normal`、`fast`、`faster` |
| `deadEnd` | f4 bit 4〜6 | 行き止まり（0〜7） |
| `heuristic` | f3 bit 1〜7 | 経路探索用の値（0〜127） |
| `junctionArea` | 交差点の記録 | 高さの格子の四角 |
| `from`・`to` | — | リンクの両端 |
| `lanesForward`・`lanesBack` | f2 bit 5〜7・bit 2〜4 | `from` から `to` への車線数と、逆向きの車線数 |
| `narrow` | f1 bit 1 | 狭い道 |
| `dontUseForNavigation` | f2 bit 0 | ナビに使わない |
| `shortcut` | f2 bit 1 | 近道（道として描かない） |
| `laneOffset` | f1 bit 4〜7 | 車線のずれ（車線の幅の ±0.5 倍を 7 段階、小数 3 桁） |
| `gpsBothWays` | f0 bit 0 | GPS で両向き |
| `length` | 0x07 | 長さ |

表の欄の詳細:

- `areas`: プロジェクトの枠にかかる区画。標準の枠で 494。ファイルのない区画も入る。
- `special`: `none`、`parkingSpace`（駐車場）、`trafficLightStop`（信号の停止線）、`stopSign`（一時停止）、
  `caution`（注意）、`emergencyVehiclesOnly`（緊急車両だけ）、`offroadJunction`（未舗装の交差点）。
  知らない値は、番号。
- `heuristic`: ゲームが経路を探すときの目安。このツールは使わない。
- `junctionArea`: 交差点の記録のあるノードだけ。最小 x、最小 y、最大 x、最大 y（m）。
  1 つのノードに記録が 2 つあれば、後のもの。
- `from`・`to`: 向き付き。どのリンクも、両端から 1 回ずつ出る（一方通行の道も）。
- `length`: ファイルの値のまま。直線の距離とは合わないことがある。使わない。

書かないもの:

- 歩行者のノード（特別な種類 10・14・18）と、それにつながる線。
- 読まなかった区画のノードへの線。
- 交差点の記録の高さの格子。四角の範囲だけを書く。

### `sources.json`

- どこから読んだか。
  GTA V と鍵のフォルダ、サーバーの resources、区画の置き換え、同じ順位の重なり、読めなかったアーカイブ。
- 数。区画・車のノード・リンク・交差点の四角・名前。
- 次の 2 つは、あるときだけ書く。
  - 読めずに飛ばしたサーバーの ynd（`serverFileErrors`: ファイルの場所と理由）。
  - ノードに書いてある区画か番号が、ファイル名・順番と違うファイル（`numberMismatches`）。

名前のファイルは、`gxt2-format.ja.md`。
