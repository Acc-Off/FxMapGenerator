## 必要なもの

- .NET SDK 10。`global.json` で、10.0 の機能帯に固定している。
- Node.js 22 以降。画面は、App プロジェクトの `BuildWeb` ターゲットでビルドされる。
- Lua 5.4（`lua` と `luac`）。次の 2 つのテストに使う。
  Lua がなければ、`dotnet test` はこの 2 つのテストを飛ばす。
  - FiveM リソースの、構文の検査とテスト。
  - 書き出すミニマップのリソースの、スクリプトのテスト。

## 構成

- `src/FxMapGenerator.App`: exe。
  127.0.0.1 の Kestrel、コマンドライン、設定、ジョブ、ゲームとの接続。
- `src/FxMapGenerator.Core`: 処理の本体。Windows に依存しない。
  処理のステップ、格子処理、ベクタ、描画（SkiaSharp）、タイル、見積もり、プロジェクトの形式。
- `src/FxMapGenerator.GameData`: ゲームのファイル形式。
  - テクスチャ辞書（`.ytd`）、DDS の圧縮。
  - RPF のアーカイブと鍵。
  - 道のノード（`.ynd`）。
  - 文字の表（`.gxt2`）。
  - Scaleform のファイル（`.gfx`。形を何も描かないものにする）。
- `src/FxMapGenerator.Web`: 画面。Vite + React + TypeScript + Zustand。exe に埋め込む。
- `tools/FxMapGenerator.DevTools`: 開発用のコマンド。
  `devtools ytd-info`、`ytd-decode`、`calibrate`、`make-icon`、`mdi-icons`、`sample-land`、
  `sample-land-bundle`、`sample-island`、`preview-timings`、`gfx-empty`、`island-map`、`interior-maps`。
- `resource/fxmapgen-capture`: exe が、ゲームのコンソールを通して操作する FiveM リソース（Lua）。
  下の「FiveM リソース」を参照。
  ゲームのコンソールは、FiveM クライアントのコンソール（ゲームの中で F8 で開くもの）。
  サーバーのコンソールではない。
- `data/`: 同梱のデータ。
  - 既定の範囲と、範囲のプリセット（`range-presets.json`）。
  - 見積もりの既定値（`timings.json`）。
  - サーバーのプリセット。
  - 材質の名前と種類（`materials.json`・`material-classes.json`）。
  - 同梱の道路の編集（`road-edits-default.json`）。中身は、下の「同梱の編集」。
  - アトラス・道路地図のスタイル（`styles/`）。
  - スタイルエディタの項目の表（`style-schema.json`）と、見本の土地（`sample-island/`）。
  - POI とその見た目（`poi/`・`poi-styles.json`）。
  - POI スタイルの MDI のアイコン（`mdi-icons.json`）。
  - 路線番号（`routes.json`）。
  - ミニマップのリソースの部品（`minimap/`）。
  - 書き出すビューア（`viewer/`）。
- `tests/`: xUnit のテスト。GTA V も FiveM も要らない。
  - `tests/resource`: 偽物のゲームで実行する、リソースのテスト。
  - `tests/minimap`: 書き出すミニマップのリソースのスクリプトを、小さな偽物のゲームで動かすもの。
- `Docs/spec/`: 形式の仕様。
  - リソースとの行の形式（`link-protocol.ja.md`）。
  - プロジェクトファイルと作業フォルダ（`project-format.ja.md`）。
  - スタイル（`style-format.ja.md`）。
  - POI（`poi-format.ja.md`）。
  - 道のノード（`ynd-format.ja.md`）。
  - 文字の表（`gxt2-format.ja.md`）。
- `third_party/gta-toolkit`: 同梱（MIT）。`README-FxMapGenerator.md` を参照。

## ビルド・テスト・起動

```
dotnet build FxMapGenerator.slnx -c Release
dotnet test FxMapGenerator.slnx -c Release
dotnet run --project src/FxMapGenerator.App -c Release -- --no-browser
```

App のビルドは、画面のファイルが変わったときに、
`src/FxMapGenerator.Web` で `npm ci`（初回）と `npm run build` を実行する。
`-p:SkipWebBuild=true` を付けると、Node なしでビルドできる（画面は埋め込まれない）。

### 起動のときの指定

```
FxMapGenerator [--port <数>] [--data-dir <フォルダ>] [--gta <フォルダ>] [--keys <フォルダ>]
    [--no-browser] [--app] [--verbose] [--version] [--help]
```

| 引数 | 中身 |
|---|---|
| `--port` | 待ち受けるポート。既定は 20400 |
| `--data-dir` | 設定とログのフォルダ。既定は `%LOCALAPPDATA%\FxMapGenerator` |
| `--gta` | GTA V のフォルダ |
| `--keys` | 暗号鍵のフォルダ |
| `--no-browser` | 起動のときに、ブラウザを開かない |
| `--app` | 画面を、タブではなく、アプリのウィンドウで開く |
| `--verbose`、`-v` | デバッグのログを出す |
| `--version` | exe の版と、同梱のライブラリの版を出す |
| `--help`、`-h` | 引数の一覧を出す |

- `--port`: そのポートが使われていれば、続く 10 個のポートの中で、空いているものを使う。
- `--gta`・`--keys`: アプリの設定より優先する。フォルダの決め方は、下の「GTA V と鍵のフォルダ」。
- `--app`: Edge か Chrome の `--app=` で開く。
- `--version`: 下の「単一ファイルの exe」も参照。

### 画面をその場で直しながら見るとき

1. exe を `--no-browser` で起動する。
2. `src/FxMapGenerator.Web` で、`npm run dev` を実行する。
3. http://localhost:5173 を開く。API は、127.0.0.1:20400 に中継される。

`FXMAPGEN_WEBROOT=<フォルダ>` を付けると、exe は、埋め込みの代わりに、そのフォルダの画面を出す。

## 画面なしのコマンド

| コマンド | すること |
|---|---|
| `new` | プロジェクトファイルを作る |
| `import` | 前に撮った撮影と採取を、作業フォルダにコピーする |
| `plan` | やることの表と、所要時間の見積もりを出す |
| `build` | 残りの作業を、ジョブとして実行する |
| `precheck` | 事前確認を実行する |
| `export` | 書き出しを、ジョブとして実行する |
| `convert` | 編集した画像の変換を、ジョブとして実行する |
| `retake` | 範囲のブロックに、再取得の印を付ける・外す |

### new

```
FxMapGenerator new <file.fxmapgen.json> [--name <名前>]
    [--maps satellite,atlas-postalcodemap,atlas-postalcodemap-ja,roadmap,...] [--work <フォルダ>]
```

プロジェクトファイルを作る。

| 引数 | 中身 |
|---|---|
| `--name` | プロジェクトの名前。なければ、ファイル名から付ける |
| `--maps` | 作る地図。`,` で並べる。なければ、衛星地図だけ |
| `--work` | 作業フォルダ。なければ、プロジェクトファイルのあるフォルダ |

`--maps` に書けるもの:

- `satellite`: 衛星地図。
- `roadmap`: 道路地図。
- `atlas-<スタイル>`: アトラス。スタイルは、同梱の `postalcodemap` か `regional`。英語の地図を作る。
- `atlas-<スタイル>-ja`: 日本語の地図も作る。言語は、アトラスのスタイルすべてに共通。

### import

```
FxMapGenerator import <file.fxmapgen.json> [--capture <フォルダ>] [--scan <フォルダ>]
```

前に撮った撮影と採取を、プロジェクトの作業フォルダにコピーする。
ブロックごとに、どのデータ項目があるかを記録する。
元のフォルダは読むだけ。

| 引数 | コピーするもの | ファイル |
|---|---|---|
| `--capture` | そのフォルダの撮影 | `<block>.png`、`.cam.txt`、`.hmap` |
| `--scan` | そのフォルダの採取 | `<block>.txt` |

`--capture` と `--scan` の、どちらか 1 つは要る。

### plan

```
FxMapGenerator plan <file.fxmapgen.json> [--workers <数> | --level full|strong|normal|light]
    [--processors <数>] [--json]
```

やることの表を出す。
表の中身は、ステップごとの残りと、選んだ並列数での所要時間。
所要時間の計算は、下の「所要時間の見積もり」。

並列数は、次のどちらかで指定する。
指定しなければ、プロジェクトの値を使う。

- `--workers`: 数で指定する。
- `--level`: 論理コアの割合で指定する。full は 100 %、strong は 70 %、normal は 50 %、light は 30 %。

ほかの引数:

- `--processors`: 論理コアの数として使う数。なければ、この PC の数。
  `--level` の割合は、この数に掛ける。
- `--json`: 表を、JSON で出す。

### build

```
FxMapGenerator build <file.fxmapgen.json> [--workers <数> | --level full|strong|normal|light]
    [--scale <qx>,<qy>] [--recalibrate] [--no-game] [--gta <フォルダ>] [--keys <フォルダ>]
```

残りの作業を、ジョブ（下の「ジョブ」）として実行する。
次の順に進む。

1. **撮影・採取**: 地図に必要なデータ項目（撮影画像、高さの格子、採取）のないブロックがあれば、最初に行う。
   ゲームの中で行う（下の「ゲーム: 接続・事前確認・撮影・採取」）。
   - `--no-game` を付けると、撮影・採取をせず、今あるデータだけで作る。
   - 撮影・採取の間も、撮ったブロックから順に、仮の縮尺でオルソ補正する。
2. **衛星地図**: 撮影・採取の後に、次のものを作る。
   - 縮尺の補正。隣り合う撮影の重なりから 1 回測り、`state/scale.json` に持つ。
     `--recalibrate` で測り直し、`--scale` で値を指定する。
     測る組がなければ、同梱の既定値を使う。
   - オルソ補正した z8 のタイル。
     対象は、撮影か、写真の位置合わせに使う高さ（`PhotoItems`）より古いブロック。
   - 範囲の外の外洋の塗り。
   - 縮小タイル。
3. **地図データ**: アトラス・道路地図を作るときに、続けて作る。次の順（下の各節）。
   ゲームファイル → 道路グラフ → 地表 → 地区と地域の色 → 文字 → 道。
   文字は、アトラスを作るときだけ。
4. **セル描画と縮小タイル**: 地図データの後に作る。
   セルの地図データ → セルの描画 → 縮小タイルの順（下の各節）。
   セルの描画と縮小タイルは、地図ごと。
5. **ミニマップ**: プロジェクトにミニマップがあれば、最後に作る（下の「ミニマップと書き出し」）。

実行中の表示と止め方:

- 5 秒ごとに、進み具合を出す。
- Ctrl+C を 1 回押すと、実行中の単位が終わってから止まる。2 回押すと、すぐに止まる。
- もう一度 `build` を実行すると、続きから始まる。

### precheck

```
FxMapGenerator precheck <file.fxmapgen.json>
```

事前確認（下の「ゲーム: 接続・事前確認・撮影・採取」）を実行する。
確認した項目と、結果とテスト撮影の置き場を出す。
終了コードは、問題なしが 0、要対応が 1。

### export

```
FxMapGenerator export <file.fxmapgen.json> [--out <フォルダ>] [--maps satellite,...|none] [--zip]
    [--base-url <URL>] [--max-zoom 6|7|8] [--no-minimap] [--resource-name <名前>]
    [--editable <地図>,...] [--editable-zoom 6|7] [--editable-format psd,svg]
    [--workers <数>] [--gta <フォルダ>] [--keys <フォルダ>]
```

書き出し（下の「ミニマップと書き出し」）を、ジョブとして実行する。

| 引数 | 中身 |
|---|---|
| `--out` | 書き出し先のフォルダ |
| `--maps` | 書き出す地図。`,` で並べる。`none` は、地図なし |
| `--zip` | Web の部分を、zip にする |
| `--base-url` | タイルを公開する URL。lb-phone の例に使う |
| `--max-zoom` | Web タイルの最大ズーム |
| `--no-minimap` | ミニマップのリソースを書き出さない |
| `--resource-name` | ミニマップのリソースの名前 |
| `--editable` | 編集用のファイルを書き出す地図。`,` で並べる |
| `--editable-zoom` | 編集用のファイルのズームレベル |
| `--editable-format` | 編集用のファイルの形式。`psd`・`svg`。`,` で並べる |
| `--workers` | 並列数 |
| `--gta`・`--keys` | GTA V と鍵のフォルダ |

- 指定しない項目は、プロジェクトに残した前回の選択を使う。
  なければ既定値を使う: タイルのある地図すべて、プロジェクトファイルの横の `export`、最大ズーム 8。
- 編集用のファイルは、`--editable` を付けたときだけ書き出す。
  `--editable-zoom`・`--editable-format` は、`--editable` と一緒に使う。指定しなければ、前回の値を使う。
- ミニマップのリソースは、プロジェクトにミニマップがあれば、`--no-minimap` を付けない限り書き出す。
- 書き出せない選択のときは、理由を出して、終了コード 65 で終わる。
- コマンドで指定した選択は、プロジェクトに残さない。
- ミニマップのリソースは、ゲームのファイルから、内装の地図の一覧を読む。
  カヨ・ペリコの道を読むプロジェクトでは、島の地図も読む。
  `build` と同じく、`--gta`・`--keys` のゲームから読む。
  指定がなければ、アプリの設定のゲームを使う。

### convert

```
FxMapGenerator convert <file.fxmapgen.json> --picture <PNG> [--map <地図>] [--out <フォルダ>]
    [--no-tiles] [--no-minimap] [--resource-name <名前>] [--base-url <URL>]
    [--workers <数>] [--gta <フォルダ>] [--keys <フォルダ>]
```

編集した画像の変換（下の「書き出し: 編集した画像の変換」）を、ジョブとして実行する。

| 引数 | 中身 |
|---|---|
| `--picture` | 変換する PNG の画像。必須 |
| `--map` | 画像の元の地図の id |
| `--out` | 書き出し先のフォルダ |
| `--no-tiles` | Web タイルを出力しない |
| `--no-minimap` | ミニマップのリソースを出力しない |
| `--resource-name` | ミニマップのリソースの名前 |
| `--base-url` | タイルを公開する URL。lb-phone の例に使う |
| `--workers` | 並列数 |
| `--gta`・`--keys` | GTA V と鍵のフォルダ |

- `--map` がなければ、画像のファイル名から決める。
  ファイル名が、編集用のファイルの名前（`<地図>-z<ズーム>`）で始まれば、その地図。
  そうでなければ、ミニマップの対象の地図。それもなければ、プロジェクトの最初の地図。
- `--out`・`--base-url` がなければ、プロジェクトに残した前回の書き出しの値を使う。
- 変換できないときは、理由を出して、終了コード 65 で終わる。
- プロジェクトファイルは、変えない。
- ミニマップのリソースがゲームのファイルから読むものは、`export` と同じく、`--gta`・`--keys` のゲームから読む。

### retake

```
FxMapGenerator retake <file.fxmapgen.json>
    [--blocks z8_<x>_<y>,... | --rect <西>,<南>,<東>,<北> | --all] [--clear]
```

範囲のブロックに、再取得の印を付ける。
MLO を入れたなど、サーバーを変えた後に使う。

次の `build` の撮影・採取が、印のあるブロックで、地図に必要な項目をすべて取り直す。
その後のステップは、取り直したデータを使うものを作り直す。

| 引数 | 対象 |
|---|---|
| `--blocks` | 名前で指定したブロック。どれも範囲の中のブロックであること |
| `--rect` | ゲーム座標（m）の四角にかかる、範囲のブロック |
| `--clear` | 印を付ける代わりに外す。`--clear --all` は、すべてのブロックから外す |
| 指定なし | 印のあるブロックを出す |

作業フォルダをほかの実行が使っている間は、実行せずに、終了コード 65 で終わる。

### 終了コード

| コード | 意味 |
|---|---|
| 0 | 完了。`precheck` では、問題なし |
| 1 | 単位かステップの失敗。`precheck` では、要対応 |
| 130 | 止めた |
| 64 | 引数の誤り |
| 65 | プロジェクトの誤り。または、作業フォルダをほかの実行が使っている |

### 所要時間の見積もり

所要時間の見積もりは、`data/timings.json` の値を元にする。
値は全域の実行で測ったもので、中身の説明は、そのファイルの `about` にある。

見積もりは幅で出す。
幅は、合計に `spread` を掛けたもの。
`spread` は、撮影・採取が 0.9〜1.2、ほかのステップが 0.8〜1.3。

**撮影・採取**

陸と水のブロックごと・項目ごとに、時間を足す。

| 値 | 数えるもの |
|---|---|
| `shot`・`height` | 撮影画像、高さの格子 |
| `scanGround`・`scanRoads` | カメラの直後の採取 |
| `scanGroundAlone`・`scanRoadsAlone` | カメラなしの採取 |
| `scanCanopy` | 木の茂みの採取 |
| `cameraMove` | カメラで取るブロックに 1 回 |
| `farMove` | カメラで取るブロックの、隣り合うまとまりに 1 回。となりでないブロックへの移動 |

ほかに、準備・片付けと、接続の確認の時間を足す。

**ゲームを使わないステップ**

値は、並列数 1 での 1 単位の時間。
単位を並列数に配って、所要時間を出す。

- オルソ補正と地表: ブロックごと。
- セルの地図データ（`cells.prepPerBlock`）と、セルの描画（`cells.drawPerBlock` の `atlas`・`roadMap`）:
  セルの、陸と水のブロックごと。余白のブロックも数える。
  水のブロックは、描くのは速いが、地図データは深さの帯を作るので重い。
- ミニマップ（`ytd.perSheet`）: シートを並べて数える。

次の 2 つは、中で並列に動くステップ。
値は並列数 1 での時間で、並列数で割る。

- `lowZoom`: 縮小タイル。地図の種類ごとの値。
  標準の枠で測った値なので、枠の広さに比例して増やす。
- `ortho.scalePerBlock`: 最初の縮尺の補正の測定。範囲のブロックごと（そのときは撮影済み）。
  プロジェクトに、測った補正がない間だけ数える。

並列数が 2 以上のときは、撮影・採取の横で、撮ったブロックをオルソ補正する。
そのため、そのブロックのオルソ補正の時間は、撮影・採取の時間に入る。

### 差分更新のときの見積もり

差分更新では、全域のステップを作り直す前は、次のものを見積もりに入れる。

| 見積もりに入れるもの | 対象 |
|---|---|
| 地表 | 取り直したブロックと、まわりのブロック |
| セル | 取り直したブロックとまわりのブロックを含むセル。道の編集の変わったブロックを含むセル |
| ミニマップのテクスチャ | そのセルのもの |

**地表が全ブロックになるとき**

- サーバーのリソースの一覧、枠、カヨ・ペリコの道を読むかどうかが変わったとき。
  読む道のデータで、道路グラフが変わるため。
  一覧のフォルダの中の ynd を直したときは、見積もりに入れない。
- 道の編集が変わったとき。

**道の編集の変わったブロック**

道路グラフの記録にある、ブロックごとの編集のハッシュと比較して決める。

**そのセルのミニマップのテクスチャ**

- 6 つのシートのうち、そのセルのシート。
- シートが 1 つでもあれば、全体図。
- 標準の枠の外のセルのテクスチャ。
- 衛星地図をミニマップにしたときは、オルソ補正の残りがあれば全部。

**後から分かるもの**

- 次の変更で増えるセルは、そのステップが終わってから分かる:
  地表（ほかの道路グラフで作り直したとき）、道の形、文字、地域の色。
- 実行中のステップは、実際の残りから見積もる。

## ジョブ

地図を作る処理は、ジョブとして実行する。コマンドからでも、画面からでも同じ。
exe の中で、同時に実行するジョブは 1 つ。ブラウザを閉じても続く。
コードは `src/FxMapGenerator.Core/Jobs/`。API は [api.ja.md](api.ja.md#ジョブ)。

### ステップと単位

- ステップ（`Stage`）は、まず残りの単位を決める。
  単位は、ブロック、セル、地図の組、全域で 1 つ、のどれか。
- ジョブは、単位を 1 つずつ、空いたスレッドに配る。
- 全域で 1 回のステップは、中のループを `StageContext.Parallel` で実行する。
  呼び出したスレッドが自分で項目を進め、空いたスレッドが手伝いに加わる。
- ステップは、順に実行する。

### 並列数

- ゲームを使わないステップは、選んだ並列数で実行する。
  並列数は 1〜論理コア数で、プロジェクトの `parallel` に既定値を持つ。
- 並列数は、実行中に変えられる。
  - 上げると、すぐに配る数が増える。
  - 下げると、実行中の単位はそのまま終わらせ、数が下がるまで、新しい単位を配らない。
    ループの中なら、次の項目から。
- 2 つ目のスレッドからは、空きメモリが足りなければ、増やさない。
  必要な量は、そのステップの 1 単位分（`MemoryPerUnit`）に、PC のほかの用途の 1 GB を足した分。
  そのときは、スナップショットに、いくつで止めているかが出る（`memoryLimitedAt`）。

### ゲームを使うステップ

- 単位を、1 つずつ実行する（並列数に関係なく）。
- その横で、補助の処理を、`Stage.Helpers` 個まで実行できる（`StageContext.RunBesideAsync`）。
  - 空いたスレッドを待って、実行する。
  - 処理中の単位に並ぶ。
  - `units.csv` に、自分の名前で残る。
  - 並列数が 1 のときは、実行しない。
- 上限は、「ゲームの 1 つ + 補助」と並列数の、小さい方。
- 撮影・採取は、撮ったブロックの仮のオルソ補正を、補助の処理として実行する。

### 止め方

- 区切りで止める（既定）: 実行中の単位は終わらせ、新しい単位は配らない。
- すぐ止める: 実行中の単位を打ち切る。ステップの後片付けは、それでも実行する。
- 終わった単位は、すべて `state/stages.json` に記録する。遅くとも 2 秒ごとと、ステップの終わりに書く。
- 次の実行は、残りから続ける。

### 実行ごとのフォルダ

作業フォルダの `logs/run-<yyyyMMdd-HHmmss>/` に、次のものを置く。

| ファイル | 中身 |
|---|---|
| `inputs/` | 始めたときの、入力のコピー |
| `run.log` | ログ |
| `units.csv` | 単位ごとの、ステップ・単位・開始・秒・結果・スレッド数の上限 |
| `run.json` | 最後のスナップショット、並列数の変更、失敗、始めたときのやることの表 |

`inputs/` にコピーするもの:

- プロジェクトファイル。
- 道の編集のファイル。
- 地図が使う、自分のスタイル（`styles/`）。
- POI のフォルダ（`poi/`）と `poi-styles.json`。指定している PNG も。

実行は、このコピーだけを読む。
そのため、実行中に直したものは、次の実行に入る。

道の編集のファイルだけは、それを読む最初のステップ（道路グラフ）が始まるときに、コピーし直す。
そこまでに保存した編集は、その実行に入る。

### 読んでいる入力のロック

ステップごとに、読んでいるプロジェクトの入力の名前を持つ（`StageInputs`）。
そのステップが終わるまで、その入力は変えられない（`JobRunner.LockedBy`、スナップショットの `locks`）。

入力の名前は、次のとおり。

範囲、枠、作りたい地図、サーバー、ゲームのコンソールの接続先、ゲームファイル、カヨ・ペリコ、番地、言語、
スタイルとその部分、POI、道の編集、ミニマップ。

入力ごとの違い:

- 道の編集: 変えられないのは、それを読む最初のステップが始まってから、
  最後のステップが終わるまで（`JobRunner.Held`）。
  撮影・採取やオルソ補正の間は、保存できる。
- 枠（`frame` = 標準の枠のまわりに足したセル）: 読むのは、枠の全体を覆うステップ。
  ゲームファイル、地域の色、道の形、縮小タイル（衛星地図も）。
  範囲のブロックを読むステップ（撮影・採取、オルソ補正、道路グラフ、地表）の間は、変えられる。
  枠を変えても、範囲のブロックは変わらないため。
- カヨ・ペリコの選択（`cayoPerico`）: 自分のロックを持つ。
  読むのは、ゲームファイル（島の道のファイル）と、文字（島の地区名）のステップ。
- サーバーのリソースフォルダ: ゲームファイルのロックのまま。

### 作業フォルダごとに 1 つ

実行の間は、`state/run.lock` を開いたままにする。
ほかの実行（別の exe やコマンド）は、持ち主のプロセス番号を示して、始めない。

## ゲームファイル

画面のジョブ一覧では「ゲームファイルの読み込み」。

アトラス・道路地図を作るプロジェクトでは、撮影・採取と衛星地図の後に、このステップを実行する。
`GameFilesStage`、全域で 1 単位。

### 読むものと書くもの

1. GTA V のアーカイブの索引を、1 回作る。
2. プロジェクトの枠にかかる区画の ynd を読む。道のノード、リンク、交差点の記録。
   - 標準の枠で 494 区画。
   - 区画の格子は y 8192 までで、それより北の枠の部分に、区画はない。
   - `cayoPerico` がオンなら、島の道のファイル（区画の番号 + 1024）を、その区画のファイルの代わりに読む。
3. 英語・日本語の GXT2 を読む。
4. サーバーの ynd で、区画を置き換える。
   - `gameFiles.serverResources` の順に、後勝ち。フォルダの中は、辞書順。
   - 道の採取は、その地点が道の上かをゲームに聞くので、サーバーが配る道のデータにも従う。
     置き換えた区画のブロックは、取り直すまで、前の道のデータでの道の採取のまま。
5. `game/` に書く。形は、`Docs/spec/ynd-format.ja.md`・`gxt2-format.ja.md`。

| ファイル | 中身 |
|---|---|
| `paths.json` | 車のノードとリンク |
| `names.json` | 通り名と地区名 |
| `sources.json` | どこから読んだか |

### 待つ条件、読み直し、所要

- 採取の通り名と地区名も、名前表を引く。
  そのため、範囲に道の採取のないブロックがある間は、待つ。同じ実行の撮影・採取が、先に取る。
- 枠か `cayoPerico` が、
  `sources.json` を読んだときのもの（`extraCells`・`cayoPerico`・`islandAreas`）と違えば、
  読み直す。
- 所要は、並列数 1 で 4 秒ほど。ファイルがディスクのキャッシュにあるときの値で、最初の 1 回は 13 秒ほど。
- ジョブ一覧は、このステップを 2 つの部分に分けて出す。
  `gameFiles.paths`（道の区画）と、`gameFiles.names`（名前表）。

### 実行の外で、今すぐ読む

実行の外で、今すぐ読むこともできる。
入口は、`GameFilesStage.ReadNow`、道の編集の画面の「ゲームファイルを読み込む」、
`POST /api/project/road-editor/game-files`。

- ステップと同じファイルを、そのときある採取の名前で書く。
- 使う場面は、2 つ。
  - 最初の撮影・採取の間に、道の編集の画面を使うため。
  - GTA V やサーバーの道のデータが変わったときに、読み直すため。ステップは、その変更に気づかない。
- 読んだ `paths.json`・`names.json` が、前と同じバイトなら、何も変えない。
- 違えば、置き換える。
  - ステップが前に済んでいれば、今済んだことにする。次の実行が、道のステップを作り直す。
  - 一度も済んでいなければ、ステップは残ったまま。採取がそろった後に動く。
- 実行の中で、ゲームファイルか地図データのステップが実行中の間は、拒否する（409 `LOCKED`）。

### GTA V と鍵のフォルダ

GTA V と鍵のフォルダは、この PC のもの。プロジェクトは持たない。
次の順で決める（`GameFilesLocation.Resolve`）。

1. exe の起動の引数 `--gta`・`--keys`。`build` にも、同じ引数がある。
2. アプリの設定。`settings.json` の `gtaFolder`・`keysFolder`。
3. 見つけられるもの。探し方は、`Docs/spec/project-format.ja.md` の「アプリの設定」。

コマンドの `build` も、既定のデータフォルダの設定を読む。

### 前提条件

- 「GTA V のインストール先・暗号鍵」: プロジェクト設定の画面に 1 行。
  アトラスか道路地図を作るプロジェクトと、ミニマップの地図を選んだプロジェクトに出す。
  上の順で決まったフォルダに、`GTA5.exe` と鍵の 4 ファイルがあるかを見る。
  `GET /api/project/checks` の `gameFiles` に出す。値は次のとおり。
  `gta`・`gtaSource`・`gtaOk`・`gtaProblem`（`notFound` / `notGta`）・`keys`・`keysSource`・`keysMissing`。
- 「サーバーのリソースフォルダ（任意）」: プロジェクトの `gameFiles.serverResources` の、
  どれもあるかを見る。
  指定がなければ、問題なし。1 行に 1 つ。
  `serverResources` に出す。値は、`count`・`entries`・`missing`。

### 「アプリの設定」の窓

設定のフォルダは、「アプリの設定」の窓で選ぶ。
窓は、上の帯の「⚙ アプリの設定」で開く。プロジェクト設定の「アプリの設定を開く」からも開く。

- 入れたフォルダで、何が見つかるかを見せる（`GET /api/settings/gamefiles?gta=&keys=`）。
  決まったフォルダ、その出どころ、`GTA5.exe` と鍵があるか、探した鍵のフォルダと、足りないファイル。
  `--gta`・`--keys` が優先され、そう示す。
- 設定に書く。

### テスト

- テストは、ゲームのファイルを読まない。gta-toolkit で書いた小さな ynd と、手で組んだ GXT2 を使う。
- コマンドの `build` のテストは、採取がないので、ゲームファイルと道路グラフのステップが待つ。

## 格子の処理と採取の読み込み

### 格子の部品

`src/FxMapGenerator.Core/Grids/` は、地図データの格子の部品。外部のライブラリは使わない。

| 部品 | 中身 |
|---|---|
| `Grid<T>` | 格子。行優先 |
| `Kernel` | 核。OpenCV と同じ形の、楕円、四角、十字 |
| `Morphology` | 2 値と濃淡の、膨張・収縮・開演算 |
| `Components` | 連結成分。番号は、最初のマスの行の順 |
| `DistanceTransform` | 最も近いマスと距離 |
| `Filters` | 窓の数え上げ。端は折り返し |
| `PointIndex` | 点の近傍 |
| `GridFile` | ファイル。形は `Docs/spec/project-format.ja.md` |

- 格子の外の扱いは、2 通りある。使う所ごとに選ぶ。膨張は、どちらも同じ。
  - `Erode` / `Open`: 外を数えない（端から削れない）。
  - `ErodeEdgeOff` / `OpenEdgeOff`: 外を「なし」とする（端から削れる）。
- 最も近いマスが 2 つ以上あるときは、行の小さい方、次に列の小さい方を取る。
- 濃淡の収縮・膨張は、核の各行が、中心をはさんで左右同じ（楕円、四角、十字）なら、
  行ごとの最小・最大を、幅 1 ずつ広げて作る。
  幅 r の値は、幅 r − 1 の値の左右の隣から作る。数マスずつまとめて。
  846 × 846 に 151 m の楕円の開演算で、0.06 秒ほど。
- 太い折れ線の塗り（`ThickLines`）は、OpenCV の `polylines`（8 連結、太さ 2 以上）と同じマスを塗る。
  区間ごとに、太さの半分ずつ左右に広げた四角形を、1/65536 マスの固定小数で塗る。
  始点と、各区間の終点に、円を置く。
- どれも、1 スレッドで動く。並列は、ステップの単位の側でかける。

### 採取の読み込み

`src/FxMapGenerator.Core/Scan/` は、次のもの。

- `ScanFile`: 採取の読み込み。行 → 格子。
- `Materials`: 材質の種類。
- `ScanArea`: 範囲の採取を、1 枚の格子として、位置から引く。

### 線と数の部品

`src/FxMapGenerator.Core/Geometry/` は、線と数の部品。

- `Polyline`: 弧長、4 m ごとの観測点、Douglas-Peucker の間引き、ゆるい角の丸め。
- `Num`: Python 3.11 と numpy と同じビットを出す計算。
  `math.hypot`、`round`、`numpy.interp`・`median`、窓の平均。
  しきい値のどちら側に落ちるかまで、同じにするため。
  `Math.Sqrt(x * x + y * y)` は、1 割ほどの長さで、最後の桁が違う。

## 道路グラフ

ゲームファイルの次のステップ。`RoadGraphStage`、全域で 1 単位。
コードは `src/FxMapGenerator.Core/RoadGraph/`。

ynd の道のリンク（`game/paths.json`）を、地図の道（通りごとの鎖）にまとめて、`data/roads.json` に書く。
形は `Docs/spec/project-format.ja.md`。
範囲の道の採取の道路判定で、幅を測る。そのため、ゲームファイルと同じく、採取を待つ。

### 道の編集の適用

プロジェクトの道の編集（`roadEdits`）は、読んだ道のリンクに、
グラフを作る前に適用する（`RoadEditsFile.PathsOf`）。
コードは `src/FxMapGenerator.Core/RoadEdits/`。道の形も、同じように適用する。

- 足したノードとリンクを、ゲームのものの後に入れる。
- ノードを動かす。
- 値を変える。
- 隠したノード（とそのリンク）と、リンクを外す。

適用する条件:

- ゲームのノードは、キーで見つける。`original` の位置のままのときだけ、適用する。
- ゲームのリンクは、元の車線数のままのときだけ、適用する。
- 合わない編集（サーバーの道のデータが変わったときなど）は、適用しない。
  理由と一緒に、ログと記録に出す。

### 作る順

1. **鎖**（`Chains`）
   - 範囲のまわり 60 m の、車のノードとリンクを使う。近道のリンクは外す。
   - 各ノードで、リンクを、一番まっすぐ続く組に分ける。
     - 2 本のノードは、折り返し以外。
     - 3 本以上は、35 度まで。別の名前の通りどうしは、組まない。一方通行の向きが続かない組は、作らない。
   - 組をたどって、鎖にする。
   - 交差点の中心（交差点の印があり、3 本以上）は、線から抜く。
2. **幅と格**（`SurfaceWidth`、`RoadGraphBuilder.Classify`）
   - 幅: 端から 15 m より内を 4 m ごとに、直角に ±25 m を 0.25 m ごとに、道路判定を引く。
     中心を含む走りの幅の、中央値にする。
   - 道の編集で幅の決まったリンクの上の点は、測る代わりに、その幅にする。
     幅の決まったリンクは、幅を入れたリンクと、足したリンク。
     足したリンクは、採取の道路判定に出ないので、車線数からの幅。
   - 点が 3 つに満たない短い道は、そのうち、いちばん長いリンクの幅にする。
     その道は、最後までこの幅のまま。
   - 名前: 名前のあるノードの多数決。
     道の編集で足したノードは、名前なしも 1 票。
     名前のある道のノードから足した道は、足したノードの名前になる。
   - 格: 高速の印・未舗装の印・名前・車線数・幅から決める。
3. **束**（`Bundles`）
   - 同じ通りの平行な鎖を、1 本の中心線に寄せる。
     条件は、20 m 以内、向きの差が小さい、高さの差 3 m 未満。
   - 束全体の幅を、1 回測る。
   - 寄せる量は、鎖に沿って補い、前後 5 点で平均する。
4. **線の仕上げ**
   - 線を間引く（1.5 m、束は 2.5 m）。ゆるい角を丸める。
   - 120 m 未満の `street` が、同じ通りの `major` につながっていれば、`major` にする。
   - 束の道は、通りごとに、幅を 1 つにする。
   - `minor` のまとまりで、ほかの道と 1 点以下でしかつながらないものは、駐車場の通路（`parking`）。
   - 短い切れ端を捨てる。

### 記録、作り直し、所要

- `data/roads-record.json` に、作ったブロックと数、適用した道の編集（`roadEdits`）を残す。
- 作り直すのは、次のとき。
  - ゲームファイルか道の採取が、これより新しいとき。
  - 範囲が違うとき。
  - 道の編集の中身が、記録（`roadEdits.digest`）と違うとき。
    ファイルを替えたときと、なくしたときも。同じ中身で保存し直したときは、作り直さない。
  - ファイルがないとき。
- 編集のファイルが読めないときは、理由をすべて挙げて、失敗する。
- 所要は、986 ブロックで、並列数 1 で 9 秒ほど。うち 7 秒は、採取を読む時間。
- 中のループ（鎖ごとの幅、束の観測点）は、`StageContext.Parallel` で実行する。結果は、
  スレッド数によらず同じ。

## 地表

道路グラフの次のステップ。`LandcoverStage`、ブロックごと。
コードは `src/FxMapGenerator.Core/Landcover/`。

- 読むもの: ブロックとまわり 8 ブロックの地面の採取、ブロックの道の採取、道路グラフ。
- 書くもの: 地面の種類・水・建物・木の茂み。`data/landcover/<block>.grid` に書く。
  形と各配列の意味は、`Docs/spec/project-format.ja.md`。
- 高さは、高さの品質で決まる（`SurfaceHeights.LandcoverItems`。下の「ゲーム」の、高さの品質）。
  - バランス: 地面の採取。
  - 品質重視: 地面の採取と高さの格子の、マスごとに高い方。

### 作る順

1. **ブロックの面**（`BlockSurface`）
   - 高さ（上の高さ）。地面の採取は、当たった高さと水面の高い方。穴は、一番近いマスで埋める。単精度。
   - 材質の種類、開けた水、道路判定、木の茂み。
   - まわりのブロックの分も、同じもの。`LandcoverStage` の中で、5 行分のブロックを使い回す。
2. **地面の種類**（`LandcoverBuilder`）
   - 材質の種類 → 地面の種類（`GroundClasses`）。
   - 水の近くの砂を、砂浜にする。
   - 5 × 5 の多数決（`Majority`）。
   - 小さな欠片の併合（`MergeSmall`）。
   - 材質 `DEFAULT` は、市街地ではなく、それだけの種類 `defaultMaterial` にする。
     `DEFAULT` は、ゲームが固有の材質を付けていない、地形・岩・小物など。
     材質から地面が何かは分からないので、塗りと、なじませるかどうかは、スタイルが決める。
     同梱の「PostalCodeMap 風」は、自然の地面と一緒になじませる。
     山の斜面にあるこの材質の地面が、くっきりしたふちで目立たないようにするため。
     舗装やコンクリートは市街地のままで、くっきり塗る。
3. **地形**（`GroundModel`）
   - 3 × 3 ブロックを並べた格子の上で作る。
   - 自然の地面か舗装の種を、壁で区切った大きな面の上のものに絞る。
   - 段差の小さいマスを歩いて、広げる。
     歩いてつながる面は、となり合う種が 2 つ以上まとまっているときだけ、地面にする（`MinSeedGroup`）。
     軒の 1 マスの種から、屋根が地面にならないようにするため。
   - 残りのマスには、一番近い歩ける地面の高さを入れる。
4. **建物**
   - 地形より 3 m 高い、屋根の材質のまとまり。道の上と岩を除く。
   - 駐車場の規則（`GarageRule`）: 151 m の開演算より 6 m 高い、舗装のまとまり。
     道路グラフの通り・幹線・高速の線を幅で塗った所の下にあるものと、水に囲まれたものは除く。
5. **建物でないまとまりを外す**（`FalseBuildings`）
   - 岩場: 次の 3 つを満たすまとまり。
     歩ける傾きより急なので地面にならないが、本物の建物には壁があるか、舗装の中に建つ。
     - 材質の 5 割以上が、`DEFAULT`（材質の名前のない当たり。岩のオブジェクトなど）か、自然の地面。
     - 壁（外が 2.5 m 以上低い縁）が、縁の 6 割未満。
     - まわり 5 m（水を除く）の 9 割以上が、自然の地面か `DEFAULT`。
   - 駐車場の規則のまとまり（角でつながるもの）で、次のどちらかのもの。
     - まわり 10 m に、中央の高さから 3 m 以内の下の自然の地面が、15 % 以上ある。
       丘、土手、岸壁の陸側。151 m の開演算の地面が、となりの斜面か海に引っぱられた所。
     - 水が 20 % 以上ある。橋、桟橋、ダム。
   - 外したまとまりのマスでも、もう一方の規則で残るまとまりに入るマスは、建物のまま。
   - 外したマスの数は、ステップのログに出す。

### 待つ条件、作り直し、所要

- 待つのは、次の間。
  - ブロックか、範囲の中のまわりのブロックに、採取がない間。品質重視では、高さの格子も。
    撮影・採取が、先に取る。
  - 道路グラフが古い間。
- 作り直すのは、次のとき。
  - ブロックとまわりの入力が、これより新しいとき。
  - ファイルがないとき。
- 次のときは、全ブロックを作り直す。
  ステップの記録を消してから作る。待っているブロックは、作れるようになったときに作る。
  - 高さの品質を変えて、`data/landcover-record.json` の高さ（`scan`・`both`）と違うとき。記録がないときも。
  - 道路グラフの中身が、記録のハッシュ（`roadGraph`）と違うとき。
    駐車場の規則が、道路グラフを読むため。同じ中身で作り直された道路グラフは、同じとみなす。
- ハッシュのない記録（ハッシュを持つ前に作ったもの）では、ブロックより新しい道路グラフを、別のものとみなす。
- 所要は、986 ブロックで、並列数 17 で 29 秒。1 単位 0.5 秒ほど。並列数 1 なら、0.2 秒ほど。

## 道

画面のジョブ一覧では「道路」。

地表の次のステップ。`RoadsStage`、全域で 1 単位。
コードは `src/FxMapGenerator.Core/Roads/`。

道のリンクと通り名、範囲の地表の水と材質から、道を描くための形を、`data/road-shapes.grid` に書く。
形は `Docs/spec/project-format.ja.md`。

数の計算は、numpy と CPython と同じビットを出すもの（`Geometry/Num`）を使う。
numpy の `hypot` の形、`linspace`、pairwise の和、guess 付きの `interp`、CPython の `math.hypot`。

### 作る順

1. **グラフ**（`RoadNet`）
   - 車のリンク。近道のリンクを除く。道の編集を適用したもの（上の「道路グラフ」）。
   - 地表の水と材質を、全域の 1 m の格子に並べる。
     ファイル名の順。重なりは、水はどちらか、材質は後。
   - 船の航路を外す。交差点から交差点までの並びの、半分以上が水の上のもの。
     - 道のデータから、船の印は読まない。
       そのため、MLO で陸になった航路は、道として残る。足元が自然の地面なら、未舗装。
     - 地表のない所は、水。
   - 高速は、次のもの。
     - 高速の名前。
     - 印のある、60 m 以上の区間。
     - 名前のない、印付きの傾斜路。
     - 高速どうしをつなぐ、名前も印もない道。
     - 一方の端だけが高速の名前で、もう一方が普通の道に出るリンクは、道。
   - 未舗装: 並びごとに、2 m ごとの材質の半分以上が、自然の地面。
     票のない並びと高速は、ノードの未舗装の印。
2. **描くリンク**（`RoadLinks`）
   - 幅 = (両向きの車線 + 2 × 車線のずれ) × 5.5 m。
     狭いリンクは 4.0 m。未舗装は 5 m。
     道の編集で幅を入れたリンクは、どちらよりも、その幅。
   - 交差点の中のリンクは描かず、来る道を延ばす。
     - その先へ続く道に向けて、延ばす。
     - 向かい合う 2 本は、交差点を通る 1 本にする。
     - 先の道が交差点から始まるときは、交差点まで。
     - 交差点どうしの間のリンクの先へは、その先の交差点まで。
   - fork（1 本が 2 本に分かれる・合わさる所）は、枝の端を幹の上に並べて始め、重なる所を押し広げる。
   - 3 本以上がつながるノードで、まっすぐ続く組を決める。
3. **段**（`RoadLevels`）
   - 次のリンクの上にあれば、1 + その段。
     帯（縁取り + 2 m）が重なり、3 m 以上上を通り、道のリンクで 60 m 以内につながっていないリンク。
   - トンネルの上の道は、地面のまま。
   - 同じ高さの端では、高い段を 15 m 引き継ぐ。
4. **形**（`RoadShapes`）
   - 片ごとに、曲線と幅。
     - 曲線: ノードを通る centripetal Catmull-Rom、2 m ごと。
     - 幅: 30 m で平らす。fork の幹は、枝の幅まで細る。
   - 地面の帯。本当の行き止まりは、角を丸める。
   - 段の帯。
   - 止まる端の、角のつぎ。
   - 交差点の角の丸め（`RoadLinks.Joins`）。描いた縁から、半径 6 m。
     道の編集で足したリンクが、交差点の記録のないノードで、ほかの 2 本以上とつながる所も丸める。
     ノードのまわり 10 m 四方で。
   - トンネル（`TunnelOutlines`）: 区間を、0.5 m の格子に、マスの中心の内外で塗る。輪郭を、0.15 m で間引く。

### 待つ条件、作り直し、所要

- 待つのは、次の間。
  - ゲームファイルか道路グラフが古い間。
  - 範囲に、地表のできていないブロックがある間。
- 作り直すのは、次のとき。
  - ゲームファイルか範囲の地表が、これより新しいとき。
  - 範囲が変わったとき。
  - 道の編集の中身が、記録と違うとき。
  - ファイルがないとき。
- 所要は、986 ブロックで、並列数 1 で 2 秒。地表の読み込みを含む。
- 計算そのもの（`RoadsStage.Make`）は、道の編集の右の地図（下の「道の編集」）と共有する。

## 道の編集

「地図の編集」タブの、道路の画面。
プロジェクトの道の編集のファイル（`roadEdits`）を編集する。形は `Docs/spec/project-format.ja.md`。
編集は、ゲームの道のデータとの差分。道路グラフと道の形が、適用する。

- 画面: `src/edit/`
- API のコード: `src/FxMapGenerator.App/Web/RoadEditorEndpoints.cs`
- 読むもの: `Projects/RoadEditorData.cs`

### 道のデータと描画

- 道のデータは、画面に 1 回、列の形で渡す（`GET /api/project/road-editor/paths`）。全域で約 4 MB。
  - ノードと印。
  - リンクは、1 本に 1 つ。向きは、ファイルの最初の記録の向き（編集が車線数を比較する向き）。
  - 通り名の英・日。
- 画面は、編集を、サーバーと同じ決まりで、自分で適用する（`src/edit/roads/model.ts`）。
  適用できない理由も同じ。
- ノードとリンクを、キャンバスのタイルに描く（`pathsLayer.ts`）。
  - 種類ごとに色分けする。
    一般・高速・トンネル・未舗装・普段の交通が走らない道（ゲームの switched off の印）。
  - ノードは、ズーム 6 から。交差点のノードは、黒い縁の大きな点。
  - 一方通行の矢印は、7 から。
  - 当たり判定は、四角の格子。
- 変更のたびに、新しい編集を作る。元に戻すのは、200 回まで。

### 左の地図に出すもの

- 地図の下の凡例に、種類ごとのチェックボックスがある。
  ゲームの 5 種類と、それをまとめて切り替える 1 つ、追加、変更、非表示。
- 項目ごとに、マウスを重ねたときの説明がある。
- 選んだ内容は、アプリを開いている間は残す（`store.ts` の `shown`。保存しない）。
- チェックを外した種類は、描かず、拾わない。選択中のものからも外す。
  拾わないのは、クリックとマウスの下、範囲選択、道ごと選択、描画（吸着も分割もしない）、移動。
  `pick`・`inRectangle`・`inPolygon` が、種類を受け取る。
- 変更・非表示にしたゲームのものは、元の種類ではなく、「変更」「非表示」。

### 道具

- 描画、移動、選択、範囲選択、道ごと選択。キーの 1〜5 で選ぶ。
  入力欄に入力中と、窓を開いている間は、キーは効かない。
- 範囲選択は、矩形。Ctrl+ドラッグでは、なぞった線で囲んだ中のノード。
  どちらも、両端が中にあるリンクを選ぶ。Shift で追加。
- 範囲選択の間は、地図のドラッグを止める（左ドラッグで選ぶ）。
  ホイールのボタンのドラッグで、地図を動かす。

### 道ごと選択

`pathsLayer.ts` の `roadOf`。

- クリックしたリンクから両方向に、2 本だけが集まるノードを通って進む。
  次の分岐（3 本以上の道が集まるノード）か、行き止まりまで。
- 選ぶのは、リンクと、途中のノードと、行き止まりのノード。
  分岐のノードは選ばない。ほかの道のノードでもあるため。
- 近道のリンク・非表示・左の地図に出していない種類は、ここでは道に数えない。
- 分岐のノードや、道でないものは、それだけを選ぶ。
- Ctrl+クリック: 同じ通り名（編集を適用した後）のノードすべてと、両端がその名前のリンク。
  名前のないものは、その道。
- マウスを重ねると、クリックで選ぶものを、白く示す。Ctrl を押す・離すと、切り替わる。

### 右の地図

道だけを、アトラスか道路地図の色で描いた、透明なタイル。
サーバーが、セルの道の描き方で描く（`RoadShapesIndex` の上の `RoadTiles`、`RoadDrawing`）。

- 編集の 0.5 秒後に、保存前の編集で次の実行が作る道の形を、
  サーバーが計算する（`RoadEditorData.PreviewOf`）。
  - ステップと同じ `RoadsStage.Make` を、編集を適用した道のデータのコピーで実行する。
  - 地表の水と材質の層は、1 回読んで持つ。約 250 MB。
  - 新しいリクエストが来たら、計算中のものを取り消す（409 `SUPERSEDED`）。
  - 右の地図は、そのタイルを出す（`v=preview-<n>`）。全域で 0.8〜1.2 秒。
- 編集が保存したとおりで、道の形がそれで作ってあれば、最後の実行の道の形を出す。
- 範囲に、地表のまだないブロックがある間（撮影・採取の完了前）は、仮の形になる（`provisional`）。
  - そのブロックは、「地面の種類のない陸」として扱う（`RoadNet.WorldGrids` の `notMade`）。外洋にはしない。
  - その上の道は、船の航路として外さない。舗装かどうかは、道のデータの印で決める。
  - 画面は、その旨を出す。
  - 地表の層は、ブロックが増えるたびに読み直す。仮の間は、30 秒は同じものを使う。

### 保存

- 保存は、編集の確認を通して書く（`RoadEditsFile.Write`）。問題はすべて挙げ、あれば書かない。
- 編集のファイルのないプロジェクト（`roadEdits` が null）は、初めての保存で、ファイルを作る。
  プロジェクトファイルの横に `road-edits.json` を作り、プロジェクトに付ける。
  名前がふさがっていれば、`road-edits-2.json`…（`RoadEditsFile.FreeName`）。
- 実行中は、編集を読むステップ（道路グラフ、道、文字）の最初が始まってから、最後が終わるまで、拒否する
  （409 `LOCKED`）。
  その前（撮影・採取の間など）に保存した編集は、その実行に入る。

### 同梱の編集

`data/road-edits-default.json`。exe に埋め込む（`RoadEditsFile.BundledBytes`）。
どのサーバーの地図にも使える編集を、編集のファイルの形で持つ。

- 中身は、空港の滑走路、登山道、ノース・ヤンクトンの道の非表示、カヨ・ペリコの道、追加の細かい道、
  市街地の道路形状の改善。
- 1 つの編集ごとに、1 つのまとまり（`groups` と、そのノード・リンクの `group`）。
- まとまりの名前は、英語と日本語（`ItemName`）。
- テストで、次のことを確認する。
  読めること、アプリが編集を書く形のままであること、すべての項目が名前のあるまとまりに入っていること。

**新しいプロジェクト**

新しいプロジェクト（画面の `ProjectSession.Create` と、コマンドの `new`）は、このコピーから始める。

- `RoadEditsFile.StartFromBundled` が、出力する地図にかかわらず、プロジェクトファイルの横に、
  空いた名前で書く。
- まとまりの名前は、画面の言語の名前 1 つ（`RoadEditsFile.Copied`）。コマンドは英語。
- `roadEdits` に付ける。

**今のプロジェクトへの取り込み**

今のプロジェクトは、画面で、まとまりを取り込む。
「同梱の編集を取り込む…」、`GET /api/project/road-editor/bundled`、`model.ts` の `takeIn`。

- 保存前の編集への、1 回の変更になる（「元に戻す」1 回）。
- 足したノードは、プロジェクトの次の番号から振る。
- 同じ位置（x・y・z それぞれ 1 cm 以内）に、編集の足したノードがあれば、足さずに、それを使う。
- 編集がすでにつないでいる 2 つのノードの間のリンクは、足さない。
- ゲームのノード・リンクへの編集は、次のときは取り込まない。数は、窓に出す。
  - プロジェクトの編集が、同じものを編集しているとき。プロジェクトの編集を残す。
  - プロジェクトのゲームのデータが、同梱の編集の見たとおりでないとき。
- 同梱の編集が足す通り名は、英語の名前で合わせる。
- 編集がすでに持っているまとまり（その項目がある）は、もう一度は選べない。
- アプリを新しくしても、プロジェクトの編集は変わらない。

**あるノードにだけ適用するまとまり**（`whereFound`）

ノース・ヤンクトンの道の非表示が、これに当たる。プロローグの町の道 395 ノードを隠す。
枠によって読まれない区画があり、カヨ・ペリコの道を読むと、島のファイルに置き換わる区画もある。

- ゲームのデータにないノードの編集も、数えずに取り込む。
- 適用するときは、合わないものを、黙って飛ばす（`RoadEditSet.Match`、画面は `applyEdits` の `leftOut`）。
- 「適用できない編集」には並べない。

### まとまり

- 編集の一覧は、まとまりを 1 行にする。名前と、その項目の数。
  リンクの編集の端だけのノードは、数えない。
- 「取り消し」は、まとまりのすべてを取り消す。
  - 足したノードとリンクは、そのノードにつなげた自分のリンクと一緒に消える。
  - ゲームのノード・リンクへの編集は、なくなる。
- まとまりの項目は、直しても（非表示、移動、分割）、まとまりのまま。
- 地図は、まとまりを読まない。道路グラフ・道の形・文字は、まとまりに関係なく、編集を適用する。

### 自分で付ける通り名

編集のファイルの `streets` に持つ。ハッシュ → 英語、日本語かなし。
地図に描くラベルなので、画面は、日本語の地図を作るときだけ、日本語を聞く。

- 新しい名前のハッシュは、英語の名前を小文字にした、ゲームのハッシュ（joaat）。
- 使われていれば、どの通りも使っていない、次の数にする。
  0 でなく、ゲームの名前にもノードにもなく、ほかの追加した名前にもない数。
- 英語の名前は、ゲームの名前とも、ほかの追加した名前とも違うこと。
- 画面は、名前を入れて選択中のノードに付けるのを、1 回の変更で行う。
  どのノードも使わなくなった名前は、外す（`prune`）。
- 道路グラフは、ハッシュだけで扱う。
- 道の形（`RoadNet`: 高速道路の名前、同じ通りの続き）と文字は、ゲームの名前と一緒に読む。
  `RoadEditSet.ApplyTo` が `PathFile.Streets` に入れる。`GameNames.WithStreets`。

## 地区と地域の色

画面のジョブ一覧では「地域色」。

地表の次のステップ。`RegionsStage`、全域で 1 単位。
コードは `src/FxMapGenerator.Core/Regions/`。

- `ZoneGrid`: 範囲のブロックの道の採取の地区を、全域の 4 m の格子（`data/zones.grid`）にする。
  格子の枠（ブロックの四角を、整数の m に丸めたもの）も持つ。
  地域の色と文字が読む。
- `RegionField`: 地域の色。地面の画像が地域の色を使うスタイルの地図があるときだけ、作る。
  そのスタイルは、同梱の `regional` と、それを元にした自分のスタイル。
  - 地区から、スタイルの表で、地域を決める。
  - 地域ごとの陸の割合を、SciPy と同じガウスぼかしで混ぜた色にする。
  - 地図のスタイルの `regions` の中身ごとに、1 つ作る（`data/regions-<key>.grid`）。
    key は、中身の SHA-256 の先頭 12 桁。同じ中身のスタイルは、共有する。
- 作り直すのは、次のとき。
  - 範囲のブロックの道の採取か、地表が新しいとき。
  - 範囲か枠が変わったとき。
  - まだない地域の色を必要とするスタイルがあるとき。
- 記録に、範囲のセルごとに、そのセルの地面の画像が読む部分のハッシュを持つ（`RegionField.WindowDigest`）。
  読む部分は、セルの 1 m の格子の点のまわりの 4 m の点と、まわり 1 点。
  地域の色が新しくなっても、作り直すのは、その部分が変わったセルだけ。

## セルの地図データ

画面のジョブ一覧では、「セル描画」の中の「前処理」。

地域の色の後のステップ。`CellPrepStage`、単位はセル。
コードは `src/FxMapGenerator.Core/Cells/`。

セルごとに、地図の組によらない地図データを、`cells/<セル>/` に作る。
形は `Docs/spec/project-format.ja.md`。

### 作るもの

- **地表の層**
  - 地表のマスクを、塗る前のマスクで作ってから、輪郭にする（`Vectors/`、potrace の多角形の処理）。
    マスクは、地面の種類、水、深さの帯、木の茂み、建物の色。
  - 層ごとに、スタイルの値を表す名前（`set`）を持つ。同じ値のスタイルは、同じ層を使う。
- **陰影と等高線**
  - 高さは、地表と同じ。バランスは、地面の採取の表面。品質重視は、高さの格子との、マスごとに高い方。
    記録の `heights` は、`scan`・`both`。
    建物を抜く所と、陰影の元が、同じ高さになる。
  - 陰影は、SciPy のぼかしと numpy の勾配。等高線は、contourpy の serial と同じ線。
  - 陰影は、陰影の値の組ごとに 1 つ（`shade-<key>.grid`）。
    key は、値の SHA-256 の先頭 12 桁。記録の `shades`。
    同じ値のスタイルは、同じ陰影を使う。
- **地面の画像**（`ground-<スタイル>.png`）
  - スタイルの `groundRaster` で作る。材質の色を混ぜる / 地域の色に材質の濃淡。

### 作り直し

作り直すのは、次のとき。ハッシュのない記録は、変わったものとして扱う。

- セルのブロックの地表・採取・高さデータが新しく、中身が記録（`inputs`）と違うとき。
  `inputs` は、ブロックごとに、読んだファイルのハッシュ。
  `ContentDigest` は、ファイルのハッシュを、大きさと更新時刻が同じ間は、メモリに覚えておく。
- 記録のブロックの高さが、今の高さの品質の高さと違うとき。
- スタイルの値が、記録と違うとき。
- 地域の色が新しく、セルの部分が変わったとき（`regions`）。

記録には、書いたファイルごとのハッシュ（`outputs`）も持つ。`layers.json`、陰影、地面の画像。

セル描画は、その地図のスタイルが読むファイルのハッシュを、まとめて比較する（`CellPrepStage.OutputFor`）。
そのため、ほかのスタイルのファイルが変わっても、描き直さない。

## 目印（POI）

地図に描く POI。コードは `src/FxMapGenerator.Core/Poi/`。形は `Docs/spec/poi-format.ja.md`。

### 読み方

- プロジェクトの `poi`（POI のフォルダ）を読む。null は、同梱の `data/poi/`。
- ディスクのフォルダ（設定は `_.json`）と、まとまり（`.json` 1 つ）から、
  引き継いだ値にする（`PoiData.Resolve`）。
  引き継ぐのは、POI スタイル・出す地図・表示・ロック。
- POI スタイルは、同梱の `data/poi-styles.json` に、`poiStyles` のものを足す。
- 同梱の POI は、Highway One の A〜Z の 26 個（`highway-markers.json`）と、
  色付きの丸 5 個（`colored-dots.json`）。
  postal code map の元の地図から取った位置で、ロックつき。

### 描き方

- 描き方は、文字・丸に文字・丸・アイコン。
- アイコンは、次のどちらか。
  - MDI のアイコン（`icon`）。`data/mdi-icons.json` の名前。
    `MdiIcons` が、24×24 の枠の path 1 本を、`SKPath.ParseSvgPathData` で描く。
  - POI スタイルのファイルの横の PNG（`image`）。記録が比較する値に、中身の SHA-256 が入る。
- `badgeColor` は、アイコンの後ろに、1.5 倍の丸を描く。
- `showLabel` は、丸・アイコンの右に、ラベルを書く。
  大きさは `labelSize`。なければ、大きさの 0.6 倍。丸の上のアイコンは、丸の色で。
- 寸法は、`PoiLayout` にまとめる。描画（`CellPainter`）と、文字の場所（`LabelPlacer`）が使う。
- 記録が比較するのは、`ResolvedPoi.Drawn`。
  ラベル・位置・見た目・出す地図・表示。ない言語のラベルは、空として書く。
  文字と、セルごと（`CellInputs.PoisDigest`）に比較する。
- セルは、横のラベルが西から届く POI も描く。

### 名前とラベル

- POI の `name`: 文字 1 つ。一覧と検索に使い、地図には描かない。
- POI の `label`: 地図に描く文字。言語ごと（`LabelPlacer.PoiLabel`）。
- フォルダ・まとまり・POI スタイルの名前も、文字 1 つ（`ItemName`）。
- 同梱のまとまりと POI スタイルは、英語と日本語の名前を持ち、画面の言語で出す。
  最初の保存（`PUT /api/project/poi?language=`、`PoiFiles.Copied`）で、その言語の名前 1 つにする。

### 出す地図と実行

- 出す地図は、アトラス地図と道路地図。
  ミニマップは、選んだ地図のタイルをそのまま使う（POI も入る）。
- 実行は、POI のフォルダを `inputs/poi/` に、
  POI スタイルのファイルを `inputs/poi-styles.json` にコピーして読む。
  指定している PNG は、その横にコピーする（`JobRunner.CopyPoi`、`Project.UsePoiCopy`）。

### POI の画面のファイル

`PoiFiles` が扱う。

- `PoiEditSet`（フォルダ、POI つきのまとまり、自分の POI スタイル）に読み、ファイルごとに書き戻す。
  - 同じことを書いたファイル（アプリの書き方で）は、そのまま。
  - 新しいフォルダは、同梱のまとまりから始める。名前は、画面の言語。
  - なくなった `.json` とフォルダは、消す。
- パスは、ディスクの決まりで確認する（`PathProblems`、`SafeName`）。
- `PoiImport` は、CSV か JSON から、POI を読む。
  CSV の列の名前は、`x`・`y`・`label`・`labelJa`・`name`・`color`・`size`。
- `PoiSample` は、POI スタイルを、セルと同じ描き方で描く。z8。z7・z6 は縮小。

### MDI のデータ

MDI のデータは、npm の `@mdi/svg` から作る。ビルドの依存にはしない。

```
npm pack @mdi/svg@7.4.47        # できた .tgz をフォルダに展開（tar -xzf）
dotnet run --project tools/FxMapGenerator.DevTools -c Release -- mdi-icons <展開先>/package data/mdi-icons.json
```

使われなくなったアイコンは除く。画面の検索用の別名と分類、版を持つ。

## 文字

画面のジョブ一覧では「ラベル」。

地区と地域の色の後のステップ。`LabelsStage`、単位は言語。
コードは `src/FxMapGenerator.Core/Labels/`。

- アトラス地図の言語ごとに、全域の文字を 1 回置く（`LabelPlacer`）。描画は、置いた文字を描くだけ。
- 差分更新でも、全域の文字を置き直す。
  同じ入力なら同じ文字になり、変えた所のまわりの文字だけが動く。
- 描き直すのは、文字の変わったセルだけ。

### 置くものと順

- 番地: プロジェクトの `postals`（null は、nearest-postal の表の URL）を 1 回取り、
  `data/postals.json` にコピーする。
  大きさは、番地の `size`。なければ、スタイルの地区ごとの表。
- 置く順: 番地と POI（重なりを調べない）→ 地区名 → 通り名（格の高い名前から）。
- 重なりは、1 m の格子で判定する（`Occupancy`、Pillow の多角形の塗りと同じマス）。
  置いた文字のまわりに、`clearance` を空ける。
- 文字の寸法は、この PC のフォント（SkiaSharp、ヒントなし）。
  外形は、Skia が測ったまま（1 m 単位に切り上げない）。

### カヨ・ペリコの島の地区名

- カヨ・ペリコの島の地区（`ISHEIST`）の名前は、プロジェクトが島の道を読むとき（`cayoPerico`）だけ置く。
  `LabelsStage.UnnamedZones` を、`LabelInput.UnnamedZones` に渡す。スタイルエディタのプレビューも、
  同じ決まり。
- この地区は、島のまわりの海と、既定の範囲に入っている空母の所まで広がっている。
  そのため、島のない地図では、海の上に名前が出る。
- 地区そのもの（地域の色、番地の大きさ、クリックした地点の地区）は、変わらない。
- 記録の `cayoPerico` が、プロジェクトの値と違う（か、ない）と、置き直す。

### 通り名

- 通り名の線（`StreetParts`）は、次の順で作る。
  1. 同じ名前の道を、端がまっすぐ続く組で、つなぎ直す。
  2. つながらない大通りは、形から中心線を取る（2 m の格子、閉じ、細線化）。
  3. 上下線を、真ん中の線にまとめる。
  4. 50 度より急な角で切る。
  5. ほかの名前の高速道路と並ぶ所を、分ける。
- 数の計算は、C・numpy・Python と同じビットを出すもの（`Num`）を使う。
  C の pow の `x ** 2`、numpy の arange と round、Python の `//` と round。
- 骨格の点を線に分ける順は、CPython の set の並び順（`PixelSet`）にしている。
- 通り名は、ゲームの名前（`game/names.json`）と、道の編集が足す名前（`streets`。英語と日本語）。
  日本語のない名前は、日本語の地図でも英語。
- 道の編集を読むステップが実行中の間は、画面から保存できない。

### ファイル、作り直し、所要

- 置き方のハッシュごとに、ファイルを作る。
  置き方のハッシュは、スタイルの `labels` の、色・縁取り以外の SHA-256。
  同じ置き方の地図（同梱の `postalcodemap` と `regional`）は、1 つのファイルを使う。
- 作り直すのは、次のとき。
  - 道路グラフ・地区・ゲームの名前が新しいとき。
  - 置き方のハッシュのファイルがないとき。
  - 番地のコピー・POI・道の編集の通り名（`streetsSha256`）が、記録と違うとき。
- 所要は、全域で 1 言語 5 秒ほど。

## セルの描画

画面のジョブ一覧では「セル描画」と「縮小タイル」。

セルの地図データと文字の後のステップ。`CellDrawStage`、単位はセル。
アトラスと道路地図の地図ごとに、`cells.<地図>`。
コードは `src/FxMapGenerator.Core/Render/`。

セルを z8 の縮尺（1 ブロック 1,024 px）で描き、セルの自分のブロックを z8 のタイルに切って、
その上の z7〜z5 を作る。
タイルの縮小は、衛星地図と同じ Lanczos。

### 描く順

`CellPainter` は、次の順に描く。

1. 背景。
2. 地面の画像（双一次で拡大）か、地面の層。
3. ここまでの絵に、陰影（`ShadeLayer`）。
   1 m の明るさを、SciPy の `ndimage.zoom`（1 次）と同じ値で拡大し、float32 で掛ける。
4. 残りの層を、層の順に。
   偶奇で塗り、同じ色の 0.6 px の縁で、つなぎ目を隠す。
   木の茂みは、色の重ねか模様。等高線は、線。
5. 道。
   トンネル、未舗装の道、地面の高さの帯の縁取りと塗り、角のつぎ、交差点の角の丸め、上の段の帯を段ごとに。
6. 最後に、文字。番地、POI、地区名。通り名は 1 字ずつ。

水の不透明度:

- 不透明度（`paint.waterOpacity`・`paint.sea.opacity`）が 1 より小さい水と水深の帯は、
  その所の下の絵を消して、その色と不透明度で塗る。
  その後に描くものは、不透明のまま。
- 絵に透明を残すのは、そういう水のあるスタイルだけ（`MapStyle.SeeThroughWater`）。透明のあるタイルは RGBA。
  ほかのスタイルの絵は、不透明にする。

### 描くものの選び方

- 層は、スタイルの値を表す名前（`set`）が、そのスタイルのものだけを描く。
  色は、スタイルから取る（文字のファイルには、色を持たない）。
- 道の形・文字・POI は、セルの四角のまわりにかかるものだけを選ぶ。
  外の物は絵に出ないので、選び方で絵は変わらない。
- 絵は、セルの四角の画素で作った線を、ブロックごとに 1,024 px ずらして描く。メモリは、ブロック 1 枚分。
  つなげると、セルを一度に描いた絵と同じになる。
- セルが全域のデータから使うものは、1 か所で選ぶ（`CellInputs`）。描画は、これだけを描く。
  - 道の形: セルのブロックの四角の外 50 m までにかかるもの。
  - 文字と POI: 点が、その外 200 m までにあるもの。

### 記録、描き直し、所要

- 道の形と文字のステップは、セルごとの部分のハッシュを、記録（`cells`）に持つ。
- `cells/<セル>/draw-<地図>.json` に、セルを描いたときのハッシュを持つ。
  - `prep`: 地図データのうち、その地図が読むファイルのもの。セルの記録の `outputs` からまとめる。
  - `roads`・`labels`・`pois`。
- 描き直すのは、次のとき。
  - スタイルが、`data/draw-<地図>.json` と違うとき（全セル）。
  - セルの描画の記録がないとき。
  - セルが使うものが変わったとき。
    地図データ・道の形・文字は、そのステップが描画より後に動いたときだけ、比較する。
    同じ中身で作り直された道の形や文字では、セルを描き直さない。
- 所要は、全域 23 セルで、1 地図 30 秒ほど（並列 12）。

### 縮小タイル

`CellLowZoomStage`、`lowZoom.<地図>`。

- プロジェクトの枠の中で、範囲の外の z8 タイルを、スタイルの外洋の色と不透明度で塗る。
  - 色: `MapStyle.OpenSea` = `paint.sea.sand` の最後。最も深い帯の色。
  - 不透明度: その帯の不透明度（`paint.sea.opacity` の最後）。同梱のアトラスのスタイルでは、透明。
  - 範囲の端の海が、段なく続く。衛星地図の外洋と同じ扱い。
- z7〜z0 を、全部作り直す。
- 枠が記録（`data/low-zoom-<地図>.json`）と違うときも、作り直す。狭めた枠の外に残ったタイルは、消す。
- 4 枚とも同じ、一様で不透明なタイルの親は、そのバイトをそのまま書く。
  Lanczos は、一様な絵を一様なまま縮めるので、縮めた結果と同じ。
- 所要は、全域で 1 地図 10 秒ほど。
- ミニマップ（ytd）は、衛星地図と同じ作り方で、アトラスと道路地図からも作れる。
- 書き出しのビューアの背景も、同じ外洋の色。

## ミニマップと書き出し

### ミニマップ（ytd）

コードは `src/FxMapGenerator.Core/Minimap/`。
プロジェクトの `minimap`（地図）を選ぶと、ビルドの最後のステップになる。

**6 つのシート**

標準の枠を、4500 m 四方の 2×3 のシート（行 0 が北、列 0 が西）に分ける。
シートごとに、次のことをする。

1. その地図のタイルから、1 枚 4096 px の絵を組み立てる。
   - z6 のタイル 16×16。z6 のタイル 1 枚が、1 ブロック。ないタイルは透明。
   - プロジェクトの `minimap.outside` が `transparent` なら、範囲の外のブロックも透明にする。
   - 8192 px（z7）は選べない。
     ゲームで比較して違いがなく、FiveM が DXT5 の 64 MiB を「大きすぎる」と警告するため。
2. 2 つの形で圧縮する。ミップは 1。
   - DXT5（`minimap_sea_<行>_<列>`）。
   - DXT1 の 1 ビット透明（`minimap_<行>_<列>`）。
     先に、完全に透明でない画素を、すべて不透明にする（半透明の水も）。
     レーダーは DXT1 を描き、地図が透明な所だけ、下の全体図が見える。
   - ゲームのミニマップは、この名前でテクスチャを探す。
   - 小さいミップがあると、テクスチャ品質「標準」でゲームがそれを使い、拡大するとぼやける。
   - 圧縮は、256 行ずつの帯に分け、空いたスレッドで並べて実行する。
     ブロックは 1 つずつ圧縮されるので、帯をつなげたものは、全体を 1 度に圧縮したものと同じ。
3. `ytd/<地図>/4096/` に書く。一時ファイルから置き換える。

記録と作り直し:

- 記録は、`ytd` の `<地図>@4096/<行>_<列>`。
  シートを作った 256 枚のタイルのハッシュは、`data/minimap-<地図>-<行>_<列>.json`。
- その地図の縮小タイルの記録より古いシートは、そのタイルが変わったときだけ、残りに出る。
  1 つのシートは 2 × 2 セル。
  そのため、差分更新で作るのは、多くても描いたセルのシートで、そのうちタイルが変わったシートだけ。
- 6 つがそろったら、範囲の外の扱いを、`data/minimap-<地図>.json` に書く。
  今の設定と違えば、6 つとも残りに出る。
  もう一方の扱いで作り直し始めるとき、先に記録を消す。
  途中で止まっても、今の扱いのシートの横に、前の記録が残らない。

**全体図**

単位がもう 1 つ（`<地図>@4096/lod`）あり、ゲームがレーダーの下に敷く全体図を作る。
`minimap_lod_128`、`MinimapLod`。

- ゲームのものは、標準の枠（6 つのシートと同じ 9000 × 13500 m）を、128 × 128 px に縮めた絵。
- そのため、地図の標準の枠の z2 のタイル 6 枚を並べて、その大きさに縮める（Lanczos）。
- スタイルの外洋の色（衛星地図は黒）の上に重ねて不透明にし、DXT5・ミップ 1 にする。
- 作っていないか、そのタイルが変わったときに、残りに出る。
  タイルのハッシュは、`data/minimap-<地図>-lod.json`。
- ジョブ一覧は、シートと一緒に数える。

**標準の枠の外のセル**

標準の枠の外（カヨ・ペリコなど、セルを足した枠）の地図は、ゲームの 6 つのシートには入らない。
標準の枠の外で、範囲のブロックを持つセルごとに、テクスチャを 1 つずつ作る。
`MinimapExtraTiles`、単位 `<地図>@4096/cell_<行>_<列>`。

- そのセルの z6 のタイル 8 × 8 を並べる。
- 2,250 m を 2048 px（シートと同じ細かさ）。DXT5・ミップ 1。透明は、シートと同じ。
- 名前は `fxmapgen_extra_<行>_<列>`。マイナスは `m`（例 `fxmapgen_extra_m1_0`）。
- 枠はセル単位で広がる。そのため、セルは、シートの中か、まるごと標準の枠の外かの、どちらか。
- ゲームの中では、Extra Map Tiles が描く（下の「ミニマップのリソース」）。
- 残りに出る決まりは、シートと同じ（`data/minimap-<地図>-cell_<行>_<列>.json`）。
- ジョブ一覧は、シートと一緒に数える。

**所要**

シート 1 つで、14 秒ほど。シートを並べて、帯は空いたスレッドで実行する。
並列数 12 で、6 つが 15 秒（`data/timings.json`）。

### 書き出し: Web の部分

- Web の部分は、書き出すたびに作り直す。前の書き出しのタイルは、残さない。
- ほかのファイルがあり、記録のないフォルダには、書かない。
- Web タイルは、最大ズーム（`maxZoom`、6〜8、既定 8）までを書く。
  - 1 段下げるごとに、ファイル数は約 4 分の 1。
    衛星地図の全域で、z8 まで 32,769、z7 まで 8,193、z6 まで 2,049。
  - 静的なホストには、ファイル数に上限があるものがある。
  - ビューアは、その先を引き伸ばして表示する。
- 上か左にセルを足した枠では、タイルの番号を、枠の北西の角から振り直して書き出す（`WebExport.Renumbers`）。
  - z3〜z8 は、番号をずらしてコピーする。z2〜z0 は、書いた z3 から作り直す。
  - その格子に合わせて作った地図とは、番号が合わない。
  - ビューア・lb-phone の例・README は、枠に合わせて書く。
  - 書き出すのは、枠の中のタイルだけ。

lb-phone の例:

- lb-phone は、`resolution` から、縮尺とズームの段を計算する。
  `resolution` は、最大ズームでの地図全体の画素数。
  標準の枠なら、z8 で 32768×49152、z7 で 16384×24576。
- そのため、例の `resolution` と `zoom.max` は最大ズームに、
  `topLeft`・`bottomRight` はプロジェクトの枠に合わせる。
- タイルは、loaf-scripts の地図タイルと同じ格子。z8 の 1 枚 = 70.3125 m。
  標準の枠の z7 までの書き出しは、loaf の設定と同じ `resolution`。

### 書き出し: 変更前のタイル

前回の書き出しの後に書き換えた地図のタイルは、書き換える前の中身を残す（`TileStore.Keeping`）。

- 同じバイトのタイルは、書き直さない。
- 違うバイトで最初に上書きしたときに、前のバイトを、作業フォルダの `before/<地図>/{z}/{x}/{y}.png` に置く。
- 対象は、セル描画・縮小タイル・オルソ補正・撮影中の仮のオルソ補正。
- まだ書き出していなければ、「前」は、タイルを最初に書き換えた実行の前の地図。
- 書き出しが済むと、書き出した地図の `before/<地図>` を消す。書き出さなかった地図は、前のタイルが残る。
- 地図表示の「変更前との比較」は、これを読む（下の「画面と、開いているプロジェクト」）。

### 書き出し: ミニマップのリソース

- リソース名には日付を付け、同じ名前があれば、`-2`、`-3` を足す。
  FiveM は、同じ名前のリソースのファイルを、キャッシュに残すため。
- 画面とコマンドで、名前を指定できる（英小文字・数字・`-`・`_`）。
- 6 つのシートは、ゲームと同じ名前のファイルで、ゲームのものを置き換える（リソースの stream の仕組み）。
- 標準の枠の外のテクスチャは、同梱の Extra Map Tiles 3.0.1 が描く。
  MIT。公開されたものをそのまま（`data/minimap/README.md`）。
  - 書き出しが、その形の `config.lua` を書く。セルごとに、タイルを 1 つ。
    - `txd` = `txn` = テクスチャ。
    - `x`・`y` = セルの北西の角（ゲームの m）。
    - `x_scale` = `y_scale` = 0.5（1 で 4500 m）。
    - `alpha` 100。
  - `remove_blur`（傾いたレーダーのマスクの差し替え）は、タイルがあるときだけ true。
  - Extra Map Tiles は、タイルの角に見えない blip を置くので、ESC の地図がそこまで動く。
  - 標準の枠だけのプロジェクトも、同じリソース（タイルなし）。
- `zoom.lua` は、ESC の地図のズームの段と、レーダーのズーム（1100、歩きも車も）を決める。
  値は、postal code map（Virus_City）の元のスクリプトと同じ。
  プレイヤーのいる内装で、呼ぶ命令を変える（下の「内装の地図」）。
  リソースを止めると、レーダーのズームとズームの段を、ゲームのものに戻す。
- 空の ydd は、postal code map の最初の版のもの（`data/minimap/README.md`）。
- レーダーは、FiveM を起動したときに読んだ絵を、ゲームを閉じるまで持ち続ける。入り直しでも替わらない。
  ESC の地図は、すぐ替わる。
- リソースの README（英語と日本語）に、次のことを書く。
  - 入れた後は、FiveM を起動し直すこと。
  - 外すリソース: PostalCodeMap、ほかのミニマップ、すでに動かしている Extra Map Tiles。
    島の地図を入れるときは、CayoPericoMinimap などの島の地図のリソースも。島を読み込むリソースは残す。
  - 建物の中と地下で出る地図。
  - 島を読み込むリソースが毎フレーム呼ぶ 2 行と、その扱い（下の「内装の地図」）。
- `tests/minimap/run-resource.lua` は、書いたリソースのスクリプトを、
  小さな偽のゲーム（Lua 5.4）で動かす（テスト用）。
  Extra Map Tiles がタイルを描く位置と blip、ズームの呼び出し、止めたときに戻すものを見る。
  プレイヤーを、外、絵のない内装、絵を持つ内装、地下の内装に順に置いて、呼ぶ命令を見る。

内装の地図:

- ゲームは、内装ごとにレーダーの絵を持つ。ファイルは `int<内装の名前の joaat>.gfx`。
- `common\data\ui\frontend.xml` の `<minimap_interiors>` は、絵と内装の表。
  1 行が、絵の名前、置く位置、その絵にまとめる内装の名前。
- リソースは、この 2 つから作った一覧 `interiors.lua` を持つ（`InteriorMaps`）。
  - `RADAR_OWN_PICTURE`: 自分の絵を持つ内装の、名前のハッシュ。
    絵のファイル名の数字と、表の行（地下の 4 枚を除く）がまとめている内装。
  - `RADAR_UNDERGROUND`: 地下の通路の絵の行。絵の名前、位置、まとめている内装の名前。
- 地下の通路の絵は 4 枚。
  `V_FakeMetro`（地下鉄と水路）、`V_FakeWaterTunnel`、`V_FakeTunnel_SC1`、`V_FakeTunnel_ID1`。
  製品が持つのは、この 4 つの名前だけ。
- 一覧は、書き出しのときに、この PC の GTA V から読む（`MinimapGameFiles`）。
  - 表は、ゲームの順で最後にある `data\ui\frontend.xml`（`update.rpf` のもの）。
  - 表のファイルは、整った XML ではない（コメントにハイフンが続く）。行は、タグで拾う。
- 書き出しには、GTA V と暗号鍵が必要（`MINIMAP_NO_GTA`・`MINIMAP_NO_KEYS`）。
- 絵のファイルが 1 つもないゲームと、表がないゲームは、エラー。
- 4 枚のうち、表に行がない絵は、入れずに書く。ログに出す。
- 編集した画像の変換が書くリソースも、同じ。

`zoom.lua` は、プレイヤーのいる内装で、呼ぶ命令を 3 つに分ける。
内装は `GetInteriorFromEntity` と `GetInteriorLocationAndNamehash` で見分け、内装が変わったときだけゲームに聞く。

| プレイヤーのいる所 | 呼ぶ命令 | 見え方 |
|---|---|---|
| 外。絵のない内装 | `SetRadarZoom(1100)` | 地上のズームの地図 |
| 自分の絵を持つ内装 | `SetRadarZoom(0)` | 間取りに切り替わる |
| 地下の絵がまとめている内装 | `SetRadarZoom(1100)`、`SetRadarAsExteriorThisFrame()`、`SetRadarAsInteriorThisFrame(絵, x, y, 0, 0)` | 地上のズームの地図に、通路の絵が重なる |

- `SetRadarZoom` で決めた値は、決め直すまで残る。0 で、ゲームの値に戻る。
  そのため、毎フレーム呼ぶ。呼ぶのは、徒歩か乗り物のときだけ。
- 自分の絵を持つ内装では、ESC の地図が内装の表示の間だけ、`HideMinimapExteriorMapThisFrame()` を呼ぶ
  （`IsPauseMenuActive() and IsPausemapInInteriorMode()`）。
  ESC の地図も、間取りだけになる。
- レーダーのためには、外の地図を隠さない。
  ESC を閉じている間は、ゲームが内装の表示かどうかを知る手段がない。
- 地下の内装では、`SetRadarAsExteriorThisFrame()` が外の地図を残す。
  ESC の地図も、内装の表示にならない。
- この形は、ゲームで見て決めた。

サーバーの設定 `fxmapgen_minimap_fixed_zoom`:

- `server.cfg` に `setr fxmapgen_minimap_fixed_zoom true` を書くと、
  `zoom.lua` は、どこでも `SetRadarZoom(1100)` を呼ぶだけになる。
- クライアントに配られる convar。リソースが動き出したときに読む。
- 島を読み込むリソースが、場所に関係なく毎フレーム次の 2 行を呼ぶサーバーのためのもの。
  `SetRadarAsExteriorThisFrame()` と `SetRadarAsInteriorThisFrame(h4_fake_islandx, ...)`。
  Cfx.re フォーラムの「The Cayo Perico Island Available for FiveM」の IPL のリソースが、そうしている。
- その 2 行が呼ばれている間、ゲームは内装の絵を出さない。
  ゲームが出せる絵は、1 フレームに 1 枚。
  2 つのリソースが呼ぶと、後から起動したリソースの絵が出る。
- そのサーバーでは、自分の絵を持つ内装の中のレーダーが、大きく拡大された地図だけになる。
  絵が出ないまま、ズームだけがゲームのものに戻るため。
- README は、2 行を消すか、この設定にするかを、それぞれの結果と一緒に書く。

カヨ・ペリコの島の地図:

- カヨ・ペリコの道を読むとき（`cayoPerico`）は、何も描かない島の地図を入れる（`IslandMap`）。
  この PC の GTA V の `int3232302352.gfx` の、形 4 つを空にしたもの。`SCALEFORM_DLC_FILE` で登録する。
- 島は、この地図の絵（シートの中の所と、枠の外のセル）で見える。
- サーバーの島のスクリプトが島の地図を要求していなくても（`h4_fake_islandx` の
  `SetRadarAsInteriorThisFrame`）、島は見える。
  リソースは要求しない。
- 内装の地図の一覧と同じく、書き出しのときに、この PC の GTA V から読む。
- 範囲にない島の陸のブロックを数える（画面に出す。ゲームでは、そこの島が欠ける）。
- ファイルは、リソースにだけ入れる。

### 書き出し: 編集用のファイル

地図を、レイヤーに分けた 1 枚の絵として書き出す。
ほかのソフトで開いて、手を加えるためのもの。
形式は 2 つ。

| 形式 | 開くソフト | 中身 |
|---|---|---|
| PSD | Photoshop、GIMP | どのレイヤーも画像 |
| SVG | Inkscape、Illustrator | 道路・文字・POI は形と文字。ほかのレイヤーは PNG の画像 |

開いて確認したのは、GIMP 3.2 と Inkscape 1.4。

コードは、次のとおり。

- `Core/Export`: `EditableStages.cs`（2 つのステップ）、`LayeredBlock.cs`（レイヤーを縮める）、`PackedBlocks.cs`（一時ファイル）。
- `Core/Export`: `PsdFile.cs`・`PackBits.cs`（PSD）、`SvgFile.cs`（SVG）。
- `Core/Imaging`: `PngWriter.cs`（SVG がリンクする PNG）。
- `Core/Render`: `CellPainter.DrawLayers`（レイヤーごとに描く）、`MapLayer.cs`（レイヤーの一覧）。

**書くとき**

- 書くのは、その書き出しで地図を選んだときだけ。
- どの地図を書いたかは、プロジェクトに残さない。`export.editable` に残すのは、ズームレベルと形式。
- コマンドの `export` は、`--editable <地図>,...` を付けたときだけ書く。
- 選んだ地図を、選んだ形式のすべてで書く（`EditableChoice.Written`）。
  地図を選んで、形式を 1 つも選ばないと、書き出せない（`NO_EDITABLE_FORMAT`）。

**大きさとファイル**

- 絵は、プロジェクトの枠の全体。
- ズームレベルは 6 か 7（`EditableChoice`）。1 ブロックが、z6 で 256 px、z7 で 512 px。
- 標準の枠の z6 は 8192×12288 px。ミニマップのシート 6 枚と同じ画素。
- `<地図>` は、Web タイルのフォルダと同じ名前（`MapSet.ExportName`）。
- PSD のファイルは `editable/<地図>-z<ズーム>.psd`。
  1 辺が 30,000 px を超えるか、ファイルが 2 GB を超えるときは、PSB（`.psb`）にする。
- SVG のファイルは `editable/<地図>-z<ズーム>.svg`。
  リンクする PNG は、横のフォルダ `<地図>-z<ズーム>-svg/` に置く（下の「SVG の形」）。
- 同じ名前のファイルとフォルダは、上書きする。

**レイヤー**

下から順に（`MapLayer`）。その地図にないものは、書かない。

| レイヤー | 中身 | 描画モード |
|---|---|---|
| 地面 | 背景の色と、地面の絵か地面の面。陰影なし | 通常 |
| 陰影（暗い側） | 陰影が地面を暗くする所 | 乗算 |
| 陰影（明るい側） | 陰影が地面を明るくする所 | 覆い焼きカラー |
| 木の茂み | 木の茂み | 通常 |
| 水 | 水と、海の深さの帯 | 通常 |
| 建物 | 建物 | 通常 |
| 等高線 | 等高線 | 通常 |
| 線路 | 線路 | 通常 |
| 道路 | トンネル、未舗装の道、道と縁、高架 | 通常 |
| 番地 | 番地 | 通常 |
| POI | POI | 通常 |
| 地区名 | 地区名 | 通常 |
| 通り名 | 通り名 | 通常 |

- 陰影の 2 枚は、地面にクリッピングする（`MapLayers.Clipped`）。地面のない所には、効かない。
  SVG には、クリッピングに当たる指定がない（下の「SVG の形」）。
- 範囲の外のブロックは、水のレイヤーに、スタイルの外洋の色を入れる（タイルと同じ。外洋が透明なスタイルでは、何も入れない）。
- 衛星地図は、タイルそのままの 1 枚（「衛星地図」）。
- レイヤーの名前は、画面の言語（`MapLayers.Name`）。
  コマンドでは、アプリの設定の言語が `ja` のときだけ日本語。
  PSD の古い名前の欄には、英語の名前を入れる。
- レイヤーの大きさは、中身のあるブロックを囲む四角。
- 地面から線路まで（`MapLayers.LastPicture` まで）は、どの形式でも画像。
  その上の道路・番地・POI・地区名・通り名は、PSD では画像、SVG では形と文字。

**レイヤーごとに描く**（`CellPainter.DrawLayers`）

- 地図のタイルを描く `DrawArea` と同じステップを、種類（`StepTag`）で、レイヤーごとの絵に振り分ける（`MapLayers.Of`）。
  `DrawArea` は、そのまま。
- 陰影は、地面に掛ける数（`ShadeLayer.Factor`）を、2 枚に分ける。
  - 1 未満の所は、暗い側に、その数の灰色を入れる。乗算は「下の色 × 灰色」。
  - 1 を超える所は、明るい側に、「1 ÷（1 − 灰色）」がその数になる灰色を入れる。覆い焼きカラーは「下の色 ÷（1 − 灰色）」。
- 透ける水は、下のものを置き換える描き方（`FilledLayer`）。そのため、地面を、水の所で抜く。
  - 水のステップを、不透明な絵の上にも描く。
    その絵に残った不透明度から、水の不透明度を引いたものが、水が残した地面の割合。
  - 地面の不透明度 = その割合 ÷（1 − 水のレイヤーの不透明度）。水のレイヤーを重ねると、地図の画素になる値。
  - 不透明な水の下では、地面を残す。
- レイヤーを下から重ねると、`DrawArea` の絵になる。差は 8 ビットの丸めの分で、陰影のある所で 3〜4 段まで。

**レイヤーを縮める**（`LayeredBlock.Shrink`）

レイヤーを 1 枚ずつ縮めて重ねても、タイルにはならない。

- タイルは、全部を重ねてから縮めた絵。縮めると、形のふちの明暗が少し強まる。
- 透ける水の岸では、地面と水を別々に縮めると、境の画素がタイルより透ける。

そのため、縮めたレイヤーは、縮めた絵から逆に求める。

1. z8 で、レイヤーを下から 1 枚ずつ重ねた絵を作る。
   順は、地面、陰影を掛けた地面、その上のレイヤーを 1 枚ずつ。
2. その絵を、どれもタイルと同じ縮め方で縮める
   （`EditableLayersStage.Shrink`: z8 の 4 枚を z7 の 1 枚に、z6 ならその 4 枚を 1 枚に。Lanczos）。
3. 縮めた「1 つ前まで」の絵を「ここまで」の絵にするものを、そのレイヤーにする。

レイヤーごとの求め方は、次のとおり。

- 地面は、最初の絵そのもの。
- 陰影の 2 枚は、縮めた地面と、縮めた「陰影を掛けた地面」の比。
  - 3 つの色を 1 つの比で 1 段以内に出せる画素は、灰色。
  - 出せない画素は、色ごとの比。
- ほかのレイヤーは、不透明度を、1 枚で縮めたときの値から始める。
  色は、「ここまで」の絵になる色にする。
  - 形の中は、塗りの色のまま。
  - 形のふちは、縮めるときの明暗の強まりを持つ。
- 不透明度を動かすのは、「ここまで」の絵にするために要る所だけ。
  - 透ける絵の上では、「ここまで」の絵の不透明度になる値にする。透ける水の岸が、これに当たる。
  - 0〜1 の色では「ここまで」の絵にならない所は、不透明度を上げる。
    レイヤーが画素を動かせるのは、不透明な分だけのため。
- 1 枚で縮めたレイヤーに何もない画素には、次の 2 つがそろうときだけ、画素を足す。
  足すのは、形の外に出る明暗の縁で、薄い白か黒になる。
  - 縮めた 2 枚の絵が、そこで違う。
  - そこまでのレイヤーを重ねた絵が、「ここまで」の絵とまだ違う。

どこまで合わせるかは、`LayeredBlock.Slack` の 3 つの値。

| 値 | 既定 | 意味 |
|---|---|---|
| `Inside` | 3 | レイヤーに中身のある画素で、残してよい差。255 段のうち |
| `Beside` | 3 | レイヤーに中身のない画素で、残してよい差 |
| `BesideOpacity` | 0.25 | 中身のない画素に足す不透明度の上限 |

- 差を小さくするほど、足す画素が濃くなる。
- 白や黒に近い画素は、少し動かすだけでも、濃い画素が要る。
  例: 白より 10 段暗い画素を 5 段明るくするには、不透明度 50 % の白が要る。

重ねた絵とタイルの差で、残るものは次のとおり。

- 上の「残してよい差」。
- 上限より濃い画素が要る所。
- z8 でのレイヤーと絵の差。
- 透ける水の上にある、不透明な形のすぐ外。
  縮めると、タイルはそこで少し透ける。上に重ねるレイヤーでは、透かせない。

**まとめる**

2 つのステップで作る。

1. `export.layers`（`EditableLayersStage`）。単位は、アトラス地図・道路地図のセル。
   - セルのブロックを、レイヤーごとに描く。
   - ブロックのレイヤーを、ズームレベルの大きさにする（上の「レイヤーを縮める」）。
   - 縮めたレイヤーは、行ごとに圧縮した形（`PackBits`）で、一時ファイルに置く（`PackedBlocks`）。
     場所は、書き出し先の `editable/.work/`。
   - 使用メモリは、セル描画と同じくらい。
   - 縮める処理は、レイヤー 1 枚につき 2 回。1 枚だけの絵と、そこまで重ねた絵。
   - 形式が SVG だけのときは、線路より上のレイヤーを縮めない。SVG は、それらを画像にしないため。
2. `export.files`（`EditableFilesStage`）。単位は、地図と形式の組。
   - PSD と SVG は、同じ一時ファイルから書く。レイヤーを描くのは 1 回。
   - 書き終えたら、書き出しの記録に足す（`ExportRecord.AddEditable`）。
   - ステップの終わりに、一時ファイルを消す。

PSD を書く手順は、次のとおり。

- 重ねた絵（PSD の最後に入る、全部を 1 枚にした絵）は、その地図のタイルから作る。
- レイヤーは、ブロックの行を、左から右へつないで 1 行にする。
  圧縮した行は、つなぐだけで、その 1 行を圧縮したものになる。
- 行の長さを先に数えて（`PsdFile.Measure`）、PSD か PSB かを決めてから書く。
  絵の全体は、メモリに載せない。

SVG を書く手順は、次のとおり。

- 画像のレイヤーを、1 枚ずつ PNG に書く（`PngWriter`）。レイヤーごとに、並列で書く。
  ブロックの行を 1 行ずつ読んで（`PackedBlocks.Pixels`）、そのまま書く。絵の全体は、メモリに載せない。
- 道路・文字・POI は、地図のデータから書く（`SvgFile`）。読むのは、`data/road-shapes.grid`、文字の配置、POI。
- PNG と SVG は、`editable/.work/` に作って、書き終えてから置き換える。
  同じ名前のフォルダは、消してから置く。

- セルが 1 つでも失敗したか、途中で止めたときは、ファイルを作らずに、一時ファイルを消す。

**PSD の形**（`PsdFile`）

- 8 ビット、RGB。レイヤーは、アルファ・赤・緑・青の 4 つの面。どの面も、行ごとの PackBits。
- レイヤーの名前は、ユニコードの欄（`luni`）と、古い名前の欄の両方に書く。
- 画像リソースは、解像度（72 ppi）だけ。
- 重ねた絵に透明な所があるときは、4 つ目の面をその透明度にして、レイヤーの数を負で書く。
  色は、白の上に重ねた値で書く（画像編集ソフトの書き方。読む側が白を取り除く）。
- PSB は、長さの欄が 8 バイト、行の長さが 4 バイト。

**SVG の形**（`SvgFile`）

- 1 単位が、ズームレベルの 1 画素。`width`・`height`・`viewBox` は、絵の画素数。
  1 画素 1 単位で PNG に書き出すと、編集した画像の変換が読める大きさになる。
- レイヤーは、ルートのすぐ下の `<g>`。Inkscape のレイヤーの印（`inkscape:groupmode="layer"`）を付ける。
  - `id` は、英語の名前から作る（`SvgFile.Id`。例 `Shading_dark_side`）。
  - `inkscape:label` は、画面の言語の名前。
- 座標は、小数 2 桁。形の点は、前の点からの差で書く。
- SVG は書くだけで、製品は読まない。

画像のレイヤー:

- `<image>` で、横のフォルダの PNG をリンクする（`xlink:href`。相対パス）。
- PNG の名前は、レイヤーの英語の名前から付ける（`EditableChoice.PictureName`）。
  `ground`・`shading-dark`・`shading-light`・`tree-canopy`・`water`・`buildings`・`contours`・`railway`。
  衛星地図は `satellite`。
- 陰影の 2 枚は、レイヤーの `style` に `mix-blend-mode` を付ける。
  暗い側は `multiply`、明るい側は `color-dodge`。
- SVG には、下のレイヤーでのクリッピングに当たる指定がない。
  そのまま置くと、地面のない所に陰影の灰色が出て、地面が画素の一部に掛かる所は不透明になる。
  そのため、水が透けるスタイルでは、PNG の画素を 2 か所変える
  （`EditableFilesStage.ShadeInGround`・`KeepToWholeGround`）。
  - 陰影の PNG は、地面が画素の全体に掛かる所だけにする。
  - 地面が画素の一部に掛かる画素は、地面の PNG に、陰影を掛けた後の色を入れる。
  - 重ねた絵は、PSD のレイヤーを重ねた絵と同じになる。

道路（`RoadDrawing` が描く順のまま、形 1 つが `<path>` 1 つ）:

| グループ | 中身 |
|---|---|
| トンネル | トンネル 1 つが 1 つの形。輪郭の全部。半透明の塗りと、破線の縁 |
| 未舗装の道 | つながる線分を 1 本にした線。幅のある線 |
| 一般道の縁、高速道路の縁 | 道の縁の面、道の端の継ぎ目の縁、交差点の角の縁 |
| 一般道、高速道路 | 道の面、道の端の継ぎ目の面 |
| 交差点の角 | 角を丸めた所の面と、その継ぎ目 |
| 高架 1、高架 2、… | 高さごと。縁、未舗装の道、一般道、高速道路の順 |

- グループの色は、グループの `fill`（未舗装の道は `stroke`）に書く。形は、色を持たない。
- 描くときに線で描いているもの（継ぎ目の縁、交差点の角の縁と継ぎ目）は、線の輪郭の面にして書く
  （`SKPaint.GetFillPath`）。グループの中の形が、どれも同じ色の面になる。
- 交差点の角の継ぎ目は、角の面で切り抜いた形にする（`SKPath.Op`）。
- 範囲のブロックに掛かる形を、切らずに書く。範囲の端で形を切るタイルとは、そこが違う。

文字:

- 番地・地区名・POI の文字は、1 つが `<text>` 1 つ。
  位置は、描くときと同じ数から出す（`CellPainter.SetText`）: 幅の中央と、字の高さの中央が、その点に来る。
- 通り名は、`<text>` 1 つに、1 字ごとの `x`・`y`・`rotate` の並びを付ける。
- 縁取りは、文字の `stroke`。`paint-order` で、塗りの下に描く。
- カーニングと合字は、切る（`font-feature-settings:'kern' 0`、`font-variant-ligatures:none`）。
  描くときは、1 字ずつ、字の送り幅どおりに並べているため。
- フォントは、スタイルのフォント名と太さ。開く PC に入っているフォントで表示される。

POI:

- POI 1 つが、`<g>` 1 つ。`inkscape:label` は、POI の名前（なければ文字）。
- 丸は `<circle>`、MDI のアイコンは `<path>`、PNG のアイコンは `<image>`。
  PNG は、`poi-<POI スタイルの id>.png` の名前で、横のフォルダにコピーする。

### 書き出し: 編集した画像の変換

編集用のファイルを画像編集ソフトで編集し、全体を 1 つの PNG に書き出した画像から、
Web タイルとミニマップのリソースを作る。

- プロジェクトの地図には、足さない。作業フォルダにも、何も書かない。
- 書き出しとは別のジョブ。
  画面では、書き出しの画面の「編集した画像を変換」。コマンドは `convert`。

コードは、次のとおり。

- `Core/Imaging/PngRows.cs`: PNG を行ごとに読む。
- `Core/Export/PictureConvert.cs`: 選択（`ConvertOptions`）、画像の確認（`EditedPicture`）、
  できない理由（`ConvertStages.Check`）。
- `Core/Export/ConvertStages.cs`: 3 つのステップ。
- `Core/Minimap/MinimapTextures.cs`: テクスチャを作る部分。ミニマップのステップと共用。

**画像**

- PNG。プロジェクトの枠の全体で、編集用のファイルと同じ大きさ（`EditedPicture.Size`）。
  標準の枠で、z6 は 8192×12288 px、z7 は 16384×24576 px。
- ズームレベルは、画像の大きさから決める（`EditedPicture.ZoomOf`）。
  どちらの大きさでもなければ、変換しない（`BAD_SIZE`）。
- 行ごとに読む（`PngRows`）。絵の全体は、メモリに載せない。
  - 8 ビットと 16 ビット。色つき・灰色・パレット。
  - アルファ、`tRNS` の透明な色、パレットの不透明度。
  - 16 ビットは、上の 8 ビットを使う。
  - インターレースの PNG は、読まない（`INTERLACED`）。行が順に並ばないため。
  - 色のプロファイルとガンマは、見ない。チャンクのチェックサムは、確認しない。
- 読んでいる間、ファイルは上書きできない。

**元の地図**

画像を作った元の地図を、1 つ選ぶ（`ConvertOptions.Map`）。
出力に、その地図の次のものを使う。

- タイルのフォルダ名（`MapSet.ExportName`）と、地図の名前。
- 海の色。Web タイルの背景と、小さな全体図の下の色（`MinimapTextures.Under`）。
- クレジット。

選ばなければ、次の順に決める（`EditedPicture.DefaultMap`）。

1. 画像のファイル名が、編集用のファイルの名前（`<地図>-z<ズーム>`）で始まる地図。
2. ミニマップの対象の地図。
3. プロジェクトの最初の地図。

**ステップ**（`ConvertStages.For`）

1. `convert.tiles`（`ConvertTilesStage`）。単位は、画像 1 つ。
   - 画像を、タイルの行ごとに読んで、そのズームレベルのタイルに切る（`ConvertTilesStage.Cut`）。
     画像の画素が、そのままタイルの画素になる。
   - その下のズームを、z0 まで作る。ほかの地図と同じ縮め方（`LowZooms.BuildParents`）。
   - タイルは、書き出し先の `.convert/tiles/` に置く。番号は、作業フォルダのタイルと同じ。
2. `convert.textures`（`ConvertTexturesStage`）。ミニマップのリソースを出力するときだけ。
   - 単位は、6 つのシート、小さな全体図、標準の枠の外のセル。
   - ミニマップのステップと同じ部品で作る（`MinimapTextures`）。同じタイルからは、同じファイルになる。
   - `minimap.outside` が `transparent` なら、範囲の外のブロックは、画像に何があっても透明。
   - テクスチャは、書き出し先の `.convert/ytd/` に置く。
3. `convert.files`（`ConvertFilesStage`）。単位は、`web` と `resource`。
   - `web`: タイルを、`web-edited/<地図>/tiles/<地図>/` に書く。
     番号は、書き出しと同じ振り方（`ExportGrid`）。
   - `web`: ビューア、lb-phone の例、README、クレジットも書く。
     lb-phone の例の最大ズームは、画像のズームレベル。
   - `web`: 同じ名前のフォルダは、作り直す。ほかの名前のフォルダは、残す。
   - `resource`: ミニマップのリソースを書く（`MinimapResource.Write`）。
     中身は書き出しのものと同じで、テクスチャだけが画像から。名前の決まりも同じ。
   - 記録に足して、最後に `.convert/` を消す。

- 途中で止めたときと、失敗したときも、`.convert/` を消す。
  ステップの間で止めて残ったものは、次の変換か書き出しが、最初に消す。
- 書き出しの `web/` には、触らない。書き出しは、`web-edited/` に触らない。

**記録**（`fxmapgen-export.json`）

- `webEdited`: `web-edited/` にある出力の一覧（`ExportWebEdited`）。
  フォルダを消したものは、次に書くときに外れる。
- `resources` の `fromPicture`: そのリソースを画像から作ったとき、true。
- 記録のないフォルダに変換したときは、記録を作る。

**残すもの**

- 画面から変換したときは、画像ファイルの場所と元の地図を、プロジェクトに残す（`export.picture`）。
  出力形式の選択は、残さない。
- コマンドは、何も残さない。

**できない理由**（`ConvertStages.Check`）

| コード | 意味 |
|---|---|
| `NO_FOLDER` | 書き出し先がない |
| `NOT_EMPTY` | 書き出し先に、ほかのファイルがある |
| `NOTHING` | 出力形式を、1 つも選んでいない |
| `BAD_MAP` | 元の地図が、プロジェクトの地図でない |
| `BAD_PICTURE` | 画像を変換できない |
| `MINIMAP_NO_GTA`・`MINIMAP_NO_KEYS` | ミニマップのリソースに要る GTA V か暗号鍵がない |
| `BAD_NAME` | リソース名が使えない |
| `BAD_URL` | 公開先の URL が http(s) でない |

`BAD_PICTURE` の中身は、画像の確認の結果（`PictureInfo.Problem`）。
`NOT_FOUND`、`NOT_PNG`、`INTERLACED`、`BAD_SIZE` のどれか。

### 書き出し: クレジットと地図の名前

- クレジットは、地図の元（撮影・採取したサーバー）のあとに、
  その地図が実際に使ったデータの `credit` を集めて書く
  （`WebExport.DataCredits`）。同じ文は 1 回。
  - スタイル。
  - 番地と路線番号（文字の記録の数が 1 以上のとき）。
  - 出ている POI のまとまり。
  - 出ている POI が MDI のアイコンを描くときは、アイコン（`MdiIcons.Credit`）。
- 同梱のデータは、次の文を持っている。
  - PostalCodeMap 風の見た目と、A〜Z マーカー・色付きの丸（Virus_City）。
  - 路線番号（GTA Wiki）。
- 既定の番地の元（nearest-postal、MIT）の文は、プログラムが持つ（`PostalCodes.DefaultCredit`）。
  番地を既定の URL から取ったときに使う。
- 地図の名前は、スタイルの名前と、英語でない地図は言語から作る（`MapSet.Title`）。
  同梱のスタイルは英語の名前、自分のスタイルは書いたとおり。
- 英語のアトラス地図のタイルのフォルダは、言語を付けない（`MapSet.ExportName`）。

## FiveM リソース

`resource/fxmapgen-capture` は、サーバーに置くリソース。exe に埋め込む。
`FxMapGenerator.App.csproj` の `capture/<パス>`、`Services/CaptureResource.cs`。

- 画面は、選んだフォルダに `fxmapgen-capture/` として書き出すか、そのフォルダ 1 つを入れた zip を返す。
  同じ名前のフォルダがあれば、そこの版を見せて、置き換えるかを聞く。
- 起動（`refresh`・`ensure`）と、撮影・採取を取り終えた後の停止（`stop`）も、
  exe がゲームのコンソールから送る
  （下の「ゲーム」）。
- exe は、ゲームのコンソールソケットから `fxmapgen <サブコマンド> ...` を送り、リソースが出す行を読む。
  行は、どれも `[fxmapgen] ` で始まる。
- コマンドと出す行の形（プロトコル 1）は、`client/link.lua` の冒頭にまとめてある。
  詳しくは、`Docs/spec/link-protocol.ja.md`。

### ファイル

| ファイル | 中身 |
|---|---|
| `client/link.lua` | 最初に読まれる。共有の状態、ゲームのコンソールのコマンド、サーバー側への問い合わせ |
| `client/env.lua` | 撮影用の環境と、キャラクターを地面に下ろす処理 |
| `client/camera.lua` | 真下向きのカメラと、読み込みの待ち |
| `client/sample.lua` | `hmap`: 見えている面の高さの格子 |
| `client/scan.lua` | ブロックの採取 |
| `server/main.lua` | ワールドの掃除、`hello`、撮影の後に空腹と渇きを満たす |

**`client/link.lua`**

`hello`・`status`・`res`・`ping`。

**`client/env.lua`**

- `env on` / `env off`: 撮影用の環境。
  NPC なし、HUD なし、正午、快晴、雲なし、霧なし、露出の固定、乾いた地面、キャラクターを隠して固定。
- `safe`: キャラクターを、地面に下ろす。
  - 真下への光線が、地面の当たり判定に当たってから下ろす。
  - 立っていた高さが分かっているときは、そのすぐ下（2 m 以内）に、当たり判定か水面が来るまで、
    10 秒まで待つ。
    床や屋根の当たり判定は、その下の地面より遅れて来ることがあるため。
  - 来なければ、それより下で当たった所に下ろす。
  - どこにも当たらなければ、固定したまま `safe=0` を返す（`fxmapgen safe` でやり直す）。
  - ゲームの `HasCollisionLoadedAroundEntity` は、使わない。
    スクリプトが見る場所を外した後は、地面があっても false のままなので。

**`client/camera.lua`**

`tile` / `cam`。

- 真下向きのカメラ。
- 読み込み待ち。水だけのブロックでは、2.5 秒で打ち切る（5×5 点の 25 点すべてが水のとき）。
- 中心の真下の当たり判定の待ち。地面なら、光線が当たるまで。水の上は、待たない。
- 落ち着き待ち。ゲームの読み込み要求が 0 のまま `quietMs` 続き、かつ最低 10 フレーム。
  `quietMs` は、tile の最後の引数。既定 1500。
- `READY` / `FAIL` の行。
  READY に、`quiet=` と、落ち着き待ちの間の 1 秒あたりのフレーム数 `fps=`。
- ビーコンの通し番号。

**`client/scan.lua`**

`scan ground` / `scan roads` / `scan stop`。ブロックの採取。

- 地面: 2×2 の区画ごとに、場面と当たり判定を読み込ませてから、取る。
  取るのは、1 m ごとの光線 2 本（木の茂みを足すと 3 本）と、水面。
  読み込ませる順は、次のとおり。
  1. 真下への光線が、当たり判定に当たる。
  2. ゲームが、キャラクターのまわりの当たり判定を読み込んだと答える。3 秒まで。
  3. 読み込み要求が 0 のまま、0.3 秒。5 秒まで。

  建物は、地面より後に来ることがある。遠くから飛んだ直後は、読み込んだと答えた後にも来る。
- 道: 中心で読み込ませてから、1 m ごとの道路判定と、4 m ごとの通り名・地区を取る。
- 行は `MSCAN`（形式 v=1）。採取の番号 `seq` と、ブロックの名前を持つ。
- 1 行分の値は、900 文字までの部分に分けて出す。
  ゲームは、クライアントが出す 1 行を、1,023 文字で切るため。

**`server/main.lua`**

- カメラをブロックの上に置くたびに、ワールドを掃除する（`tile`: 撮影か高さの格子のとき）。
  権限 `command.fxmapgen` があり、ほかに誰もいないときだけ。採取だけのときは、掃除しない。
- `hello`。
- 撮影の後に、空腹と渇きを満たす。

### 撮影の間に止めるリソース

撮影の間にクライアントで止めるリソースは、サーバーのプリセットから決まる。
プリセットは、`data/presets/<id>.json`。Core に埋め込み、`ServerPresets` で読む。
プロジェクトは、一覧を自分のものに替えられる（`server.stopResources`）。

### ゲームなしのテスト

```
luac -p resource/fxmapgen-capture/fxmanifest.lua resource/fxmapgen-capture/client/*.lua resource/fxmapgen-capture/server/*.lua
lua tests/resource/run-tests.lua
```

`tests/resource/fakegame.lua` は、リソースのスクリプトを、素の Lua 5.4 で動かす。
呼ぶネイティブを、小さな模型に差し替える。模型は、次のもの。

- 16 ms のフレームで進む、仮想の時計。
- コルーチンのスレッド。
- 30 ms 遅れのネットイベント。
- ゲームと同じく、1,023 文字で切る、クライアントの行。
- 作り物の世界。建物のある陸、海、池、山、読み込みが落ち着かない区画。
  - 海の底は、陸から 500 m 以内で 40 m、1 km 以内で 300 m、その先は 600 m。
    底が斜めに深くなるブロックが 1 つ。
  - 陸には、コンクリートの建物、100 m ごとの舗装の道、その間の芝と木。通り名と地区もある。
- キャラクターが動いてから 20 フレームで尽きる、読み込み要求。途中でまた出る場面も仕込める。
- キャラクターが来て少しすると読み込まれる、当たり判定。350 m より遠くから来たときは、1.5 秒。
- 地面より後に来る、建物の当たり判定。テストが決めたときだけ。まわりを読み込んだと答えた後に来る形も。
- 真下への光線。
- 実物と同じく、スクリプトが見る場所を外すと false のままになる、`HasCollisionLoadedAroundEntity`。
- 落ちる所で固定を解いていないかの点検。

テストの実行:

- `run-tests.lua` は、コマンドと、すべての行の値と形を確認する。採取は、全点の値を、作り物の世界と比較する。
- `dotnet test` も、Lua 5.4 が PATH にある（か `FXMAPGEN_LUA` で指定した）ときは、これを実行する。
  書き出させた撮影と採取（`--emit <フォルダ>`）を、exe の撮影と採取の読み取りで読む。
- `fxmanifest.lua` の版は、`Directory.Build.props` の `<Version>` と同じにする（テストで確認する）。
- CI は、Ubuntu の Lua 5.4 で、構文の検査とテストを実行する。
- リリースは、exe と `SHA256SUMS.txt` だけを付ける（リソースは exe の中）。

## ゲーム: 接続・事前確認・撮影・採取

ゲームとは、ゲームのコンソールソケット（127.0.0.1:29200）と、FiveM のウィンドウだけでつながる。

- `src/FxMapGenerator.Core/Capture/`: Windows に依存しない部分。
- `src/FxMapGenerator.App/Game/`: この PC のゲーム。
- API は [api.ja.md](api.ja.md#ゲーム)。

### 接続

- `src/FxMapGenerator.App/FxConsole/` は、FxDeck 0.7.0 からコピーした接続。名前空間だけが違う。
- テストも、FxDeck のもの。
  エミュレータには、コマンドに、決めておいた行を返す口（`Responder`）を足した。
- ゲームは、同時に 1 つの接続しか受けない。
  そのため、exe の中でも、ゲームのコンソールへの接続は、同時に 1 つだけ開く（`LocalGame`）。
  事前確認と、実行の撮影・採取は、重ならない。

### 行のやり取り

`GameLink` が、コマンドを送り、応答の行を待つ。

- 待つ間は、3 秒何も送っていなければ、`fxmapgen ping` を送る。ゲームは、約 5 秒で切る。
- 会話は、記録に書く。高さの格子の行は、BEGIN と END だけ（行はファイルにある）。
- tile の応答は、次のものだけを取る。
  - 要求番号がそれより前の要求のものでなく、`block=` の合う READY。
  - FAIL。
- ERROR の行でも、待ちを終える。
- 撮り直しの前に、`status` で今の番号を確認する。
  そのため、待ちきれずに後から届いた前の READY は、取らない。
- 採取と高さの格子は、受け取ったときに確認する。
  値でない字、来なかった行、点の数の合わない行。
- 欠けて届いたものは、そのときの失敗にする。撮影・採取が、そのブロックのその項目を取り直す。

### ウィンドウ

`GameWindow` は、`FiveM_…GTAProcess` のウィンドウを扱う。

- 描画領域の大きさと、PrintWindow（描画領域・全内容）で取った RGBA。
- ほかのウィンドウの後ろにあっても取れ、フォーカスを奪わない。
- 画面の外に出したウィンドウは、合成されないので、黒くなる。

### 画像の確認

`FrameChecks` は、次のものを見る。

- ビーコン: 左上の 4×4 px。準備済みの緑と、要求番号の下 3 ビット。
- 通知の帯: 下中央の平らな緑。
- 海の上で目立つもの: 画面の中央値から 40 を超えて外れる画素を、16 px の区画でまとめて囲む。
  海そのものは、15 ほどしか外れない。

囲みごとに、地図に使う範囲（`MapArea`）にかかるかを持つ。
`MapArea` は、真ん中のブロックの正方形と、そのまわり 64 px。
画面の左右の端（FiveM 本体の透かし文字など）は、地図に写らない。

### 撮影・採取のステップ

`VisitStage`。ゲームを使うステップなので、1 つずつ実行する。

**準備**

- 接続。
- hello: プロトコル、版がこの exe と同じか、サーバー側の応答、権限、ほかのプレイヤー。
- ウィンドウの描画領域 1920×1080。
- 止めるリソース: プロジェクトの一覧。なければ、プリセットのもの。動いているものだけを `stop` する。
- `cl_drawPerf 0`。
- `fxmapgen env on`。

**落ち着き待ち**

`state/settle.json`（事前確認の測定、下）から取る。なければ、1.5 秒。
実行のログに出し、tile ごとに送る。

**ブロックごとの手順**

ブロックは、北の行から、行ごとに向きを変えて進む。足りない項目だけを、順に取る。

1. 撮影画像か高さの格子が必要なら、`fxmapgen tile` → READY。
2. 撮影画像: 300 ms 後にフレームを取る。
   ビーコンが準備済みで、要求番号が合うまで、最大 4 枚。
   通知の帯は、5 秒待ちを 3 回まで。
3. 高さの格子: `fxmapgen hmap 1`。
4. 採取が必要なら、続けて `fxmapgen scan ground` → `fxmapgen scan roads`。
   - 木の茂みを描く地図があれば、`canopy` を付ける。
     木の茂みだけが足りないときも、地面ごと取り直す。
   - 採取だけのブロックは、カメラも tile も使わない。
     リソースが、キャラクターを動かして読み込ませる。
5. ファイルを、それぞれ書き終えてから、置き換える。
   - `capture/<block>.png`
   - `.cam.txt`（READY の行）
   - `.hmap`
   - `scan/<block>.txt`（MSCAN の行）。
     片方の採取だけを取り直したときは、もう片方の行を、ファイルから残す。
6. 取った項目を、記録する。
   - 地面を取り直したのに、木の茂みを付けなかったときは、前の木の茂みの項目を消す。
   - 再取得の印のブロックは、古い項目を消して、印を外す。

失敗したら、env on をかけ直して、2 回まで取り直す。
撮影画像が不要なら、ウィンドウの大きさを確認せず、`cl_drawPerf` も送らない。

**高さの品質**

プロジェクトの `heightQuality`。コードは `SurfaceHeights`。

| 値 | 取るもの |
|---|---|
| `speed` | 高さの格子だけ |
| `balance` | 地面の採取だけ（当たった高さと水面の高い方） |
| `quality` | 両方 |

- `speed` は、衛星地図だけのとき。アトラスか道路地図があると、プロジェクトの誤り。
- 写真の位置合わせ（オルソ補正・縮尺の測定・撮影中の仮のタイル）は、`PhotoItems`。
  `quality` は、マスごとに高い方。
- 地表の地面と建物と、セルの陰影・等高線は、`LandcoverItems`。
  `quality` は、同じくマスごとに高い方。`balance` は、地面の採取。
- null は、地図の組み合わせの既定。衛星地図だけは `speed`、アトラスか道路地図を含むと `quality`。
- 衛星地図がなくても `quality`。
  高さの格子を地表に使い、カメラで先に読み込むので、採取が速くなる。時間は、採取だけのときとほぼ同じ。
- 撮影・採取が取る項目は、`Planner.NeedsItem`。
  衛星地図 = 撮影と `PhotoItems`。アトラス・道路地図 = 採取と `LandcoverItems`。

**見積もり**

- 採取は、2 つに分ける。
  - 撮影か高さの格子の直後の採取（`scanGround`・`scanRoads`）。
  - 採取だけのとき（`scanGroundAlone`・`scanRoadsAlone`）。カメラが先に読み込んでいない分、遅い。
- カメラで取るブロックには、1 回ずつ、カメラの移動（`cameraMove`）を足す。
  そのブロックの、最初のカメラの項目の行に足す。
- カメラで取るブロックを、隣り合う（まわりの 8 つ）まとまりに分ける。
  まとまりごとに 1 回、となりでないブロックへの移動（`farMove`）も足す。最初のカメラの項目の行に足す。
  採取だけの値は、散らばったブロックで測ったので、その分を含む。

**後片付け**

すぐ止めたときも、実行する。

- `fxmapgen env off`。リソースが、キャラクターを下ろす。
- 止めたリソースを、逆の順に `ensure` する。

**撮影用リソースの停止**

- 範囲のどのブロックも取り終えたときは、後片付けの最後に、撮影用リソースを止める。
  取り終えたとは、失敗なしで、止めていないこと（`Finish` の `StageEnd.Complete`）。
  - HELLO の `res` の名前で、`stop` する。
  - 続く `fxmapgen hello` が応答しないことを、確認する。
  - `Options.StopAtEnd`。確認する時間は、`StopCheck`。
- 途中で止めた・失敗があったときは、止めない。続きを、すぐ始められるようにするため。
- 権限がなくて止まらなくても、撮影の命令がなければ、何もしない。
- どちらでも、実行のお知らせ `gameDone` を出す（`JobSnapshot.announcements`、`StageContext.Announce`）。
  - `resource`。
  - `stopped`: `1` 止めた / `0` 止めた後も応答する / `kept` 止めない設定 /
    `unknown` ゲームのコンソールへの接続が切れた。
  - `restarted`: 起動し直したリソース。

**実行を止める場合と、記録**

- 次のどれかなら、実行を区切りで止め、理由をスナップショットの `stopReason` に出す。
  残りのブロックを、失敗にしない。
  - 拒否された（ほかのプレイヤー・権限）。
  - ウィンドウがなくなった・大きさが変わった。
  - 接続が戻らない。
- 実行のフォルダに、次のものを置く。
  - 会話の記録 `console.log`。高さの格子と採取の行の中身は、入れない。
  - 止めたリソースの一覧 `stopped-resources.txt`。

**仮のオルソ補正**

衛星地図を作るときは、撮影と並べて、仮のオルソ補正をする。
`ProvisionalOrtho`、撮影のステップの `Follower`。

- ブロックの撮影画像と、写真の位置合わせに使う高さ（`PhotoItems`）がそろうたびに、補助の処理で、
  次のことをする。
  - そのブロックの z8 のタイルと、その上の縮小タイルを書く。z7 の 4 枚、z6〜z0 の 1 枚ずつ。
  - オルソ補正の記録を付ける。`units.csv` では `ortho.provisional`。
- 縮尺の補正は、次の順で決める。
  1. 指定（`--scale`）。
  2. このプロジェクトの値（`state/scale.json`）。
  3. 同梱の既定値（`ScaleStore.Default`）。既定の範囲の全域から測った値。視野角 2°。
- 撮影の後のオルソ補正のステップは、今までどおり、縮尺を測る。
  - `tiles` の補正と、ブロックの端で 3 cm 未満しか違わなければ、そのタイルを残して、
    その補正をプロジェクトのものにする。
    3 cm は、z8 の 1 画素の 1/10（`ScaleStore.Agrees`）。
  - 違えば、全ブロックを作り直す。
- 範囲の外の海と、縮小タイルの全体は、その後の縮小タイルのステップが作り直す。
- 撮影のステップが終わると、補助の処理は、手元の 1 ブロックを終えて止まる。
  残りは、オルソ補正のステップが作る。

### 事前確認

`Precheck`。画面の「接続の確認」。

- 項目ごとに、合否、値、文（英語）と、画面が自分の言葉にするための `codes`（`PrecheckItem` の注記）を持つ。
- 確認の順は、次のとおり。
  1. 接続。
  2. hello。
  3. ウィンドウ。
  4. 止めるリソースの状態。
  5. テスト撮影。撮影・採取と同じ設定で、標準の枠の北西の角の海（`z8_0_0`）を撮る。
     - 目立つものを囲む。
       ✗ にするのは、地図に使う範囲にかかるものだけ。範囲の外のものは、`values.outside` に数えて示すだけ。
     - 通知の帯。
  6. 天候・時刻・近くの NPC（`status`）。
  7. 落ち着き待ちの測定（下）。
  8. ゲームを元に戻す。env off、止めたリソースを `ensure`。
- 結果は、作業フォルダの `logs/precheck-<時刻>/` に置く。
  `report.json`、`shot.png`、範囲の白線と囲みを描いた `shot-marked.png`、`console.log`、
  `settle-<block>-first.png` / `-last.png`。
- 前提条件の確認のゲームの行は、いちばん新しい結果から出す。

**撮影用リソースを止めた後**

- 撮影・採取が、範囲のブロックをすべて取り終えて、撮影用リソースを止めると、
  その時刻を残す（`ResourceStop`）。
  置き場は、作業フォルダの `state/capture-stopped.json`。
- それより前の事前確認は、確認していないものとして扱う。
  - `PrecheckReport.LatestFor` が、結果に `resourceStoppedUtc` を付ける。
  - 前提条件のゲームの行は、合否なしに戻る。
  - 画面は、結果を出さず、リソースの起動と接続の確認を、もう一度するよう案内する。
- 止めても応答が続くとき（権限がない）と、途中で止めた実行では、残さない。

**実行に撮影がないとき**

撮影がないとは、撮影の必要な地図がない、または範囲のどのブロックも撮影済み、ということ。

- ウィンドウ・テスト撮影・落ち着き待ちを、確認しない。合否なし、code `notNeeded`。
  結果は、それらを除いて判定する。画面は出さない。
- 天候・時刻・NPC も、確認しない。
  写真にしか出ないため。採取の光線は、地図の当たり判定だけに当たる。
- リソースの状態を読んだところで終える。何も止めず、env on もしない。

### リソースの起動

`ResourceStart`、画面の「リソースを起動」。

- HELLO に応答すれば、何もしない。
- 応答しなければ、`refresh` → 3 秒 → `ensure fxmapgen-capture` → 3 秒 → もう一度 HELLO。
- どれも、サーバーのコマンド。送れるのは、その権限のあるプレイヤーだけ。
- 起動のときのゲームのコンソールの行（送ったものと、返ってきたもの）を、そのまま返す。
  画面は、起動できなかったときに、理由の候補と一緒に出す。
  候補は、フォルダ名が違う、サーバーにない、権限がない。

### ゲームを使うのは 1 つずつ

`JobManager.UseGame`。

- ゲームのコンソールへの接続は 1 つ。
  そのため、実行のゲームでの作業（撮影・採取）、事前確認、リソースの起動は、重ならない。
- 事前確認とリソースの起動は、始めるときにゲームを取り、終わると放す。
- 取れないときは、409。
  - 実行にゲームでの作業が残っていれば、`GAME_BUSY`。
  - 事前確認の間は、`GAME_CHECKING`。
  - リソースの起動の間は、`GAME_STARTING`。
- その間は、ゲームでの作業のある実行も、始まらない（`POST /api/jobs` が同じ 409）。
  ゲームでの作業のない実行は、始まる。
- 何がゲームを手で使っているかは、SSE の `gameUse` で出す。
  `{ "kind": "precheck" | "resourceStart" | null }`。
- 画面はその間、「実行」「接続の確認を実行」「リソースを起動」を、理由つきで押せなくする。

### 「サーバーにある」の印

`ResourcePlacement`。作業フォルダの `state/capture-resource.json`。

- exe は、サーバーのフォルダを見られない。
  そのため、撮影用リソースがサーバーにあることを、印で持つ。
- 印が付くのは、次のとき。
  - 画面でリソースを書き出したとき（`saved`）。
  - リソースの起動・事前確認・撮影・採取の始めに、リソースが exe と同じ版で応答したとき（`answered`）。
  - 利用者がチェックを付けたとき（`user`）。
- 印の版が exe の版と違えば、ないのと同じ。
- 前提条件 `capture`（撮影・採取が残っているとき）は、この印を見る。

### 落ち着き待ちの測定

`SettleProbe`。事前確認の中で実行する。

この PC のゲームが、読み込み要求が 0 になった後も、絵を変え続ける時間を測る。
遠景の差し替え、テクスチャが細かくなる、など。

1. 場所は、事前確認の前にプレイヤーがいた場所から、遠い方の市街地。
   北はパレト・ベイ、南はロスサントスの中心部。まだ読み込んでいない場所。
2. 候補のブロック（建物が多く、水がなく、隣り合う）を、`quietMs` 0 で撮る。
3. READY から、0.2 秒ごとに 3 秒間、フレームを取る。
4. 地図に使う範囲で、各フレームを、最後のフレームと比較する。
   24 段階を超えて違う画素が 0.05 % 未満のフレームが、最後まで続く最初の時刻を、そのブロックの時間とする。
   会話の記録には、8 段階・48 段階の割合も出す。
5. 最後まで変わり続けた、水がある、READY が来ないブロックは、次の候補に譲る。
6. 2 ブロック測れたら、長い方の 1.5 倍（10 ms 単位で切り上げ）を、`state/settle.json` に置く。
7. 測れなければ、そのファイルを消す。撮影・採取は、既定の 1.5 秒で待つ。

### 描画設定

- `RenderSettings`: 撮影に必要な値の表と、差分、値だけの書き換え。
  - 値は、テクスチャなどの品質、拡張距離スケーリング、飛行中の高精細ストリーミング、ウィンドウ 1920×1080、
    VSync オン など。
  - VSync オンなら、画面のリフレッシュに合わせて描き、GPU に余裕が残る。
    そのため、ほかのプログラムが GPU を使っても、描く速さが変わらず、測った落ち着き待ちが、
    撮影中も保たれる。
  - 書き換えは、値だけ。ほかの行・並び・改行は、そのまま。
- `RenderSettingsFile`: `%APPDATA%\CitizenFX\gta5_settings.xml` を扱う。
  - 書き換える前に、`%LOCALAPPDATA%\FxMapGenerator\render-backups\` に、控えを保存する。
  - 戻すときは、控えを書き戻す。
  - FiveM が動いている間は、どちらもしない。FiveM は、閉じるときに自分の値を書き戻すため。

### テスト

`tests/FxMapGenerator.Core.Tests/Capture/FakeGame.cs` は、偽物のゲーム。
コマンドに、リソースと同じ形の行を返す。ウィンドウには、作り物の世界とビーコンを描く。

- ブロックごとに、不具合を仕込める。
  黒い画面、前のブロックの画面、通知、ウィンドウの大きさ、応答なし、遅れて届く READY、落ち着かない、拒否、
  HMAP ABORT、ゲームが長い行を切るように途中で切れた採取の行。
- 落ち着き待ちのために、次のことを仕込める。
  測定は、粗い時間を見つけ、数画素は無視しなければならない。
  - READY を、要求の `quietMs` だけ遅らせる。
  - 読み込みが終わってから、しばらく粗い絵を出す。
  - ブロックの絵を変え続ける。
  - 毎フレーム、数画素だけ変える。
- 偽物のゲームで、撮影・採取 → オルソ補正をジョブで実行すると、
  同じ画面を撮影ファイルとして直接書いた場合と、バイト単位で同じタイルになる。
- 撮影と並べた仮のオルソ補正も、オルソ補正のステップが同じ補正で作るものと、同じタイルになる。
- テストは、この PC のゲームを使わない。
  テスト用のホストのゲームは、動いていないゲーム。CLI の `build` のテストは `--no-game`。
- ウィンドウの取り込みのテストは、画面の左上に、小さなウィンドウを一瞬出す。

### 撮影の再生

偽物のゲームは、前に撮った撮影を再生できる（`Replay` = 撮影のフォルダ）。
そのブロックの画面、READY の行、高さの格子を返す。

`tests/FxMapGenerator.App.Tests/Demo/ReplayDemo.cs` は、それをゲームにして、exe を画面つきで動かす。

## 画面と、開いているプロジェクト

exe が開いているプロジェクトは 1 つで、どのタブにも同じものが出る（`ProjectSession`）。
変わるたびに、SSE の `project` で、全部のタブに送る。最近の一覧は、`settings`。
API は [api.ja.md](api.ja.md)。

プロジェクトを開くと、見出しのタブで、6 つの画面を切り替える。
プロジェクト設定、計画・進捗、FiveM 設定・接続検証、地図の編集、地図表示、書き出し。
開いたときは、計画・進捗。
前提条件に ✗ のある画面は、タブの名前の横に、数を出す。

画面の文言は、項目は文語（体言止め）、解説はです・ます。
内部の言葉（コードのステップの名前など）や、アプリの版のことは、出さない。

### はじめの画面

`src/start/`。

- 新規プロジェクト: 名前、プロジェクトファイル、作業フォルダ、サーバーのプリセット、出力する地図。
  出力する地図は、衛星地図・アトラス・道路地図。
  道路の編集は、同梱の編集のコピーから始める。
- 開く: Windows のファイル選択ダイアログを、exe が出す。
- 最近使用したプロジェクト。

### アプリの設定

`src/shared/AppSettingsDialog.tsx`。

- 上の帯の「⚙ アプリの設定」で開く窓。はじめの画面と、プロジェクトの画面にある。
- 表示言語・テーマ・GTA V と暗号鍵のフォルダを、保存でまとめて書く。
  フォルダは、入れたそばから、見つかるものを出す（上の「ゲームファイル」）。

### 計画・進捗の画面

`src/project/`。

**左の欄**

- 出力する地図: 衛星地図、アトラス、道路地図。
  アトラスは、スタイルの一覧。プロジェクトの地図の言語のそれぞれで作る。
- 「高さの品質」: 出力する地図の下にある。速度重視・バランス・品質重視のラジオボタン。
  地図の組み合わせに合わないものは、灰色にして、理由を出す。
  見出しの解説に、全域の目安の時間と、後から地図を加えるときの時間の表。
- ミニマップ。
- 並列数: 論理コア数までのスライダー。

**中の地図**

- Leaflet。ゲームの m を座標にした CRS。
- 下地は、PostalMap か、このプロジェクトの衛星タイル。
- ブロックの格子を、色分けする。取得状況で、または実行の後は、実行状況で。
- 範囲の道具: 矩形や個別に、範囲へ追加・除外。既定範囲に戻す。
- ドロップダウン「プリセットから追加」: プロジェクトが通常範囲外の地図を含めるときに出す。
  カヨ・ペリコ、Roxwood。ブロックがすべて範囲にあるものは、選べない。
  選ぶと、窓で次のものを出す。追加の後は、地図を、そのブロックの所へ動かす。
  - 追加するブロックの数（陸・水域）。
  - プリセットに必要なときは、枠を広げること（辺とセル数）。上限を超えるときは広げず、理由だけ。
  - プロジェクトが読んでいなければ、カヨ・ペリコの道のチェックボックス。
- 再取得の道具（その下の行）: 範囲のブロックを、矩形や個別に、再取得の対象にする。
  個別は、もう一度押すと外れる。すべて外す道具もある。

**実行状況の欄**

地図の下にある。

- いつも出る 1 行: 実行対象の目安。
  または、実行中のステップ・進捗・残り時間・エラー・CPU・メモリ・並列数・実行と停止のボタン。
- その下に、開け閉めできる欄: 処理中の単位（1 つ 1 行）、エラーと理由、ログ。

**右の欄**

- ジョブ一覧。
  - 行は、内訳に開ける。
  - 行を押すと、その行のブロックやセルを、地図で囲む。
  - 残りは、件数と内訳（陸・水域）の 2 行。
  - ゲーム内・手作業は、ステップ名の横の札。
- 満たしていない前提条件。✗ の行だけ。
  それぞれ、直す所へのリンク。プロジェクト設定・FiveM 設定・接続検証・アプリの設定。
  なければ、「前提条件はすべて満たしています」。
- 右の欄の幅は、境目をドラッグして変え、アプリの設定に残す。ダブルクリックで、既定の 440 px。

**そのほか**

- 今の実行が読んでいる入力は、理由を出して、変えられなくする。
- 解説の文は、`|` で始まる行を、表として出す（`HelpLayer`）。

### ジョブ一覧の実行中の表示

実行を追っている間は、5 秒ごとに、表（`plan`）も読み直す。

ステップの行:

| 状態 | 表示 |
|---|---|
| 待っている間 | 今の表の残りと、実行の見込み時間。残りが 0 なら「待機」 |
| 準備中 | 「準備中」 |
| 実行中 | バーと、「済 / 全部」と、エラー数。全域で 1 件のステップは「実行中」 |
| そのあと | 完了・停止・エラー |

- 撮影・採取の内訳（ステップではない）は、次のように出す。
  - バー: 実行を始めたときの行ごとの残り（`plan` の `atStart`）から、今の残りを引いた数。
  - 時間: 撮影・採取の残り時間（実測）を、内訳の見積もりの比で分ける。
- 親の行は、子の合計。単位がそろえば単位の数、違えばステップの数。
- 合計は、実行の残り時間（実行状況と同じ値）。
- 手作業の 2 行（FiveM を起動する前の準備、接続の確認）は、前提条件から状態を出す。

### 実行中の地図

- ブロックのステップ（撮影・採取、オルソ補正、地表）は、ブロックを色分けする。
- セルのステップ（前処理・セル描画）とミニマップの間は、セル・シートの枠を色分けする。
  処理中の枠の中に、段階の名前。ブロックは、薄い線だけにする。
  実行の後は、最後のセル・シートのステップの枠。
- 描いている地図（アトラス・道路地図）は、描き終わったセルから、セルの範囲だけのタイルの層を足す。
  セル描画は z8〜z5 を書くので、それより下のズームでは、z5 を縮小して出す。
- その地図の縮小タイルが始まると、地図全体の層にする。
- 処理中の単位の一覧から、セル・シートへも移れる。

### 撮影中の表示

- 実行状況の表示で、衛星地図を作るプロジェクトでは、衛星地図のタイルを、下地の上に重ねる。
  撮ったブロックから順に、写真が出る。完了のブロックは、枠だけ。
- ジョブ一覧に衛星地図の作業（オルソ補正か縮小タイル）が残っている間は、札を出す。
  衛星地図を出している地図の左下に、「衛星地図: 仮表示（縮尺の確認前）」。地図表示の画面も同じ。
- 実行中は、5 秒ごとに、タイルとブロックの状態を読み直す。

### 地図のタイル

- URL に、プロジェクトのキーと、読み直すたびに増える番号を付ける（`?p=<鍵>&v=<番号>`）。
  プロジェクトのキーは、作業フォルダから作る短い値。
- プロジェクトを替えると、層を作り直す。
- 読み直すときは、新しい層のタイルがそろってから、古い層を外す（ちらつかない）。
- exe は、タイルを `Cache-Control: no-cache` と ETag で返す（変わっていなければ 304）。
  ないタイルは、`no-store` で返す。
  同じ URL が、開いているプロジェクトのタイルを返し、実行中はタイルが書き換わるため。

### PostalMap のタイル

PostalMap のタイル（postal-code-map-tile）は、地図の枠は同じだが、縮尺が違う。

- その z6 の 1 枚は 375 m（地図全体で 24×36 枚）。こちらは 281.25 m。
- そのため、地図の上では、その 1 枚が、256 px の 4/3 の大きさになる。
  lb-phone の設定では、その `resolution` が 6144×9216 なので、合う。
- この大きさの絵は、整数の画素に乗らない。そのまま並べると、ブラウザが継ぎ目に線を残す。
- そのため、層のタイルは、こちらの升目（256 px の canvas）にする。
  1 枚ごとに、その下に来るタイル（最大 2×2 枚）を、
  整数の画素にそろえて描く（`mapFrame.ts` の `postalLayer`）。

### 地図の編集

`src/edit/`。道路・POI・スタイルを切り替える。

**POI**（`src/edit/poi/`）

- 左: フォルダの木か、POI スタイルの一覧。
  - フォルダの木に出すもの: まとまり（画面の「グループ」）、POI、件数、表示・ロック。
  - 操作: ドラッグで並べ替えと移動、検索、フォルダとグループの追加・名前の変更・削除、
    CSV / JSON の読み込み。
- 中: 地図。POI を、地図と同じ見た目で、ブラウザが描く（`poiLayer.ts`）。
  道具は、配置・移動・選択・範囲選択（キーの 1〜4）。範囲選択は、道路と共通の `areaSelect`。
- 右: 保存・道具・表示と、選んだものの値か、POI スタイルの値。
  - 選んだものの値: 引き継いだ値は「{名前} から」。「引き継ぎに戻す」。
  - POI スタイルの値: 描き方、アイコンの選択の窓、PNG、色・大きさ・縁取り・丸・横のラベルとその大きさ、
    アプリが描いた見本（z6・z8）。

**道路**

- 道具: 描画・移動・選択・範囲選択（Ctrl でなぞり）・道ごと選択（キーの 1〜5）。
- 操作: 削除（追加したもの）・非表示（ゲームのもの）・表示に戻す、元に戻す・やり直し、保存。
- 選んだものの値: 通り名、印、高さ。向きごとの車線数、狭い道、幅。
  通り名の、自分の名前の追加・変更は、小さな窓で。
- ゲームの道のデータの値のすべて。
- 「同梱の編集を取り込む…」: まとまりごとのチェックボックスの窓。
- 編集の一覧: 同梱の編集のまとまりか、つながったものを 1 行にする。移動、選択、取り消し。
- 適用できない編集と、その理由。
- 左の地図の凡例に、種類ごとのチェックボックス（出すもの）。
- 左右の地図は、一緒に動く。右の地図の角に、全域の地図と視野の枠（上の「道の編集」）。
- 保存していない編集があるときは、次の前に確認する。
  タブを離れる・プロジェクトを閉じる・ブラウザのタブを閉じる。

**スタイル**（`src/edit/styles/`）

上の帯:

- スタイルの選択。同梱のスタイル・このプロジェクトのスタイルの見出し付き。
- スタイルの操作。
  - 複製…: 窓で、元にするスタイル（同梱・このプロジェクト・共通）、名前、ファイル名を決める。
  - 名前の変更…
  - 削除: 使っている地図があれば、押せない。
  - 書き出し…: ファイルを保存する。
  - 読み込み…: ファイルを選ぶ。ファイル名がふさがっていれば、別のファイル名を聞く窓。
  - 共通のスタイルに保存。
- その下の行: 同梱のスタイルは変えられないこと。または、元のスタイルとファイル、使っている地図。

左の、項目の一覧:

- 検索、グループごとに開け閉め、小見出し。
- 行ごとに、名前・値・元から変えた印「変更あり」・作り直すものの札（前処理・地域色・ラベル）。
  名前の解説は、項目の表の説明。
- 一覧の幅は、境目で変える。

右の、プレビュー（下の「スタイルエディタのプレビュー」）:

- 上の帯。
  - 左の地図の値: 保存した値・元のスタイル。同梱のスタイルは、保存した値だけ。
  - ラベルの言語: 日本語の地図を作るプロジェクトだけ。
  - 窓の大きさ: 4 段階のスライダー。500 m・1 km・2 km・4 km 四方。動かすと、窓が収まるズームにする。
- その下に、2 枚の地図。左 = 保存した値か元のスタイル、右 = 編集中の値。
  - z8 のタイルを Leaflet に渡し、引いたときは、ブラウザが縮める。
  - 移動とズームは、一緒に動く。
  - ズームは、z2〜z9 の整数の段。段の間では、ブラウザがタイルの間に筋を残すため。
  - ズームを変えても、描き直さない。
  - 地図ごとに、描くのにかかった秒数。
- 地図の角に、土地の全体。押した所を中心に、窓の大きさ。黄色の枠。
- 描くもの: 「見本図」か「このプロジェクト」。
  「このプロジェクト」は、プロジェクトの地図のデータ。
  プレビューが読むもの（ブロックの採取と地表、道の形、地区）ができてから。できていれば、初めはこちら。
- プロジェクトのときは、次のものも出す。
  - 場所の一覧: 推奨の 6 か所と、このプロジェクトで足した場所（`previewPlaces`）。データのない場所は、
    選べない。
  - 「場所を追加」: 窓の中心に、名前を付けて残す。名前の初めの値は、その地区の名前。
  - 「場所を削除」: 足した場所。
  - 「下の地図」: なし・PostalMap・衛星地図（タイルがあるとき）。同じ場所を、2 枚の下に。一緒に動く。
  - 全体の小さな地図は、PostalMap に、データのないブロックを灰色で重ねる（押しても選べない）。
- 値を変えると、右を、250 ms 待ってから描き直す。新しいタイルがそろってから、古いものと替える。
- 地図を押すと、その点の色の出どころの枠を出す。
  - 上に重なっているものから順に、描いたもの・その色・画素のどれだけを覆うか。
  - 地面の画像が混ぜた、材質や地域の割合と、重なる色の重み。
  - その点の地区と、地面の種類。
  - 項目の名前を押すと、一覧のその行（表は、その行とセル）を開いて、見える所に出し、しばらく印を付ける。
  - 値や窓を変えると、調べ直す。Esc で閉じる。
- 見本の土地がまだなければ作り、その間は、進み具合を出す。できなければ、理由と「もう一度」。
- 場所・窓の大きさ・左の地図の値・言語・視野は、アプリを開いている間は残る。

値の部品:

- 色: 色の枠を押すと、ピッカー。変更は、すぐに値になる。
  - 彩度と明るさの面、色相のバー、#・R・G・B。
  - スポイト（EyeDropper のあるブラウザ）。
  - このスタイルで使っている色。
  - このブラウザで最近使った色（`localStorage`）。
- 数値: スライダー・欄・単位。刻みに合わせる。
  単位が `percent` の値は、0〜100 % で見せ、0〜1 で持つ。
- 選択: 3 つまではボタン、それより多ければ一覧。
- チェック、複数のチェック。
- フォント: この PC のフォントの一覧と、その行の言語の見本の文字。
  日本語のフォントの行は、日本語の地図を作るプロジェクトだけ。
  この PC にないフォントは、そう書いて残す。
- 文字: 空欄は、その値を消す。

表 4 つは、行の下に出す。

- 地区ごとの割り当て: 地区の名前は、プロジェクトのゲームファイルから。なければ、コード。
  地区の検索。地域・建物の色は、一覧で、空欄 = 全体の決まり。番地の大きさは、空欄 = 既定。
- 水深の帯: 深さ・砂の底・岩の底の色・不透明度。
  帯を 2 つに分ける・次の帯とまとめる。深さは、前後の帯の間だけ。
- 光: 方位・重み、足す・消す（1 つは残す）、向きと重みの小さな図。
- 略語: 略語は、欄を離れたときに入る。空欄・同じ略語は、入らない。書き戻す語、足す・消す。

変更と保存:

- 元と違う欄は、色を付ける。行ごとに、「元の値に戻す」。
- 上の帯に、元に戻す・やり直し（Ctrl+Z・Ctrl+Y）。
  同じ値を 1 秒の内に続けて変えたものは、1 回にまとめる。
- 上の帯に、保存と、保存していない変更の印と、「保存すると作り直すもの」の 1 行。
  直した行の印を合わせたもの。スタイルを使う地図がなければ、作り直すものはないと書く。
- 同梱のスタイルは、部品を押せない（理由を出す）。
- 保存していない変更があるときは、次の前に確認する。
  ほかのスタイルを選ぶ・タブを離れる・プロジェクトを閉じる・ブラウザのタブを閉じる。
  その間、スタイルの操作（複製・名前の変更・削除・書き出し・読み込み・共通のスタイルに保存）は、押せない。

### 地図表示

`src/view/`。

- 下地と重ねる地図（タイルのある地図、PostalMap、なし）と、不透明度。

- 主要な場所への移動。

**変更前との比較**

- 対象は、前回の書き出しの後に書き換えたタイルのある地図（`GET /api/project/before`）。
  地図ごとに、残したタイルの数、z8 のタイル、そのまとまり（大きい順）。
- オンにすると、今の地図を下地に、変更前の地図を重ねる（`/api/project/before-tiles/…`）。

- 変更前・変更後のボタン（キーボードの X で入れ替え）と、変更前の濃さ。
- 変わった z8 のタイルの、赤い枠。
  変更前との違いが見えないものは、灰色（`BeforeTiles.Faint`）。
  見えないとは、どの画素も、256 段で 2 段以下の違い。
- まとまりへの移動。
  見えない違いだけのまとまりは、最後の開け閉めできる欄「見た目に差のない変更箇所」に。
- 比較の間は、下地と重ねる地図は、変えられない。

## 画面のガイド

画面ごとに、短いガイド（driver.js）がある。
画面の主な所を順に明るくし、吹き出しで説明する。

- 吹き出しの中身は、題、本文、「戻る」「次へ」「完了」、{n} / {m}。
- → ← Esc も効く。暗い所を押すと、閉じる。
- 吹き出しは、アプリの色（明るい・暗い）。

### 表示するかを聞く

- この PC で、ガイドのある画面を初めて開くと、右下の小さな枠で、表示するかを聞く。
  「表示する」「あとで」「今後表示しない」。
- 聞くのは、ガイドに必要なものが画面にあり、窓が開いていない状態が、0.8 秒続いてから。
  必要なものは、最初の手順の所と、ガイドごとの条件。
  - 計画・進捗: ジョブ一覧。
  - FiveM 設定・接続検証: サーバー用リソースの欄。
  - スタイルエディタ: プレビューの 2 枚の地図の絵。
- 選んだものは、`settings.json` の `guides` に残す。
  ガイドの id → `seen`（最後まで見た、または途中で閉じた）か、`never`。
- 「あとで」と、選ばずに画面を移ったときは、残さない。ページを開き直すと、また聞く。
- 上の帯の「？ ガイド」（はじめの画面とプロジェクト画面）で、今の画面のガイドを、いつでも表示できる。

### ガイドの間の操作

- ガイドは、説明だけ。光らせた所も、ほかも、押せない（`disableActiveInteraction` と driver.js の CSS）。
- ページに driver.js の `driver-active` の印がある間は、画面のキーと、マウスオーバーの解説も止まる。
  画面のキーは、地図の編集の道具のキー、Delete、Esc、Ctrl+Z・Ctrl+Y、地図表示の X。
- ガイドの間に動いてはいけない画面のキーの処理は、`.modal-backdrop` と同じく、`.driver-active` を見る。

### ガイドの書き方

- ガイドは、`src/FxMapGenerator.Web/src/guide/guides.ts` に書く。
  id は、画面。`start`、プロジェクトのタブ、地図の編集の `roads`・`poi`・`styles`。
- 手順ごとに、所と、吹き出しの向き（任意）を持つ。
  所は、解説のキー `[data-help="…"]`。
  または、`AREA` = `data-guide="<手順の名前>"` の要素（欄・地図・項目のまとまり）。
- 文は、辞書の `guide.<手順の名前>.title`・`.text`。
- 所が画面にない手順は、始める前に外す（進み具合の数が合う）。途中で消えた手順は、飛ばす。
- 聞く所と表示する所は `GuideLayer.tsx`、吹き出しの見た目は `guide.css`。
- `scripts/check-ui.mjs` は、ガイドも確認する。
  - 手順の解説のキーが、画面で使われている（表の中は数えない）。
  - `AREA` の手順ごとに、`data-guide` の要素が 1 つだけ。
  - 同じ手順が 2 つない。
  - 手順のないガイドの文がない。
- 手順を足すときは、所の解説のキー（または要素に `data-guide` の印）と一緒に、表に書く。
  題と本文を、両方の辞書に書く。

## スタイルエディタ

- スタイルは、同梱の 3 つ（`MapStyle.Builtin`）と、プロジェクトの自分のスタイル。
  自分のスタイルは、`style-format.ja.md` の「自分のスタイル」。
- 自分のスタイルは、同梱のアトラスのスタイルに、変えた値を重ねたもの（`StyleChanges`）。
  `StyleChanges` は、重ね方、2 つのスタイルの差、場所の値の読み書き。
- 共通のスタイルは、アプリの設定のフォルダの `styles\` に、自分のスタイルと同じ形で置く。
  既定は `%LOCALAPPDATA%\FxMapGenerator\styles\`。「複製…」の元に選べる。

| すること | コード |
|---|---|
| ファイルの読み書きと確認 | `UserStyleFile` |
| フォルダの一覧と置き場 | `ProjectStyles` |
| 画面の操作 | `ProjectSession.Styles.cs` |
| API | `StyleEndpoints` |

- 画面の操作は、プロジェクトファイルを読み直してから変える。道の編集と同じ。
- 画面が値を並べる表は、`data/style-schema.json`（`StyleSchema`）。
  形は、`style-format.ja.md` の「項目の表」。
- 行を足すときは、`StyleSchemaTests` が、スタイルの値と作り直しの判定に合うかを確認する。
- 画面の解説は、項目の表の説明を、そのまま出す（部品の `help` に `{ text }`、`data-help-text`）。

## スタイルエディタの見本の土地

スタイルエディタのプレビューは、架空の海辺の土地（見本の土地）で、変更を見せる。

- 土地は、開発用のツールで作り、データとして同梱する（`data/sample-island/`）。
- アプリは、それを 1 つのプロジェクトにするだけ（`SampleIsland.Create`）。
  セルの 64 ブロックの採取、`game/paths.json` と `names.json`、番地と POI、状態。
- ゲームなしのステップが、ほかのプロジェクトと同じ手順で描く。
- ゲームのものは、入っていない。
  地区のコードはゲームのものなので、スタイルの地区の表が、そのまま効く。名前は、すべて架空。

### 土地の作り方

コードは `tools/FxMapGenerator.DevTools/Island/`。同じ乱数の種なら、同じ結果になる。

- `Sketch.cs`: 大まかな配置。大きな形だけに使う。
  海岸、山の線と山頂、川と湖、町、高速とその分岐、鉄道、幹線。
- `Layout.cs`:
  - 配置の形を、セルの上の場にしたもの。
    海岸からの距離（海岸はノイズで揺らす）、山への深さ、町か岬か、川からの距離。
  - 蛇行する川の中心線（sine-generated curve、Langbein と Leopold 1966）と、そこから決める隆起。
- `Terrain.cs`・`SampleLand.cs`:
  - 隆起と川の侵食。stream power 則を、Braun & Willett 2013 の方法で、12 m の格子。
  - 2 m の細かな起伏と崩れ（熱侵食）。
  - 海底は、海岸からの距離をノイズで伸び縮みさせて、深くする。
  - 湖は、地面が沈んだ所。川は、配置の中心線に沿って掘る。
  - 地面の種類は、高さ・傾き・水気・海からの距離から。
- `Roads.cs`:
  - 道ごとに、地形の上の最短経路を、なめらかにする。
    最短経路は、坂・水・配置からの離れ具合に費用をかけた A*。
  - 高さは、動的計画法。盛土・切土、地面や水より高い所は高架・橋、深い所はトンネル。
  - Y 字のジャンクション、ダイヤモンド型のインターチェンジ。
  - 道の下の地面を均す。
- `Town.cs`:
  - 向きの場（海岸・幹線・高速の向き、Chen ほか 2008）に沿って、通りを引く。
  - その両側に、地区ごとの区画（高い建物、中層、庭とプールのある家）、公園、駐車場。
  - 平らな低地に、畑。番地は、建物の上。

### 同梱のデータの作り直し

ツールを変えたら、同梱のデータを作り直し、そこから作ったプロジェクトを確認する。

```
dotnet run --project tools/FxMapGenerator.DevTools -c Release -- sample-land-bundle data/sample-island c
dotnet run --project tools/FxMapGenerator.DevTools -c Release -- sample-island <空のフォルダ>
FxMapGenerator build <空のフォルダ>/sample-island.fxmapgen.json --no-game --workers 2
```

- `sample-land <フォルダ> <a|b|c>` は、同梱のデータを通さずに、ツールから直接プロジェクトを作る。
  `--no-roads` で、土地だけ。
- `a`・`b`・`c` は、乱数の種。同梱は `c`。

## スタイルエディタのプレビュー

プレビューは、見本の土地か、開いているプロジェクトの地図のデータの窓を、
ファイルを書かずに描く（`StylePreview`）。

- 窓の大きさは、500 m・1 km・2 km・4 km 四方（`StylePreview.Sizes`）。
- 描き方は、セルの描画と同じ（`CellPainter`、z8 の縮尺）。
- 窓は、四角が触れる z8 のタイル（地図のタイルと同じ番号）で、範囲のブロックがあるタイルだけを描く。
- ブロックごとに、窓の中のタイルを 1 枚にして、
  並列数のスレッドで描く（`CellPainter.DrawArea` は同時に呼べる）。
  256 px に切って、PNG（速い圧縮）にして、メモリに持つ。
- ブラウザには、z8 のタイルだけを渡す。引いたときは、ブラウザが縮める。
  確認しやすさを優先し、書き出す地図の縮小タイルの絵には、合わせない。

### 見本の土地

App の `SampleLand`。

- アプリの設定のフォルダの `sample-island\` に、プレビューを初めて開いたときに作る。
- 同梱のデータからプロジェクトにし（`SampleIsland.Create`）、ゲームなしのステップを、
  セルの前処理まで実行する。
  セルの描画・縮小タイル・ミニマップはしない。42 MB ほど。
- 並列は、開いているプロジェクトの並列。なければ、CPU の半分。
- できたら、`sample.json` に、アプリの版と、同梱のデータの SHA-256 を書く。
  どちらかが違えば、次に開いたときに作り直す。

### プロジェクトの地図のデータ

App の `ProjectSession.Preview`。開いているプロジェクトの `StylePreview`。

- プロジェクトファイルか、作業フォルダの `state/stages.json` が変わったら、作り直す。
- 描くのは、採取と地表のある、範囲のブロックだけ（`StylePreview.ReadyBlocks`）。
- 道の形と地区ができるまでは、待つ（`StylePreview.Waiting`）。
- 推奨の場所は、`StylePreview.Recommended`。
- 残す窓のデータは、合わせて 300 ブロックまで。
  古いものから、それ用に作った値と描く道具と一緒に消す。
  町の 4 km の窓は、250 ブロックほどで 5〜7 GB になるため。

### 並列

- 描くたび（と点を調べるたび）に、開いているプロジェクトの並列数（`parallel`）を使う（`FixedParallel`）。
  ジョブと違い、メモリの見張りはない。
- 1 スレッドで動くのは、ラベルを置く計算と、ブロックの描画の中身。

### 作って残すもの

- 窓のデータ: 窓から 160 m の内にある範囲のブロックを、セルの前処理と同じく、格子と高さにする。
  160 m は、地面の画像と陰影のぼかしの分。
  - ブロックの読み込みは、並列（`CellGrids.Build`、`CellPrepStage.ShadeHeights`）。
  - スタイルには、関係しない。
  - ブロックの組ごとに、4 つまで残す。窓を広げても、同じブロックなら作り直さない。
- スタイルの値の組ごとに、作って残すもの。種類ごとに、4 つまで。
  - 地面の画像: `CellPrepStage.GroundValues` の組ごと。
  - 陰影: `CellPrepStage.ShadeValues` の組ごと。強さは、描画で使う。
  - 層: `CellLayers.Sets` の組ごと。
  - 地域の色: `regions` の節ごと。
    場所のまわりの、ぼかしの 3 倍の分だけを、`RegionField.Land4`・`ZonesOnFrame` の窓で計算する。
  - ラベル: 置き方の key と、言語ごと。
    プロジェクトにそのラベルのファイルがあれば、それ。なければ、ラベルのステップと同じく、土地の全体に置く。
- 色や線の幅を変えたときは、描き直すだけ。
- 描く道具（`CellPainter`、パスと塗り）も、値の組ごとに、2 つまで残す。
  同じ値で描いた窓の点を、すぐに調べられる。
- 画面の左右それぞれで、新しいリクエストが、描いている途中の古いリクエストを止める（`SUPERSEDED`）。

### 点の色の出どころ

`StylePreview.Pick`。

- `CellPainter` の描く順の各部に、何を塗るかを付けておく（`StepTag`）。
  - 各部: 背景、地面の画像、地面の層、陰影、木の茂み・水・海の帯・建物・等高線・鉄道、
    道路（`RoadDrawing` の各部）、ラベルと POI。
  - `StepTag`: 種類・色・道の格・塗り・帯と底・文字。
- その点の画素だけの面に、各部を 1 つずつ描いて、塗ったもの（と覆う割合）を拾う（`CellPainter.Pick`）。
  陰影は、掛ける倍率。
- 上から、画素をすべて覆うものまでを返す。
- 建物は、その点の地区で、色の決まりを添える。地区の表・地域・決まりのないもの。
- 地面の画像は、その点で混ぜたものを添える（`GroundRaster.Explain`）。
  - 材質の塗りのとき: なじませる範囲の材質の、ガウスの重みの割合。
  - 地域の色のとき: まわりの陸の地域の割合と、濃淡と木の暗さの重み。
    地域の割合は、ぼかしの重み。陸が遠ければ、沖の地域。
- 画面は、各部から、項目の表の行（表なら行と列）を決め、押すとその行を出す。

### 描き直しの時間の測定

種類ごとの描き直しの時間は、次のコマンドで測る。

```
dotnet run --project tools/FxMapGenerator.DevTools -c Release -- preview-timings <プロジェクトファイル> <x> <y> <出力のフォルダ> [並列]
```

- 500 m の窓で測るもの: 初めての描画、同じ値、色、地面の値、陰影の値、層、ラベル、言語、地域の色、別の場所。
- 続けて、1 km・2 km・4 km の窓と、4 km での色の変更、点の色の出どころ。
- 作ったものごとの秒数とタイルの枚数、プロセスのメモリを出す。
- 初めの描画のタイルを、`<出力>/tiles/8/<x>/<y>.png` に書く。
- プロジェクトは、アプリが作った見本の土地でも、地図のデータのあるプロジェクトでもよい。
